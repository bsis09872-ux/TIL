## LECTURE NOTE

### Introduction + QnA

### 1. LLM은 어떻게 문장을 만드는가?

**LLM(Large Language Model)** 은 대량의 텍스트를 학습하여, 주어진 문맥에서 **다음에 올 Token의 확률을 예측하면서 문장을 생성하는 언어 모델**이다.

#### Token

- **Token**: LLM이 텍스트를 처리하는 기본 단위
- 단어 하나가 반드시 Token 하나인 것은 아니며, 사용하는 Tokenizer와 언어에 따라 나누어지는 방식이 다름
- 모델에 따라 동일한 내용을 표현할 때 한국어가 영어보다 더 많은 Token을 사용할 수 있음

```text
"나는 너를"
      ↓
     LLM
      ↓
다음 Token의 확률 계산
      ↓
"좋아한다" ...
```

LLM은 학습 과정에서 데이터의 패턴을 **파라미터(Parameter)** 에 반영하고, 이를 바탕으로 다음 Token의 확률을 계산한다.

> 즉, 학습한 문장을 데이터베이스처럼 그대로 저장했다가 꺼내는 방식이 아니라, **학습한 패턴을 바탕으로 다음 Token을 확률적으로 예측하여 문장을 생성하는 통계적·수학적 접근**이다.

#### Embedding과 유사도

**Embedding**은 텍스트 등의 데이터를 의미적 특징을 담은 **실수 Vector**로 표현하는 방법이다.

대표적인 거리·유사도 계산 방법:

1. **Euclidean Distance**
   - 두 Vector 사이의 거리를 계산
   - 거리가 작을수록 서로 가까움

2. **Cosine Similarity**
   - 두 Vector의 방향이 얼마나 비슷한지 계산
   - `1`에 가까울수록 같은 방향
   - `0`에 가까울수록 방향상 관련성이 낮음
   - `-1`에 가까울수록 반대 방향

Embedding 값은 사용하는 모델과 학습 데이터에 따라 달라질 수 있으므로 **모델별·언어별 성능 차이**가 발생할 수 있다.

> **주의:** Embedding과 유사도 계산은 AI 시스템의 중요한 개념이지만, LLM의 Next-token Prediction 자체가 단순히 문장 간 유사도를 계산하여 다음 단어를 고르는 과정은 아니다.

---

### 2. 확률적 생성의 한계: Knowledge Cut-off와 Hallucination

LLM은 확률적으로 다음 Token을 생성하기 때문에 **항상 사실에 기반한 정답을 생성하는 것은 아니다.**

#### Knowledge Cut-off

모델이 학습 과정에서 접한 정보에는 시점상의 한계가 있으므로, **학습 이후 발생한 최신 정보를 모델의 학습 지식만으로는 알지 못할 수 있다.**

#### Hallucination

**Hallucination**은 LLM이 사실과 다르거나 근거가 부족한 내용을 그럴듯하게 생성하는 현상이다.

이는 단순한 일시적 오류만이 아니라 **확률적으로 언어를 생성하는 LLM의 특성에서 발생할 수 있는 구조적인 한계**이다.

```text
LLM
→ 학습된 패턴을 이용한 확률적 Token 생성
→ 항상 사실을 보장하지는 않음
→ Knowledge Cut-off / Hallucination 등의 한계
```

따라서 LLM을 잘 활용하려면 이러한 한계를 **엔지니어링을 통해 보완**해야 한다.

---

### 3. LLM의 한계를 어떻게 보완할까?

#### ① LLM 개발·설정 단계

모델의 출력 후보를 선택하는 방식을 조정할 수 있다.

1. **Top-k**
   - 확률이 높은 상위 `k`개의 Token 후보 안에서 선택

2. **Top-p**
   - 확률이 높은 Token부터 더해 **누적 확률이 `p`에 도달하는 후보 집합** 안에서 선택

3. **Temperature**
   - Token의 확률 분포를 조절
   - 낮을수록 비교적 일관되고 보수적인 출력
   - 높을수록 다양한 출력 가능성이 증가

> 이러한 설정은 **출력의 확률적 선택 방식을 조절하는 방법**이며, Hallucination 자체를 완전히 제거하는 것은 아니다.

#### ② LLM 사용·서비스 단계: Context Engineering

모델이 답변하는 데 필요한 **정보와 맥락(Context)을 적절하게 구성하여 제공하는 것**이다.

```text
사용자 질문
   ↓
필요한 지식 검색 + 관련 Context 제공
   ↓
LLM
   ↓
답변 생성
```

##### Context Window

모델이 한 번의 추론 과정에서 참고할 수 있는 **Token 범위의 한계**이다.

한계를 넘어서는 정보는 모델이나 서비스의 처리 방식에 따라 제외되거나 요약되는 등 **모든 내용을 한 번에 참고하지 못할 수 있다.**

> 단순히 질문을 잘 작성하는 것을 넘어, **모델이 답변에 필요한 정보를 어떤 방식으로 제공할 것인지 설계하는 것**도 중요하다.

#### ③ 사용자의 답변 검증: SIFT

AI의 답변을 그대로 받아들이지 않고 검증하는 과정도 필요하다.

1. **Stop**: 일단 멈추기
2. **Investigate**: 출처 확인
3. **Find**: 다른 출처와 교차 검증
4. **Trace**: 원본과 맥락 확인

> **LLM의 한계 이해 → 개발·설정 단계에서 출력 조절 → Context Engineering으로 필요한 정보 제공 → 사용자는 결과 검증**

## 교안

### 0. AI Literacy

AI 리터러시는 단순히 도구의 기능을 외우는 것이 아니라, **문제를 정의하고 적절한 AI와 도구를 조합하여 해결하고 결과를 검증하는 종합적인 활용 역량**이다.

---

### 1. AI 분야

GPT와 LLM은 AI 전체 분야 중 일부이다.

```text
Artificial Intelligence (AI)
└── Machine Learning (ML)
    └── Deep Learning (DL)
        └── Generative AI
            └── Large Language Model (LLM)
```

> 위 구조는 개념을 이해하기 위한 단순화된 분류이며, 생성형 AI 전체가 LLM인 것은 아니다.

---

### 2. Transformer Architecture

**Architecture**는 시스템의 구성 요소와 처리 구조를 설계한 방식이다.

AI에서는 데이터를 어떻게 입력받고, 어떤 방식으로 처리하고, 결과를 만들어낼지 결정하는 **모델의 구조**를 의미한다.

> 비유하면 빵 공장에서 반죽기, 오븐, 포장기를 어떻게 구성하고 연결할지 정해놓은 **공장 설계도**와 비슷하다.

**Transformer**는 2017년 논문 *Attention Is All You Need*에서 제안된 신경망 아키텍처로, 현대의 많은 LLM을 가능하게 한 핵심 구조이다.

#### Self-Attention

문장 안의 각 토큰이 **다른 토큰들과 어떤 관계를 가지는지 계산하여 중요한 정보를 반영하는 메커니즘**이다.

---

### 3. Tokenization & Next-token Prediction

- **Tokenization**: 입력 텍스트를 모델이 처리할 Token 단위로 나누는 과정
- **Next-token Prediction**: 앞의 문맥을 바탕으로 다음에 등장할 Token의 확률을 예측하는 방식

---

### 4. 모델별 특성 파악하기

모델마다 학습 방식, 성능, Context Window, 지원 기능 등이 다르므로 **문제와 목적에 맞는 모델을 선택하는 것이 중요하다.**

---

### 5. Tool Stack

하나의 AI 모델만 사용하는 것이 아니라 검색, 데이터 처리, 외부 API 등 **필요한 도구를 목적에 맞게 조합하여 문제를 해결**한다.

---

### 6. 프롬프트 5대 원칙: RTCCF

> 수업에서 학습한 RTCCF 기준을 활용하여 프롬프트의 역할, 작업, 맥락, 제약조건, 출력 형식 등을 명확하게 구성한다.

## EXERCISE & More

### Daily Quest

#### 1. Context Window란?

**Context Window**는 AI 모델이 한 번의 추론 과정에서 동시에 참고할 수 있는 **입력과 출력 등을 포함한 토큰 범위의 한계**를 의미한다.

Context Window의 한계를 넘어서는 정보는 사용하는 모델이나 서비스의 처리 방식에 따라 일부가 제외되거나 요약되는 등 **모든 내용을 그대로 참고하지 못할 수 있다.**

#### 헷갈리는 개념 구분

- 모델이 학습을 통해 알고 있는 정보의 시점 → **Knowledge Cut-off**
- 텍스트를 처리 단위로 나누는 과정 → **Tokenization**
- 데이터를 숫자 벡터로 표현 → **Embedding**
- 한 번의 추론에서 참고할 수 있는 범위 → **Context Window**

---

> 💡 **오늘의 핵심:**  
> LLM은 문장을 통째로 이해해서 정답을 꺼내는 데이터베이스가 아니라, **Token 단위로 입력을 처리하고 문맥을 바탕으로 다음 Token을 확률적으로 예측하여 출력을 생성하는 모델**이다. 따라서 모델의 한계를 이해하고 적절한 Context를 제공하며, 중요한 답변은 검증하는 과정이 필요하다.
