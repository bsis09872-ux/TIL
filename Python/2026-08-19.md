## REVIEW

### 이름 변형 규칙 (Name Mangling)

속성 이름 앞에 언더바 두 개(`__`)를 붙이면 내부적으로 `_클래스명__변수명` 형태로 이름이 변형된다.

```python
class Secret:
    def __init__(self):
        self.__password = "1234"

my_secret = Secret()

# print(my_secret.__password)       # AttributeError
print(my_secret._Secret__password)  # 1234
```

→ 원래 이름으로는 외부에서 직접 접근하기 어렵게 만들어 **정보 은닉을 보조**한다. 단, 완전히 접근을 차단하는 기능은 아니다.

## LECTURE NOTE

### 7장 1강 예외 처리

#### 대표적인 오류와 예외

- `SyntaxError`: Python 문법이 잘못된 경우
- **Exception**: 프로그램 실행 중 발생하는 예외
    - `IndexError`: 존재하지 않는 인덱스로 접근
    - `ValueError`: 자료형은 맞지만 처리할 수 없는 값이 전달됨
    - `TypeError`: 적절하지 않은 자료형으로 연산하거나 호출함
    - `ZeroDivisionError`: 0으로 나누기를 시도함

### 1. `try-except-else-finally`

```python
try:
    # 예외가 발생할 수 있는 로직
except ValueError as e:
    # 해당 예외 발생 시 처리
else:
    # 예외가 발생하지 않았을 때 실행
finally:
    # 예외 발생 여부와 관계없이 마지막에 실행
```

- `try`: 예외가 발생할 수 있는 핵심 로직
- `except`: 발생한 예외를 처리
- `else`: 예외 없이 `try`가 정상적으로 완료되면 실행
- `finally`: 예외 발생 여부와 관계없이 실행되며, 파일 닫기·DB 연결 해제 등 **반드시 수행해야 하는 마무리 작업**에 활용

`as e`는 발생한 **예외 객체를 변수 `e`로 받아** 예외 메시지 등을 확인할 때 사용한다.

```python
except Exception as e:
    print(e)
```

`Exception`은 여러 일반적인 예외의 상위 클래스이므로 여러 종류의 예외를 한 번에 처리할 수 있지만, 가능한 경우 **구체적인 예외 종류를 지정하는 것이 좋다.**

### 2. `raise`

개발자가 특정 조건에서 직접 예외를 발생시킬 수 있다.

```python
raise ValueError("잘못된 값입니다.")
```

→ 특정 상황을 오류로 정의하고, 예외를 호출한 쪽에서 처리할 수 있도록 **추가 처리에 열려 있는 구조**를 만들 수 있다.

### 3. 사용자 정의 예외

필요한 경우 직접 예외 클래스를 정의하여 프로그램의 상황에 맞는 예외를 만들 수 있다.

### 7장 2강 디버깅 기초

#### Traceback

**Traceback**은 예외가 발생했을 때 Python이 출력하는 오류 추적 정보이다.

→ 어떤 함수들이 호출되었고 **어디에서 예외가 발생했는지** 호출 경로를 따라 확인할 수 있다.

#### `print()` 디버깅의 한계

`print()`로 값을 확인할 수도 있지만 코드에 직접 출력문을 추가해야 하고, 코드가 복잡해질수록 여러 변수의 상태와 실행 흐름을 추적하기 어렵다.

#### Breakpoint & Variable Panel

- **Breakpoint(중단점)**: 원하는 코드 위치에서 프로그램 실행을 일시 정지
- **Variable Panel**: 정지된 시점의 변수 이름, 자료형, 현재 값 등을 확인

#### Debugger

| 기능 | 역할 |
|---|---|
| `Step Over` | 현재 줄을 실행하고 다음 줄로 이동. 호출된 함수 내부에는 들어가지 않음 |
| `Step Into` | 호출된 함수 내부로 들어가 한 단계씩 확인 |
| `Step Out` | 현재 함수의 나머지를 실행하고 호출한 위치로 돌아감 |
| `Continue` | 다음 중단점까지 실행 계속 |

> 함수 내부의 동작까지 확인하려면 `Step Into`, 함수 내부는 건너뛰고 현재 흐름만 확인하려면 `Step Over`를 사용한다.

#### Debug Console

프로그램이 중단된 상태에서 **표현식이나 변수 값을 직접 입력하여 확인할 수 있는 공간**이다.

### 9장 1강 내장 함수

#### `all()`과 `any()`

- `all()`: 모든 요소가 참이면 `True`
- `any()`: 하나 이상의 요소가 참이면 `True`

빈 리스트에서는 결과가 다르다.

```python
all([])  # True
any([])  # False
```

- `all([])` → `False`인 요소가 하나도 없으므로 `True`
- `any([])` → `True`인 요소가 하나도 없으므로 `False`

## EXERCISE & More

### Daily Quest

```python
def set_user_age(age):
    if age < 0:
        raise ValueError("나이는 음수가 될 수 없습니다.")
    print(f"사용자의 나이가 {age}세로 설정되었습니다.")

try:
    input_age = -5
    set_user_age(input_age)
except ValueError as e:
    print(f"[시스템 경고] {e}")
```

**실행 흐름**

1. `set_user_age(-5)`가 호출된다.
2. `age < 0`이 `True`이므로 `raise ValueError(...)`가 실행된다.
3. 예외가 발생하면서 함수의 정상 실행 흐름이 중단된다.
4. 따라서 함수 내부의 `print()`는 실행되지 않는다.
5. `except ValueError as e`가 예외를 처리하여 경고 메시지를 출력한다.

→ **`raise`로 예외 발생 → `except`에서 예외 처리**의 흐름을 확인했다.
