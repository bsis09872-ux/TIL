# Python 개발 환경 구축 및 변수

> 📅 2026.08.06

오늘은 GitHub 협업 기능을 간단히 복습하고, `uv`를 이용해 Python 프로젝트와 가상 환경을 구축했다. 또한 Python 변수, 동적 타이핑, REPL의 개념을 학습하고 VS Code에서 발생한 가상 환경 연결 문제를 해결했다.

## GitHub 협업 복습

### Squash and Merge

`Squash and Merge`는 Pull Request의 여러 Commit을 **하나의 Commit으로 합쳐** 대상 Branch에 반영하는 병합 방식이다.

기능 개발 과정에서 만들어진 여러 개의 작은 Commit을 하나로 정리할 수 있어 `main`의 Commit History를 깔끔하게 유지하는 데 유용하다.

### `git stash pop`

```bash
git stash pop
```

`stash`에 임시 저장했던 작업을 현재 Working Directory에 다시 적용하고, 해당 항목을 stash 목록에서 제거한다.

작업 내용을 복원하되 stash 기록을 유지하려면 다음 명령어를 사용할 수 있다.

```bash
git stash apply
```

## Python 코드의 실행 방식

컴파일 언어는 실행 전에 프로그램 전체를 기계가 이해할 수 있는 코드로 변환한다.

인터프리터 언어는 프로그램을 실행하는 과정에서 코드를 해석하고 실행한다.

| 구분 | 컴파일 언어 | 인터프리터 언어 |
|---|---|---|
| 변환 시점 | 실행 전 전체 변환 | 실행 과정에서 해석 |
| 특징 | 변환 후 실행 속도가 빠른 편 | 코드를 바로 실행하고 확인하기 편리함 |

Python은 일반적으로 인터프리터 언어로 분류된다.

## Python 개발 환경과 가상 환경

프로젝트마다 사용하는 Python 버전과 패키지 버전이 다를 수 있다. 따라서 프로젝트별로 독립적인 가상 환경을 구성하면 패키지와 의존성 충돌을 줄일 수 있다.

가상 환경은 Python 자체를 완전히 새로 설치하는 공간이라기보다, **특정 Python 인터프리터와 해당 프로젝트의 패키지를 분리하여 관리하는 환경**이다.

### 가상 환경 및 프로젝트 관리 방법

#### `venv`

Python에서 기본으로 제공하는 가상 환경 기능이다.

```bash
python -m venv .venv
```

#### Anaconda

Python, 패키지, 가상 환경을 함께 관리할 수 있는 도구이다. 데이터 분석 분야에서 많이 사용하지만 설치 용량이 크고 환경에 따라 의존성 충돌이 발생할 수 있다.

#### `uv`

`uv`는 Rust 기반의 빠른 Python 프로젝트 및 패키지 관리 도구이다.

- Python 버전 관리
- 가상 환경 생성
- 패키지 설치와 제거
- 프로젝트 의존성 관리
- Python 파일 실행

이번 수업에서는 `uv`를 중심으로 실습했다.

### `uv` 버전 확인

PowerShell에서 `uv`를 설치한 뒤 다음 명령어로 설치 여부를 확인했다.

```bash
uv --version
```

## 버전 번호의 의미

일반적으로 버전은 다음과 같이 표현된다.

```text
Major.Minor.Patch
1.2.3
```

| 구분 | 의미 |
|---|---|
| Major | 호환성에 영향을 줄 수 있는 큰 변경 |
| Minor | 기존 기능과의 호환성을 유지하는 기능 추가 및 개선 |
| Patch | 버그 수정 및 작은 코드 개선 |

`0.x.x` 버전은 아직 초기 개발 단계일 수 있으며, `1.0.0`부터 공개된 기능과 호환성 규칙이 비교적 안정적으로 관리된다는 의미로 사용하는 경우가 많다.

## `uv` 프로젝트 관리

### 프로젝트 생성

```bash
uv init
```

Python 버전을 지정하여 프로젝트를 생성할 수도 있다.

```bash
uv init --python 3.13
```

### 프로젝트 Python 버전 고정

```bash
uv python pin 3.13
```

프로젝트에서 사용할 Python 버전이 `.python-version` 파일에 기록된다.

### 패키지 설치

```bash
uv add pandas
```

설치한 패키지는 `pyproject.toml`의 `dependencies`에 기록된다.

```toml
[project]
dependencies = [
    "pandas",
]
```

### 패키지 제거

```bash
uv remove pandas
```

### Python 파일 실행

```bash
uv run main.py
```

`uv run`을 사용하면 가상 환경을 직접 활성화하지 않아도 해당 프로젝트 환경에서 명령어를 실행할 수 있다.

## 가상 환경 활성화와 종료

### macOS

활성화:

```bash
source .venv/bin/activate
```

비활성화:

```bash
deactivate
```

### Windows CMD

활성화:

```bat
.venv\Scripts\activate
```

비활성화:

```bat
.venv\Scripts\deactivate.bat
```

가상 환경을 사용할 때는 현재 터미널의 위치가 프로젝트 폴더인지, 어떤 가상 환경이 활성화되어 있는지 확인해야 한다.

## Kernel과 Python Kernel

운영체제의 **Kernel**은 하드웨어와 소프트웨어 사이에서 CPU, 메모리, 파일 등의 자원을 관리하는 운영체제의 핵심 구성 요소이다.

반면 Jupyter Notebook이나 VS Code에서 선택하는 **Python Kernel**은 Notebook의 Python 코드를 실행하는 프로세스 또는 실행 환경을 의미한다.

두 용어는 이름은 같지만 사용되는 맥락이 다르다.

## REPL

REPL은 코드를 한 줄씩 입력하고 즉시 결과를 확인할 수 있는 대화형 실행 환경이다.

- **Read**: 입력을 읽음
- **Evaluate**: 입력한 코드를 평가하고 실행
- **Print**: 결과 출력
- **Loop**: 과정을 반복

간단한 코드나 변수의 결과를 빠르게 확인할 때 유용하다.

## Python 변수

컴퓨터는 연산을 수행하는 기계이며, 연산에 사용할 값은 메모리에 저장된다.

수업에서는 다음과 같이 비유해 이해했다.

- 컴퓨터 → 계산하는 기계
- 변수값 → 계산할 대상
- 메모리 → 값을 기록하는 여러 개의 방
- 변수 → 값이 있는 공간을 참조하는 이름표

Python에서 변수는 값 자체라기보다 **객체를 참조하는 이름**으로 이해할 수 있다.

```python
age = 25
name = "Alice"
```

여기에서 `=`는 같다는 뜻이 아니라 오른쪽 값을 왼쪽 변수에 연결하는 **대입 연산자**이다.

```python
value = 10
value = 20
```

`value`가 새로운 객체를 참조하면 기존 객체와의 연결은 끊어진다. 해당 객체를 참조하는 이름이 더 이상 없다면 메모리 정리 대상이 될 수 있다.

### Garbage Collection

Python은 더 이상 필요하지 않은 객체가 차지한 메모리를 자동으로 관리한다.

Python에서는 참조 횟수 관리와 Garbage Collector가 함께 사용되며, 개발자가 모든 메모리를 직접 해제하지 않아도 된다.

## 동적 타이핑

Python은 **동적 타이핑 언어**이다.

변수를 선언할 때 자료형을 미리 지정하지 않으며, 자료형은 변수 이름이 아니라 실행 중 변수와 연결된 객체에 따라 결정된다.

```python
value = 10
value = "Python"
```

같은 변수 이름이 정수 객체를 참조하다가 이후 문자열 객체를 참조할 수 있다.

동적 타이핑은 코드가 간결하고 빠르게 작성된다는 장점이 있지만, 잘못된 자료형을 사용한 오류가 실행 중에 발견될 수 있다.

## 오늘의 실습: `ipykernel` 연결 문제 해결

### 문제 상황

VS Code에서 `ipykernel`을 설치했음에도 계속 설치되지 않은 것으로 표시되었다.

### 원인

CMD와 VS Code 터미널을 번갈아 사용하면서 서로 다른 가상 환경을 활성화했다.

두 가상 환경의 이름이 모두 `venv` 또는 `.venv`로 비슷해 같은 환경이라고 생각했지만, 실제로는 서로 다른 경로에 생성된 별개의 환경이었다.

따라서 한쪽 환경에 `ipykernel`을 설치해도 VS Code가 선택한 다른 환경에서는 해당 패키지를 찾을 수 없었다.

### 해결 과정

1. CMD에서 활성화되어 있던 기존 가상 환경을 종료했다.
2. VS Code에서 프로젝트 폴더를 다시 확인했다.
3. VS Code 터미널에서 올바른 가상 환경을 활성화했다.
4. 해당 환경에 필요한 패키지와 `ipykernel`을 설치했다.
5. VS Code를 재실행했다.
6. 올바른 Python Interpreter와 Kernel을 다시 선택했다.
7. Notebook 실행을 통해 정상적으로 연결된 것을 확인했다.

### 문제 해결을 통해 이해한 점

같은 이름의 가상 환경이라도 생성된 경로가 다르면 서로 다른 환경이다.

패키지는 현재 선택된 Python 환경에 설치되므로 설치와 실행 전에 다음 세 가지를 확인해야 한다.

```text
현재 터미널 위치
→ 활성화된 가상 환경
→ VS Code가 선택한 Python Interpreter 및 Kernel
```

## 오늘 이해한 내용

- 가상 환경은 프로젝트별 Python 버전과 패키지를 분리해서 관리하기 위해 사용한다.
- `uv`는 Python 버전, 가상 환경, 패키지 및 프로젝트 의존성을 함께 관리할 수 있다.
- `uv run`을 사용하면 가상 환경을 직접 활성화하지 않고도 프로젝트 환경에서 코드를 실행할 수 있다.
- Python의 변수는 값을 담는 상자라기보다 객체를 참조하는 이름표에 가깝다.
- Python은 변수에 자료형을 고정하지 않는 동적 타이핑 언어이다.
- 운영체제 Kernel과 Jupyter의 Python Kernel은 서로 다른 맥락의 개념이다.
- 패키지 설치 오류가 발생하면 경로, 가상 환경, Interpreter, Kernel이 일치하는지 확인해야 한다.
