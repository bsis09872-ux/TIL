## Review

### Word Embedding

원핫 인코딩(One-Hot Encoding)은 대부분의 값이 `0`인 **희소 벡터(Sparse Vector)** 로 단어를 표현하기 때문에 단어 사이의 의미적 관계를 나타내기 어렵다.

이를 보완하기 위해 **Word Embedding**은 단어를 저차원의 실숫값으로 이루어진 **밀집 벡터(Dense Vector)** 로 표현한다.

학습이 진행되면 의미가 비슷한 단어들이 벡터 공간에서 가까운 위치에 놓이게 된다.

> **핵심:** 원핫 인코딩은 단어의 구분에는 유리하지만 의미를 표현하지 못하고, 임베딩은 단어의 **의미적 관계를 벡터 공간에 표현**한다.

---

### RNN과 활성화 함수

RNN의 순환층에서는 주로 `tanh` 활성화 함수를 사용한다.

일반적인 은닉층에서는 ReLU를 사용할 수 있지만, RNN은 이전 시점의 상태가 다음 시점으로 반복해서 전달되므로 값이 계속 누적된다.

`tanh`는 출력값을 `-1 ~ 1` 사이로 제한하기 때문에 순환 상태를 비교적 안정적인 범위로 유지할 수 있다.

#### 지금까지 배운 활성화 함수

- **일반 은닉층:** ReLU, Sigmoid 등
- **RNN 순환층:** 주로 `tanh`
- **이진 분류 출력층:** Sigmoid
- **다중 분류 출력층:** Softmax

**Sigmoid의 한계**

Sigmoid는 출력이 `0` 또는 `1` 근처로 갈수록 기울기가 매우 작아지는 **Vanishing Gradient(기울기 소실)** 문제가 발생할 수 있다.

일반 은닉층에서는 이를 완화하기 위해 ReLU가 많이 사용된다.

---

### RNN의 기본 흐름

```text
입력값
  ↓
Embedding
  ↓
RNN Hidden State
  ↓
출력층
  ↓
확률 / Label
  ↓
Loss
  ↓
Gradient
  ↓
Weight Update
```

RNN의 핵심은 현재 입력뿐 아니라 **이전 시점의 Hidden State**를 함께 사용한다는 것이다.

```text
현재 입력 x_t ── Wx ──┐
                       ├──> h_t
이전 상태 h_t-1 ─ Wh ─┘
```

대표적으로 다음과 같은 형태로 표현할 수 있다.

```text
h_t = tanh(Wx·x_t + Wh·h_t-1 + b)
```

- `Wx`: 현재 입력에 적용되는 가중치
- `Wh`: 이전 Hidden State에 적용되는 가중치

따라서 RNN은 **이전 정보를 다음 시점으로 전달하며 기억하는 순환 구조**를 가진다.

> `Wh`가 존재하기 때문에 이전 시점의 정보가 다음 시점으로 계속 전달된다.

마지막 Hidden State는 입력 시퀀스 전체의 정보를 어느 정도 요약하고 있기 때문에 **Context Vector**처럼 사용할 수 있다.

하지만 긴 문장의 모든 정보를 마지막 상태 하나에 압축하면 **Bottleneck** 문제가 발생할 수 있다.

## Lecture Note

### 5-1. Seq2Seq Architecture

#### Seq2Seq란?

**Sequence-to-Sequence**는 하나의 시퀀스를 입력받아 다른 시퀀스를 출력하는 구조이다.

초기에는 주로 **기계 번역(Machine Translation)** 을 위해 연구되었다.

기본 구조는 다음 두 부분으로 이루어진다.

```text
입력 문장
   ↓
Encoder
   ↓
Context
   ↓
Decoder
   ↓
출력 문장
```

#### Encoder

입력 문장을 순서대로 읽으면서 정보를 내부 상태에 축적한다.

> **Encoder = 문장을 읽고 이해하는 부분**

#### Decoder

Encoder가 전달한 정보를 초기 상태로 사용하여 출력 문장을 한 토큰씩 생성한다.

> **Decoder = 이해한 내용을 바탕으로 새로운 문장을 생성하는 부분**

---

#### LSTM Encoder-Decoder

LSTM은 매 시점에 두 가지 상태를 전달한다.

- **Hidden State `h_t`**: 현재 출력과 직접 관련된 상태
- **Cell State `c_t`**: 장기간 정보를 전달하는 메모리 통로

인코더가 입력 문장을 모두 처리하면 마지막 상태가 남는다.

```text
Encoder
   ↓
h_T
c_T
   ↓
Decoder의 초기 상태
```

구조적으로는 다음과 같이 전달된다.

```text
Encoder h_T → Decoder h_0
Encoder c_T → Decoder c_0
```

> 비유하면 **입력 문장 전체의 내용을 작은 가방에 압축한 뒤 그 가방을 Decoder에게 넘겨주는 것**과 비슷하다.

---

#### Context Vector

초기 Seq2Seq에서는 인코더의 마지막 상태를 입력 문장의 전체 맥락을 담은 **Context Vector**로 사용한다.

LSTM을 사용하는 경우 마지막 `h_T`, `c_T`가 Decoder의 초기 상태로 전달된다.

```text
입력 문장
  ↓
Encoder LSTM
  ↓
(h_T, c_T)
  ↓
Decoder LSTM
  ↓
출력 문장
```

---

#### Special Token

Decoder가 출력을 시작하려면 첫 번째 입력이 필요하다.

그 역할을 하는 것이 **`<SOS>` 또는 `<BOS>` 토큰**이다.

- `<SOS>` / `<BOS>`: 문장의 시작
- `<EOS>`: 문장의 종료
- `<PAD>`: 서로 다른 시퀀스의 길이를 맞추기 위한 패딩
- `<UNK>`: 사전에 없는 단어

```text
<SOS> → 나는 → 학교에 → 간다 → <EOS>
```

---

#### Teacher Forcing

Decoder를 학습할 때 이전 시점의 모델 예측값을 다음 입력으로 계속 사용하면 초반의 작은 오차가 이후 시점까지 누적될 수 있다.

Teacher Forcing에서는 학습 시 다음 입력으로 **모델이 예측한 값 대신 실제 정답 토큰**을 넣는다.

```text
정답:
<SOS> → 나는 → 학교에 → 간다

학습 시:
<SOS>
 ↓
"나는" 예측
 ↓
다음 입력에는 예측값 대신 실제 정답 "나는" 사용
```

이를 통해 초기 학습을 보다 안정적으로 진행할 수 있다.

---

### Bottleneck과 Long-Term Dependency

#### Bottleneck

초기 Seq2Seq의 중요한 한계이다.

입력 문장이 아무리 길어도 마지막에 전달하는 상태의 차원은 고정되어 있다.

따라서 문장이 길어질수록 한정된 공간 안에 더 많은 정보를 압축해야 한다.

> **수백 페이지짜리 보고서를 A4 한 장짜리 메모에 전부 요약해야 하는 상황**과 비슷하다.

중요한 정보만 압축하다 보면 일부 정보는 희석되거나 사라질 수 있다.

> **Bottleneck = 긴 입력 정보를 고정 크기의 Context에 압축하면서 발생하는 구조적 정보 손실 문제**

---

#### Long-Term Dependency

RNN은 정보를 시간 순서대로 계속 전달한다.

```text
정보1 → 정보2 → 정보3 → 정보4 → ... → 정보100
```

이 과정이 길어지면 매우 앞쪽에 있던 정보와 뒤쪽 정보 사이의 관계를 학습하기 어려워진다.

이를 **Long-Term Dependency Problem(장기 의존성 문제)** 이라고 한다.

둘은 관련 있지만 완전히 같은 개념은 아니다.

```text
Bottleneck
= 모든 정보를 좁은 통로 하나로 보내야 하는 구조적 문제

Long-Term Dependency
= 긴 전달 과정에서 오래된 정보의 영향이 약해지는 문제
```

> 비유하면 병목은 **좁은 문 하나로 모든 사람이 지나가야 하는 문제**, 장기 의존성은 **긴 전달 게임을 하면서 처음 들은 말이 점점 흐려지는 문제**이다.

### 5-2. Attention Mechanism

#### Attention이 등장한 이유

초기 Seq2Seq는 인코더의 **마지막 상태 하나**에 의존했다.

Attention에서는 마지막 상태만 사용하는 대신 **Encoder가 만든 여러 Hidden State를 보관**한다.

```text
h1   h2   h3   h4   h5
│    │    │    │    │
└────┴────┴────┴────┘
          ↓
       Attention
```

Decoder가 출력을 만들 때마다

> "지금 단어를 만들기 위해 입력 문장의 어느 부분을 봐야 하지?"

를 계산한다.

> 기존 Seq2Seq는 **책을 모두 읽고 마지막에 만든 한 줄 요약만 보고 시험을 보는 것**이고,  
> Attention은 **책을 옆에 펼쳐 놓고 문제마다 필요한 부분을 다시 찾아보는 것**이다.

---

#### Attention의 특징

1. Encoder의 여러 상태를 활용
2. 관련성이 높은 정보에 더 큰 가중치 부여
3. Q, K, V를 이용해 필요한 정보를 탐색
4. 가중합을 통해 Context Vector 생성

---

#### Query, Key, Value

**Query (Q)**  
무엇을 찾고 있는가?

검색창의 검색어와 비슷하다.

```text
"오늘 서울 날씨"
```

현재 찾고 싶은 내용이 Query의 역할을 한다.

**Key (K)**  
각 정보가 무엇에 관한 것인지 알려주는 **이름표 / 색인**이다.

```text
서울
부산
오늘
내일
기온
강수량
```

Query는 여러 Key와 비교하여 자신과 관련 있는 정보를 찾는다.

**Value (V)**  
Key와 연결되어 있는 **실제 정보의 내용**이다.

```text
서울 / 기온 → 23℃
서울 / 강수량 → 70%
서울 / 습도 → 65%
```

```text
Query = 무엇을 찾을 것인가?
Key   = 어떤 정보인지 알려주는 이름표
Value = 그 이름표에 연결된 실제 내용
```

---

#### Attention 연산의 3단계

##### 1. 유사도 측정

Query와 각 Key의 관련성을 계산한다.

```text
Query ↔ Key1
Query ↔ Key2
Query ↔ Key3
```

Transformer의 기본 Attention에서는 주로 **내적(Dot Product)** 을 이용한다.

```text
Q · Kᵀ
```

Scaled Dot-Product Attention에서는 다음과 같이 계산한다.

```text
QKᵀ / √d_k
```

##### 2. Softmax - 가중치 분배

관련성 점수를 Softmax에 넣어 전체 합이 `1`인 확률 분포 형태로 바꾼다.

```text
서울   0.50
오늘   0.30
기온   0.15
부산   0.05
------------
합계   1.00
```

이 값이 **Attention Weight**이다.

##### 3. Weighted Sum - 가중합

각 Value에 Attention Weight를 곱한 뒤 더한다.

```text
Context = Σ(Attention Weight × Value)
```

중요한 정보는 크게 반영되고 관련성이 낮은 정보는 조금만 반영된다.

> **Context Vector = 현재 Query에 필요한 정보들을 중요도에 따라 모아 만든 요약본**

---

#### Attention에서 무엇이 학습되는가?

**Attention Weight 자체가 모델의 고정된 학습 파라미터는 아니다.**

입력이 들어올 때마다 Q와 K의 관계를 이용하여 새롭게 계산된다.

대신 Q, K, V를 만들 때 사용하는 **Projection Matrix의 가중치가 학습을 통해 업데이트**된다.

```text
Embedding
 ↓
W_Q → Query
W_K → Key
W_V → Value
```

---

#### Attention의 효과와 남은 한계

Attention은 마지막 Hidden State 하나에만 의존하던 **Bottleneck 문제를 완화**할 수 있다.

하지만 RNN 기반 Attention은 여전히 RNN 구조를 사용하기 때문에 토큰을 순차적으로 처리해야 한다.

```text
1번 처리 → 2번 처리 → 3번 처리 → ...
```

따라서 병렬 처리가 제한된다.

> RNN도 GPU를 사용할 수 있지만, 이전 시점의 계산 결과가 다음 시점에 필요하기 때문에 **시퀀스 방향의 완전한 병렬화가 어렵다.**

이러한 한계를 크게 바꾼 것이 **Transformer**이다.

### 6-1. Transformer Architecture

#### Transformer의 핵심 변화

Transformer는 RNN의 순환 구조를 제거하고 **Attention을 핵심 연산으로 사용**한다.

```text
RNN
Token1 → Token2 → Token3 → Token4
       순차 처리

Transformer
Token1
Token2  → 동시에 관계 계산
Token3
Token4
```

이를 통해 시퀀스 내 여러 토큰에 대한 계산을 병렬적으로 수행하기 쉬워졌다.

> **핵심:** Transformer는 정보를 Context Vector 하나에 더 압축하는 모델이 아니라, **토큰 간 관계를 Attention으로 직접 계산하는 구조**이다.

---

#### Transformer Encoder

전체적인 흐름은 다음과 같다.

```text
Token
 ↓
Embedding
 ↓
Positional Encoding
 ↓
Multi-Head Self-Attention
 ↓
Residual Connection + Layer Normalization
 ↓
Feed Forward Network
 ↓
Residual Connection + Layer Normalization
 ↓
Encoder Output
```

##### 1. Embedding

각 토큰을 벡터값으로 변환한다.

```text
나는      → [0.1, 0.2, ...]
너를      → [0.9, 0.2, ...]
사랑한다  → [0.3, 0.4, ...]
```

##### 2. Positional Encoding

Transformer에는 RNN처럼 순차적으로 상태를 전달하는 구조가 없다.

따라서 단어의 **순서 정보(Position)** 를 별도로 넣어줘야 한다.

대표적인 방식에서는 `sin`, `cos` 함수를 사용하여 위치 정보를 벡터에 더한다.

```text
Token Embedding
      +
Position Encoding
      ↓
순서 정보가 포함된 표현
```

##### 3. Multi-Head Self-Attention

Self-Attention에서는 한 문장 안의 토큰들이 서로의 관계를 계산한다.

```text
나는 / 너를 / 사랑한다
```

각 토큰이 다른 토큰과 얼마나 관련 있는지 계산한다.

**Multi-Head**는 Attention을 여러 관점에서 동시에 수행하는 것이다.

> **Attention Head = 서로 다른 관점에서 문장을 바라보는 평가자**

한 Head는 주어-동사 관계를 볼 수 있고, 다른 Head는 목적어-동사 관계를 볼 수 있다.

##### 4. Residual Connection

Attention이나 Feed Forward Network를 거친 출력에 **원래 입력을 다시 더해주는 구조**이다.

```text
x
├───────────────┐
↓               │
Attention       │
↓               │
Output + x ←────┘
```

Residual Connection은 단순히 값을 증폭시키기 위한 것이 아니라 **원래 정보를 보존하고 깊은 네트워크에서 Gradient가 안정적으로 흐르도록 돕는 구조**이다.

##### 5. Layer Normalization

Residual Connection 이후 값들의 분포를 정규화하여 학습을 안정적으로 만든다.

**Layer Normalization**은 각 샘플의 feature들을 기준으로 평균과 분산을 계산하여 정규화한다.

> LayerNorm은 단순히 "LLM이라서" 사용하는 것이 아니라, **각 층의 출력 분포를 안정화해 학습을 돕기 위해 사용**된다.

##### 6. Feed Forward Network

Attention으로 토큰 사이의 관계를 계산한 뒤, 각 토큰 표현을 별도의 신경망에 통과시킨다.

```text
Dense
 ↓
ReLU 또는 다른 Activation
 ↓
Dense
```

---

#### Transformer Decoder

Decoder의 기본 흐름은 다음과 같다.

```text
입력 토큰
 ↓
Masked Multi-Head Self-Attention
 ↓
Residual + LayerNorm
 ↓
Cross Attention
 ↓
Residual + LayerNorm
 ↓
Feed Forward Network
 ↓
Residual + LayerNorm
 ↓
다음 토큰 예측
```

##### Masked Multi-Head Self-Attention

Decoder는 문장을 생성할 때 미래의 정답을 미리 보면 안 된다.

따라서 현재 위치보다 뒤에 있는 토큰을 가린다.

이를 **Causal Masking**이라고 한다.

```text
나는 → 너를 → 사랑한다

"너를"을 예측하는 시점
볼 수 있음: <SOS>, 나는
볼 수 없음: 사랑한다
```

##### Cross Attention

Decoder가 Encoder의 정보를 가져오는 부분이다.

```text
Query → Decoder에서 생성
Key   → Encoder Output
Value → Encoder Output
```

즉 Decoder가

> "지금 다음 단어를 만들기 위해 Encoder에서 어떤 정보를 참고해야 하지?"

라고 묻는 과정이다.

---

#### Self-Attention vs Cross-Attention

| 구분 | Query | Key | Value |
| --- | --- | --- | --- |
| **Self-Attention** | 같은 시퀀스 | 같은 시퀀스 | 같은 시퀀스 |
| **Cross-Attention** | Decoder | Encoder | Encoder |

---

#### Transformer와 GPU

Transformer는 여러 토큰에 대한 계산을 병렬화하기 쉬워 GPU의 병렬 연산 능력을 효과적으로 활용할 수 있다.

CUDA는 NVIDIA GPU에서 이러한 연산을 수행할 수 있도록 지원하는 플랫폼이다.

단, **문장의 길이가 길어져도 계산량이 동일한 것은 아니다.**

Self-Attention은 토큰들이 서로를 비교하기 때문에 시퀀스가 길어지면 연산량도 증가한다.

중요한 차이는 다음과 같다.

```text
RNN
앞 계산이 끝나야 다음 계산 가능

Transformer
여러 토큰의 Attention 계산을 병렬적으로 수행 가능
```

### 전체 흐름 정리

```text
One-Hot Encoding
      ↓
의미 표현 부족
      ↓
Embedding
      ↓
단어를 의미 벡터로 표현
      ↓
RNN / LSTM
      ↓
시퀀스 정보를 순차적으로 기억
      ↓
Seq2Seq
      ↓
Encoder → Context → Decoder
      ↓
⚠️ 고정된 Context에 모든 정보를 압축
      ↓
Bottleneck
      ↓
Attention
      ↓
모든 Encoder State 중 필요한 정보 선택
      ↓
Q + K → Attention Weight
      ↓
Attention Weight × V
      ↓
Context Vector
      ↓
⚠️ RNN의 순차 처리 구조는 여전히 존재
      ↓
Transformer
      ↓
RNN 순환 구조 제거
      ↓
Self-Attention
      ↓
병렬 처리
      ↓
Multi-Head Attention
```

#### 한 문장씩 기억하기

**Seq2Seq**  
> 문장을 읽고 **하나의 요약 가방(Context)** 으로 만들어 Decoder에게 넘긴다.

**Bottleneck**  
> 문장이 길어져도 **가방 크기가 그대로라 정보가 빠질 수 있다.**

**Attention**  
> 가방 하나만 보지 말고 **원본을 펼쳐 놓고 필요한 곳을 다시 찾아본다.**

**Q / K / V**  
> **Q는 검색어, K는 이름표, V는 실제 내용.**

**Transformer**  
> 순서대로 전달하는 RNN을 없애고 **토큰들이 서로를 직접 바라보게 한다.**

---

### 헷갈렸던 부분 정리

- `Cell = 입력층`이 아니다. RNN/LSTM 내부에서 **상태를 전달하는 구조**를 기억한다.
- `h_t`는 단순히 입력을 벡터로 바꾼 값이 아니라 **현재 입력과 이전 상태를 반영한 Hidden State**이다.
- LSTM의 `c_t`가 모든 타임스텝을 그대로 저장하는 것은 아니다. **게이트를 통해 필요한 정보를 선택적으로 유지·갱신**한다.
- Attention Weight는 학습 내내 고정되는 Weight가 아니라 **입력마다 Q와 K를 이용해 동적으로 계산**된다.
- Transformer의 기본 Attention은 **Scaled Dot-Product `QKᵀ / √d_k`** 를 사용한다.
- RNN도 GPU를 사용할 수 있지만 **시간축의 순차 의존성 때문에 Transformer보다 병렬화가 어렵다.**
- Residual Connection은 값을 단순히 키우기 위한 것이 아니라 **기존 정보와 Gradient 흐름을 보존하기 위한 연결**이다.
- Layer Normalization은 단순히 LLM이라서 사용하는 것이 아니라 **각 층의 값 분포를 안정화하여 학습을 돕는 기법**이다.

1. **Seq2Seq Context Vector**  
   → LSTM 인코더의 마지막 **은닉 상태 `h_T`와 셀 상태 `c_T`** 를 디코더의 초기 상태로 전달한다.

2. **Teacher Forcing (교사 강요)**  
   → 디코더 학습 시 이전 예측값 대신 **실제 정답 토큰을 다음 시점의 입력으로 사용**하여 학습을 안정화한다.

3. **Attention - Query**  
   → 현재 디코더 상태를 바탕으로 **어떤 정보를 찾을지 나타내는 질문 역할**을 하며, Key와 비교하여 관련 정보를 찾는다.

4. ❌ **Transformer**  
   → 고정된 Context Vector에 정보를 더 압축하는 것이 아니라, **RNN의 순환 구조를 없애고 Self-Attention을 이용해 병렬 처리가 가능하도록 설계**했다.

5. **Causal Masking (인과적 마스킹)**  
   → 디코더가 현재 토큰을 예측할 때 **미래 토큰을 미리 볼 수 없도록 차단**하여 정답을 미리 보는 것을 방지한다.

### 오늘의 핵심

> **Seq2Seq의 고정 Context Vector가 만든 병목을 Attention이 완화했고, RNN의 순차 처리 한계를 Attention 중심의 구조로 바꾼 것이 Transformer이다.**

```text
Seq2Seq
"한 장에 다 요약하자"
      ↓
Attention
"필요할 때 원본을 다시 찾아보자"
      ↓
Transformer
"아예 서로 동시에 바라보면서 관계를 계산하자"
```
