## 😊 SUMMARY

이번 수업에서는 SQL을 이용해 데이터를 **조회하고 조건에 따라 필터링·정렬하는 방법**부터 시작해, 집계 함수를 이용한 **그룹별 데이터 분석**, 여러 테이블의 데이터를 연결하는 **집합 연산과 JOIN**까지 학습했다.

전체적인 흐름은 **`SELECT → WHERE → ORDER BY → 집계 함수 → GROUP BY/HAVING → 집합 연산 → JOIN`**으로, 관계형 데이터베이스에서 필요한 데이터를 원하는 형태로 조회하고 여러 테이블의 관계를 활용하는 방법을 학습했다.

**Keywords:** `SELECT`, `WHERE`, `CASE WHEN`, `LIKE`, `ORDER BY`, `Aggregate Function`, `GROUP BY`, `HAVING`, `UNION`, `INTERSECT`, `EXCEPT`, `JOIN`, `Cartesian Product`

# 📚 LECTURE NOTE

# 1. 데이터 조회 - SELECT

## 1-1. SELECT

`SELECT`는 테이블에서 **원하는 컬럼과 데이터를 조회**할 때 사용한다.

```sql
SELECT 컬럼명1, 컬럼명2
FROM 테이블명
[WHERE 조건식];
```

작성 순서와 실제 처리 순서는 다르다.

```text
작성 순서
SELECT → FROM → WHERE

기본적인 논리 처리 순서
FROM → WHERE → SELECT
```

`WHERE`처럼 `[ ]`로 표시된 부분은 선택사항이다.

### ALL / DISTINCT

```sql
SELECT [ALL | DISTINCT] 컬럼명
FROM 테이블명;
```

- `ALL` → 중복을 포함한 전체 값 조회, 기본값
- `DISTINCT` → 중복을 제거하여 조회

따라서 다음 두 코드는 동일하다.

```sql
SELECT ALL store_id FROM orders;

SELECT store_id FROM orders;
```

---

## 1-2. WHERE - 조건에 따른 조회

`WHERE`는 조회 범위를 **조건에 따라 좁힐 때** 사용한다.

### 비교·논리 연산자

```text
비교 연산자 → =, <, >, <=, >=, <>
논리 연산자 → AND, OR, NOT
```

여러 조건을 섞어 사용할 때는 **소괄호를 이용해 우선순위를 명확하게 표현**하는 것이 좋다.

특히 `OR` 조건이 있거나 다양한 연산자를 함께 사용할 때 주의한다.

### IN / NOT IN

여러 값 중 하나에 해당하는지 확인한다.

```sql
SELECT *
FROM customers
WHERE state = 'NY' OR state = 'CA';
```

다음과 같이 `IN`으로 표현할 수도 있다.

```sql
SELECT *
FROM customers
WHERE state IN ('NY', 'CA');
```

### BETWEEN

범위를 조건으로 지정한다.

```sql
SELECT *
FROM products
WHERE list_price >= 500
  AND list_price <= 1000;
```

다음과 동일하다.

```sql
SELECT *
FROM products
WHERE list_price BETWEEN 500 AND 1000;
```

`BETWEEN A AND B`는 **A 이상 B 이하**를 의미한다.

### IS NULL / IS NOT NULL

```sql
IS NULL
IS NOT NULL
```

- `IS NULL` → 값이 없는 상태인지 확인
- `IS NOT NULL` → NULL이 아닌지 확인

`NULL`은 일반적인 값이 아니라 **값이 없거나 알 수 없는 상태**이기 때문에 일반적인 비교·산술 연산을 할 수 없다.

```sql
SELECT NULL + 100;
```

```text
결과 → NULL
```

> **NULL이 포함된 일반적인 산술 연산의 결과도 NULL이 된다.**

---

## 1-3. CASE WHEN

`CASE WHEN`은 조건에 따라 **서로 다른 값을 부여**할 때 사용한다.

Python의 `if / elif / else`와 비슷하다.

```sql
SELECT
    order_id,
    product_id,
    list_price AS price,
    CASE
        WHEN list_price < 100 THEN '저가'
        WHEN list_price < 500 THEN '중가'
        ELSE '고가'
    END AS price_grade
FROM order_items;
```

```text
WHEN 조건1 → 참이면 결과1
WHEN 조건2 → 참이면 결과2
ELSE       → 모든 조건이 거짓
END        → CASE 종료
```

`END AS price_grade`처럼 결과에 새로운 컬럼명을 붙일 수 있다.

---

## 1-4. AS - 별칭

`AS`를 이용해 컬럼이나 테이블에 **Alias(별칭)** 를 지정할 수 있다.

```sql
SELECT list_price AS price
FROM products;
```

`AS`는 생략할 수도 있다.

```sql
SELECT list_price price
FROM products;
```

공백, 특수문자, 예약어 등이 포함된 별칭은 큰따옴표를 사용할 수 있다.

```sql
SELECT list_price AS "상품 가격"
FROM products;
```

---

## 1-5. LIKE - 문자열 패턴 검색

`LIKE`는 문자열의 패턴을 이용해 검색한다.

```sql
LIKE '키워드'      -- 정확히 일치
LIKE '키워드%'     -- 키워드로 시작
LIKE '%키워드'     -- 키워드로 끝남
LIKE '%키워드%'    -- 키워드 포함
```

`%`는 **0개 이상의 임의의 문자**를 의미하는 Wildcard다.

```sql
SELECT *
FROM products
WHERE product_name LIKE 'Electra%';
```

> 앞부분이 고정된 검색은 `%키워드%`처럼 앞에 Wildcard가 붙는 검색보다 인덱스를 활용하기 유리한 경우가 많다.

---

## 1-6. ORDER BY - 정렬

```sql
SELECT 컬럼명
FROM 테이블명
[WHERE 조건식]
ORDER BY 정렬컬럼 [ASC | DESC];
```

- `ASC` → 오름차순, 기본값
- `DESC` → 내림차순

```sql
SELECT *
FROM orders
ORDER BY store_id ASC, order_date DESC;
```

`ASC`는 기본값이므로 생략할 수 있다.

```sql
SELECT *
FROM orders
ORDER BY store_id, order_date DESC;
```

여러 컬럼을 사용하면 앞의 컬럼부터 순서대로 정렬한다.

```text
store_id 기준 1차 정렬
        ↓
같은 store_id 안에서
        ↓
order_date 기준 2차 정렬
```

예:

```sql
ORDER BY product_name ASC, list_price DESC;
```

→ 상품명을 오름차순으로 정렬한 뒤 **상품명이 같은 행 안에서** 가격을 내림차순으로 정렬한다.

# 2. 데이터 집계와 분석

## 2-1. 집계 함수 (Aggregate Function)

SQL에서도 Pandas처럼 기본적인 통계·집계 함수를 제공한다.

| 함수 | 기능 |
|---|---|
| `COUNT()` | 레코드 개수 |
| `SUM()` | 합계 |
| `AVG()` | 평균 |
| `MIN()` | 최솟값 |
| `MAX()` | 최댓값 |

### COUNT

```sql
COUNT(컬럼명)
```

→ 해당 컬럼에서 **NULL이 아닌 값의 개수**를 센다.

```sql
COUNT(*)
```

→ 전체 레코드 수를 센다.

```text
COUNT(column) → NULL 제외
COUNT(*)      → 전체 Row
```

---

## 2-2. GROUP BY

`GROUP BY`는 특정 컬럼의 **동일한 값을 기준으로 레코드를 그룹화**한다.

```sql
SELECT ...
FROM ...
[WHERE ...]
GROUP BY 그룹컬럼
[ORDER BY ...];
```

집계 함수와 함께 사용하는 경우가 많다.

```sql
SELECT
    brand_id,
    COUNT(*) AS "브랜드별 상품 개수"
FROM products
GROUP BY brand_id;
```

```text
전체 Products
      ↓
brand_id 기준 그룹화
      ↓
각 그룹별 COUNT(*)
      ↓
브랜드별 상품 개수
```

`GROUP BY`를 사용하면 `SELECT`에는 원칙적으로:

- `GROUP BY`에 포함된 컬럼
- 집계 함수가 적용된 값

을 사용한다.

예를 들어 `brand_id`로 그룹화하면서 개별 `product_name`을 그대로 조회할 수는 없다.

---

## 2-3. WHERE vs HAVING

집계 결과에 조건을 적용할 때는 `WHERE`가 아니라 **HAVING**을 사용한다.

```sql
SELECT
    brand_id,
    COUNT(*)
FROM products
GROUP BY brand_id
HAVING COUNT(*) >= 10;
```

| 구분 | 조건 적용 대상 |
|---|---|
| `WHERE` | 그룹화 전 개별 Row |
| `HAVING` | GROUP BY 이후 그룹·집계 결과 |

```text
FROM
 ↓
WHERE
 ↓
GROUP BY
 ↓
HAVING
 ↓
SELECT
 ↓
ORDER BY
```

> **WHERE = Row 조건 / HAVING = Group 조건**

# 3. 테이블 결합

## 3-1. RDBMS와 관계

현재 사용하는 DBMS는 **RDBMS(Relational Database Management System)** 로, 여러 테이블의 **관계(Relation)** 를 기반으로 데이터를 관리한다.

> 🐭 **토막 지식:** Edgar F. Codd가 관계형 데이터 모델의 이론적 기반을 제안했고, 이후 IBM의 Donald D. Chamberlin과 Raymond F. Boyce가 이를 바탕으로 SEQUEL(SQL의 전신)을 개발했다.

---

## 3-2. 집합 연산 (Set Operations)

두 `SELECT` 결과를 집합처럼 결합할 수 있다.

| 연산 | PostgreSQL | Oracle |
|---|---|---|
| 합집합 | `UNION` | `UNION` |
| 중복 포함 합집합 | `UNION ALL` | `UNION ALL` |
| 교집합 | `INTERSECT` | `INTERSECT` |
| 차집합 | `EXCEPT` | `MINUS` |

### UNION

```sql
SELECT ...
UNION
SELECT ...;
```

`UNION`은 중복을 제거한다.

반면:

```sql
UNION ALL
```

은 **중복을 유지**한다.

> SQL의 일반적인 조회 결과 자체에 중복이 없는 것은 아니다. `UNION`, `INTERSECT`, `EXCEPT` 같은 집합 연산은 기본적으로 중복을 제거한다.

### INTERSECT

두 조회 결과에 모두 존재하는 레코드를 반환한다.

```sql
SELECT order_id, order_date
FROM orders
WHERE order_date <= '2016-01-17'

INTERSECT

SELECT order_id, order_date
FROM orders
WHERE order_date >= '2016-01-15'

ORDER BY order_date;
```

### Subquery로 감싸기

집합 연산의 결과에 추가적인 가공이 필요한 경우 Subquery로 감쌀 수 있다.

```sql
SELECT *
FROM (
    SELECT order_id, order_date
    FROM orders
    WHERE order_date <= '2016-01-17'

    UNION

    SELECT order_id, order_date
    FROM orders
    WHERE order_date >= '2016-01-15'
) o
ORDER BY o.order_date;
```

> 단순 집합 연산만 필요한 경우 항상 Subquery로 감쌀 필요는 없다.

---

## 3-3. Cartesian Product

```sql
SELECT *
FROM orders, stores;
```

JOIN 조건 없이 두 테이블을 결합하면 두 테이블의 **모든 행 조합**이 만들어진다.

이를 **Cartesian Product(카테시안 곱 / 데카르트 곱)** 이라고 한다.

```text
orders = 100 Rows
stores = 3 Rows

100 × 3
   ↓
300 Rows
```

명시적으로 다음과 같이 표현할 수도 있다.

```sql
SELECT *
FROM orders
CROSS JOIN stores;
```

의도하지 않은 Cartesian Product는 결과 데이터가 급격하게 증가하여 서버에 부담을 줄 수 있으므로 JOIN 조건에 주의한다.

---

## 3-4. JOIN

`JOIN`은 두 테이블에서 **공통적인 관계를 기준으로 데이터를 연결하여 하나의 결과처럼 조회**하는 방법이다.

기존 방식:

```sql
SELECT *
FROM orders, stores
WHERE orders.store_id = stores.store_id;
```

JOIN 문법:

```sql
SELECT *
FROM orders o
JOIN stores s
    ON o.store_id = s.store_id;
```

---

### INNER JOIN

두 테이블에서 JOIN 조건을 만족하는 데이터만 조회한다.

```sql
SELECT *
FROM orders o
INNER JOIN stores s
    ON o.store_id = s.store_id;
```

`INNER`는 기본값이므로 생략할 수 있다.

```sql
SELECT *
FROM orders o
JOIN stores s
    ON o.store_id = s.store_id;
```

---

### OUTER JOIN

| JOIN | 결과 |
|---|---|
| `LEFT JOIN` | 왼쪽 전체 + 오른쪽에서 일치하는 데이터 |
| `RIGHT JOIN` | 오른쪽 전체 + 왼쪽에서 일치하는 데이터 |
| `FULL OUTER JOIN` | 양쪽 데이터 전체 |

#### LEFT JOIN

```text
LEFT TABLE  → 반드시 모두 출력
RIGHT TABLE → 조건이 일치하는 데이터 연결
```

#### RIGHT JOIN

```text
LEFT TABLE  → 조건이 일치하는 데이터 연결
RIGHT TABLE → 반드시 모두 출력
```

#### FULL OUTER JOIN

```text
LEFT TABLE + RIGHT TABLE
→ 양쪽 모두 유지
```

---

## 3-5. 여러 테이블 JOIN

여러 테이블을 연속해서 JOIN할 수도 있다.

```sql
SELECT
    o.order_id,
    o.order_date,
    s.store_name,
    f.first_name AS staff_first_name,
    f.last_name AS staff_last_name
FROM orders o
LEFT JOIN customers c
    ON o.customer_id = c.customer_id
LEFT JOIN stores s
    ON o.store_id = s.store_id
LEFT JOIN staffs f
    ON o.staff_id = f.staff_id;
```

```text
orders
  │
  ├── customer_id → customers
  ├── store_id ───→ stores
  └── staff_id ───→ staffs
```

관계형 데이터베이스에서는 각 데이터를 테이블로 분리해서 관리하고 **테이블 간 관계를 이용해 필요한 시점에 JOIN하여 조회**한다.

---

## 3-6. JOIN vs 집합 연산

| 구분 | JOIN | UNION |
|---|---|---|
| 기준 | 테이블 간 관계/조건 | 두 SELECT 결과 |
| 결합 방향 | 주로 열 방향 | 행 방향 |
| 주요 목적 | 관련 정보 연결 | 결과 집합 합치기 |
| 컬럼 구조 | 서로 다른 컬럼 연결 가능 | 컬럼 수와 대응 타입이 호환되어야 함 |

```text
JOIN
→ 관계를 따라 옆으로 연결

UNION
→ 같은 구조의 결과를 아래로 연결
```

> **JOIN = 옆으로 관계 연결 / UNION = 아래로 결과 연결**

## 🔗 오늘의 흐름

```text
SQL로 데이터 다루기
        │
        ├───────────────┬─────────────────┐
        ▼               ▼                 ▼
   ① 데이터 조회     ② 집계·분석       ③ 테이블 결합
        │               │                 │
     SELECT         COUNT/SUM/...      집합 연산
        ↓               ↓                 ↓
     WHERE          GROUP BY           UNION
        ↓               ↓             INTERSECT
 CASE / LIKE         HAVING             EXCEPT
        ↓                                 ↓
   ORDER BY                         Cartesian Product
                                          ↓
                                         JOIN
                                          ↓
                              INNER / LEFT / RIGHT / FULL
```

### 오늘의 핵심

> **SQL은 필요한 데이터를 `SELECT`하고 → `WHERE`로 고르고 → `GROUP BY`로 묶어 분석하고 → 여러 테이블에 흩어진 데이터는 `JOIN`을 통해 관계를 따라 다시 연결한다.**
