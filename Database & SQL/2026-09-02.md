# LECTURE NOTE

## 1. Database & SQL

### 1-1. 데이터와 정보

**Data(데이터)**는 아직 특정한 맥락에서 해석되지 않은 **원시 값**이다.

```text
이름
나이
구매 금액
구매 시간
...
```

**Information(정보)**은 데이터를 특정 목적과 맥락에 맞게 해석하여 **의미를 부여한 결과**이다.

```text
Data
 ↓
맥락 + 해석
 ↓
Information
```

---

### 1-2. DBMS

**DBMS (Database Management System)**는 데이터를 저장·조회·수정·삭제하고 관리하기 위한 소프트웨어이다.

```text
사용자 / Application
        ↓
       DBMS
        ↓
     Database
```

---

### 1-3. SQL

**SQL (Structured Query Language)**은 관계형 데이터베이스와 상호작용하기 위해 사용하는 언어이다.

**Query(쿼리)**는 데이터베이스에 보내는 **질의 또는 요청**을 의미한다.

```text
"회원 데이터를 보여줘"
        ↓
SQL Query
        ↓
DBMS
        ↓
Database
        ↓
결과 반환
```

## 2. RDBMS 기본 구조

**RDBMS (Relational Database Management System)**는 데이터를 **Table 형태로 관리하고 테이블 사이의 관계(Relationship)를 이용하는 DBMS**이다.

대표적인 RDBMS:

- MySQL
- MariaDB
- PostgreSQL
- Oracle Database
- Microsoft SQL Server

### PostgreSQL과 Vector DB

PostgreSQL에서는 `pgvector`와 같은 확장 기능을 이용하여 **Vector 데이터를 저장하고 유사도 검색**을 수행할 수 있다.

Embedding Vector를 검색하는 **RAG 시스템**을 구현할 때 활용할 수 있다.

```text
문서
 ↓
Embedding
 ↓
Vector
 ↓
PostgreSQL + pgvector
 ↓
유사한 Vector 검색
 ↓
RAG
```

### RDBMS의 기본 구성

| 개념 | 의미 |
|---|---|
| **Table** | 데이터를 저장하는 구조 |
| **Row / Record** | 하나의 데이터 레코드 |
| **Column / Field** | 데이터의 속성 |
| **Cell** | 특정 Row와 Column이 만나는 하나의 값 |
| **Schema** | 테이블의 구조와 제약조건 등을 정의한 설계 |

예:

| user_id | name | age |
|---|---|---:|
| 1 | Kim | 25 |
| 2 | Lee | 27 |

```text
Column → user_id / name / age
Row    → 한 명의 회원 정보
Cell   → Kim, 25 등의 개별 값
```

## 3. 데이터 무결성

**데이터 무결성(Data Integrity)**은 데이터가 **정확하고 일관된 상태를 유지하도록 하는 것**이다.

### 3-1. 도메인 무결성 (Domain Integrity)

각 Column의 값이 **정해진 자료형·범위·규칙을 만족하도록 제한**한다.

```text
AGE Column
→ INTEGER
→ 문자 입력 X
```

### 3-2. 개체 무결성 (Entity Integrity)

각 Row를 고유하게 식별할 수 있도록 **Primary Key(기본키)**를 사용한다.

Primary Key는:

```text
중복 X
NULL X
```

### 3-3. 참조 무결성 (Referential Integrity)

테이블 사이의 관계에서 **Foreign Key(외래키)가 참조하는 값의 일관성**을 유지한다.

```text
MEMBERS
user_id = 10
      ↑
      │ Foreign Key
      │
ORDERS
user_id = 10
```

## 4. Data Type

### 4-1. 숫자형

#### 정수

| Type | 크기 |
|---|---:|
| `SMALLINT` | 2 Byte |
| `INTEGER / INT` | 4 Byte |
| `BIGINT` | 8 Byte |

#### 실수 / 정확한 소수

| Type | 특징 |
|---|---|
| `REAL` | 4 Byte 부동소수점 |
| `DOUBLE PRECISION` | 8 Byte 부동소수점 |
| `DECIMAL(p, s)` | 정확한 자릿수를 지정하는 숫자 |

```text
DECIMAL(p, s)

p = 전체 유효 자릿수
s = 소수점 이하 자릿수
```

---

### 4-2. 문자형

| Type | 특징 |
|---|---|
| `CHAR(n)` | 고정 길이 문자열 |
| `VARCHAR(n)` | 최대 길이를 지정한 가변 문자열 |
| `TEXT` | 길이가 가변적인 긴 문자열 |

---

### 4-3. 논리형

```text
BOOLEAN
```

논리 상태를 표현하며 PostgreSQL에서는 `TRUE`, `FALSE` 외에 **`NULL` 상태도 가능**하다.

> `NULL`은 세 번째 Boolean 값이 아니라 **값이 없거나 알 수 없음을 나타내는 SQL의 특별한 상태**이다.

---

### 4-4. 날짜와 시간

| Type | 의미 |
|---|---|
| `DATE` | 날짜 |
| `TIME` | 시간 |
| `TIMESTAMP` | 날짜 + 시간 |
| `TIMESTAMPTZ` | 날짜 + 시간 + Time Zone 고려 |

> PostgreSQL에서는 `TIMESTAMPTZ`가 `timestamp with time zone`을 의미한다.

---

### 4-5. JSON

PostgreSQL에서는 대표적으로 다음 두 자료형을 사용할 수 있다.

```text
JSON
JSONB
```

- `JSON` → 입력된 JSON 텍스트 표현을 보존
- `JSONB` → 내부적으로 Binary 형태로 처리되어 **검색·인덱싱 등에 유리**

따라서 데이터를 자주 조회하거나 처리하는 경우 `JSONB`가 많이 활용된다.

---

### 4-6. 기타

#### ENUM

미리 정의된 값 중 하나만 선택하도록 제한할 수 있다.

```text
READY
ORDER
IN_CASH
DELIVERY
```

> ENUM 선언 방법은 사용하는 DBMS에 따라 다르다.

#### Vector

```text
VECTOR(차원 수)
```

Embedding과 같은 **고차원 Vector 데이터**를 저장할 때 활용할 수 있다.

## 5. ERD 실습

### 실습 환경

**ERD Cloud**

### 실습 목적

쇼핑몰 운영을 위한 데이터베이스 구조 설계

### 회원 정보 Table

```text
MEMBERS

아이디
비밀번호
이름
휴대전화 번호
이메일
성별
생일
주소
우편번호
가입일
```

예시:

| Logical Name | Physical Name | Data Type |
|---|---|---|
| 아이디 | `user_id` | VARCHAR(50) |
| 비밀번호 | `password` | VARCHAR(65) |
| 이름 | `name` | VARCHAR |
| 휴대전화 번호 | `phone_num` | VARCHAR |
| 이메일 | `email` | VARCHAR |
| 가입일 | `created_at` | TIMESTAMP |

### Logical Name / Physical Name

- **Logical Name (논리명)** → 사람이 이해하기 쉬운 업무상의 이름  
  예: `회원 아이디`
- **Physical Name (물리명)** → 실제 Database에서 사용하는 이름  
  예: `user_id`

### Primary Key (기본키)

**하나의 Row를 고유하게 식별할 수 있는 Column 또는 Column의 조합**이다.

```text
MEMBERS

user_id  ← Primary Key
name
email
...
```

Primary Key는:

```text
중복 X
NULL X
```

즉, 하나의 회원을 **유일하게 식별**할 수 있어야 한다.
