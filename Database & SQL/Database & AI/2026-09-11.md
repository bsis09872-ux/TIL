## 🔄 REVIEW - PostgREST & REST API

### PostgREST

Supabase에서 Table을 생성하면 내부적으로 **PostgREST**를 이용해 REST API를 자동으로 제공한다.

**PostgREST**는 PostgreSQL Database를 추가적인 Backend API 코드 작성 없이 **REST API 형태로 사용할 수 있도록 해주는 Open Source Web Server**이다.

### API

**API (Application Programming Interface)**는 서로 다른 Application이나 Software가 기능과 데이터를 주고받을 수 있도록 정의된 **Interface**이다.

### REST API

**REST (Representational State Transfer)**는 Resource를 URI로 표현하고 HTTP Method를 이용해 해당 Resource에 대한 행위를 표현하는 방식이다.

| 구분 | 역할 | 예시 |
|---|---|---|
| Resource | 접근할 대상 | `/products/1` |
| HTTP Method | Resource에 대한 행위 | `GET`, `POST`, `PUT`, `PATCH`, `DELETE` |
| URI | Resource를 식별하는 Identifier | `/products/1` |
| URL | Resource의 실제 위치를 나타내는 주소 | `https://example.com/products/1` |

대표적인 HTTP Method:

```text
GET    → 조회
POST   → 생성
PUT    → 전체 수정
PATCH  → 일부 수정
DELETE → 삭제
```

> **URI = Resource 식별**, **URL = Resource의 위치**  
> URL은 URI의 한 형태로 볼 수 있다.

### API vs SDK

- **API** → Software끼리 어떻게 요청하고 응답할지 정의한 Interface
- **SDK** → 특정 Service나 Platform을 개발할 때 필요한 Library와 도구를 묶어 제공하는 개발 도구

예를 들어 Supabase Python SDK를 사용하면 REST 요청을 직접 작성하지 않고 Python Method를 통해 Supabase API를 사용할 수 있다.

# 1. Builder Pattern & Data Class

## 1-1. Builder Pattern

**Builder Pattern**은 하나의 객체를 만들 때 필요한 값을 단계적으로 설정하여 객체를 생성하는 방식이다.

객체 생성에 필요한 Parameter가 많아질수록 생성자에 모든 값을 한 번에 전달하는 것보다 Builder를 이용하면 코드의 의미와 구조를 명확하게 표현할 수 있다.

```text
Object
← 값 설정
← 값 설정
← 값 설정
← build()
```

---

## 1-2. Data Class

Python의 `dataclass`는 주로 **데이터를 저장하기 위한 Class를 간단하게 정의**할 수 있도록 도와준다.

```python
from dataclasses import dataclass

@dataclass
class Product:
    name: str
    price: int
```

일반 Class에서 반복적으로 작성해야 하는 초기화 등의 코드를 줄일 수 있다.

### `kw_only=True`

```python
@dataclass(kw_only=True)
class Product:
    name: str
    price: int
```

`kw_only=True`를 사용하면 객체를 생성할 때 값을 **Keyword Argument**로 전달하도록 제한할 수 있다.

```python
Product(name="Keyboard", price=50000)
```

이를 통해 Argument의 의미를 보다 명확하게 표현할 수 있다.

# 2. Python Type Hint

Python에서는 변수, Parameter, 반환값에 **Type Hint**를 작성할 수 있다.

```python
num: int = 100
title: str = "abc"
```

Collection에도 Type을 표현할 수 있다.

```python
numbers: list[int]
point: tuple[int, int]
user: dict[str, str]
```

Class 또한 Type으로 사용할 수 있다.

```python
product: Product
```

### 함수 Type Hint

```python
def add(a: int, b: int) -> int:
    return a + b
```

`-> int`는 함수의 반환값이 `int`라는 의미이다.

반환값이 없는 함수는:

```python
def print_message(message: str) -> None:
    print(message)
```

처럼 `None`으로 표현한다.

> Python의 Type Hint는 기본적으로 **실행 시 Type을 강제로 제한하는 기능이 아니라**, 코드의 의도와 Type 정보를 명확하게 표현하기 위한 기능이다.

# 3. PostgreSQL Stored Program

## 3-1. Stored Program

DB Server 내부에 미리 정의해 두고 호출하여 사용하는 Program을 **Stored Program**이라고 한다.

대표적으로:

- **Function**
- **Procedure**
- **Trigger**

가 있다.

DB 내부에 Business Logic을 구성하면 여러 SQL 작업을 하나의 작업 단위로 묶거나 반복적인 DB 로직을 재사용할 수 있다.

---

# 4. Function vs Procedure

## 4-1. Function

Function은 **Parameter를 입력받아 결과를 반환할 수 있는 DB Program**이다.

```sql
SELECT 함수명(...);
```

`AVG()`, `SUM()`과 같이 SQL 안에서 사용하는 함수도 Function의 대표적인 예이다.

```sql
SELECT AVG(price)
FROM products;
```

직접 Function을 정의하여 여러 SQL 작업을 하나의 Logic으로 묶을 수도 있다.

### Transaction

Function 내부의 작업은 하나의 Transaction 안에서 처리되므로 중간에 처리되지 않은 Exception이 발생하면 작업 전체를 Rollback하여 데이터 불일치를 방지할 수 있다.

예를 들어 주문 생성 과정에서:

```text
orders INSERT
      +
order_items INSERT
```

를 하나의 Function으로 묶으면 `order_items` 처리 중 오류가 발생했을 때 주문만 남는 **유령 주문**을 방지하는 데 활용할 수 있다.

> Function 내부에서는 일반적인 `COMMIT`, `ROLLBACK`을 직접 수행하는 TCL 제어를 할 수 없다.

---

## 4-2. Procedure

Procedure는 Function처럼 DB 내부에 Logic을 작성하지만, **독립적인 작업을 수행하는 Program**으로 사용할 수 있다.

호출:

```sql
CALL 프로시저명();
```

특히 반복적인 Batch 작업이나 대량 데이터 처리처럼 중간에 Transaction을 나누어 처리해야 하는 작업에 활용할 수 있다.

```text
5,000 Rows 처리
     ↓
COMMIT
     ↓
5,000 Rows 처리
     ↓
COMMIT
     ↓
...
```

대량 데이터를 하나의 Transaction으로 오래 처리하면 Lock이 장시간 유지될 수 있으므로, Procedure를 이용해 일정 단위로 작업하고 Transaction을 나누는 방식도 사용할 수 있다.

---

## 4-3. Function vs Procedure

| 구분 | Function | Procedure |
|---|---|---|
| 호출 | `SELECT` 등에서 사용 가능 | `CALL` |
| 반환값 | 반환값 정의 가능 | Function과 사용 방식이 다름 |
| Transaction 제어 | 내부 `COMMIT`, `ROLLBACK` 불가 | Transaction 제어 가능 |
| 활용 예 | 주문·결제 등 하나의 작업 단위 | Batch·대량 데이터 처리 |

> **Function = 하나의 Transaction으로 묶어 처리**  
> **Procedure = 독립적인 작업 및 Transaction 제어가 필요한 작업**

---

# 5. Trigger

**Trigger**는 특정 DB Event가 발생했을 때 자동으로 실행되는 Stored Program이다.

예를 들어:

```text
INSERT
UPDATE
DELETE
   ↓
Trigger 실행
```

과 같이 특정 Table의 데이터 변경을 감지해 추가 Logic을 실행할 수 있다.

Function이나 Procedure가 **직접 호출**되는 방식이라면, Trigger는 설정된 Event가 발생했을 때 **자동 실행**된다는 차이가 있다.

# 6. 실습

오늘은 Function과 Procedure의 개념만 학습하는 것이 아니라 실제 Shopping Project의 주문 Logic 등에 적용할 수 있도록 **Function / Procedure 구현 코드를 작성**했다.

또한 Python에서는 Builder Pattern과 Data Class를 이용해 객체 생성 Logic을 구성하고, Type Hint를 함께 사용하여 데이터 구조를 명확하게 표현하는 방법을 실습했다.

### Snapshot Pattern

주문 시점의 상품명과 가격을 `order_items`에 따로 저장하는 이유도 함께 복습했다.

```text
products.price
→ 현재 상품 가격

order_items.item_price
→ 주문 당시 가격
```

원본 상품의 이름이나 가격이 이후 변경되더라도 과거 주문 정보가 변경되지 않도록 **주문 시점의 데이터를 복사하여 저장하는 방식**을 **Snapshot Pattern**이라고 한다.

## 📝 DAILY QUEST

### 1. Function과 Transaction ✅

**질문**  
주문 생성 시 `orders` INSERT 이후 `order_items` INSERT가 실패했을 때, 두 작업을 Function으로 묶으면 얻을 수 있는 핵심 효과는?

**정답**  
Function 내부의 Logic이 하나의 Transaction으로 처리되므로 중간에 오류가 발생하면 이전 INSERT까지 Rollback되어 **데이터 불일치와 유령 주문을 방지**할 수 있다.

---

### 2. Snapshot Pattern ❌

**내 답:** Procedure  
**정답:** **Snapshot Pattern**

주문 당시 상품명과 가격을 `order_items`에 별도로 저장하여, 이후 원본 상품 정보가 변경되더라도 과거 주문 내역이 바뀌지 않도록 한다.

> **Snapshot = 특정 시점의 값을 그대로 보존**

---

### 3. Function vs Procedure ❌

Function과 Procedure는 Transaction 제어 방식과 실제 활용 목적에서 차이가 있다.

- **Function** → 하나의 Transaction 안에서 처리되는 Logic, SQL 내부에서도 활용 가능
- **Procedure** → `CALL`로 독립 실행하며 Transaction을 나누어 처리하는 Batch 작업 등에 활용 가능

> Function과 Procedure는 단순히 반환값 유무만으로 구분하는 것이 아니라 **호출 방식과 Transaction 제어 방식**까지 함께 이해해야 한다.

---

### 4. 대용량 Batch 처리 ✅

5만 건의 데이터를 한 번에 처리하면 Lock이 오래 유지될 수 있다.

Procedure에서 예를 들어 5,000건씩 처리하고 중간에 `COMMIT`하면 Lock 유지 시간을 줄여 다른 Transaction이 장시간 대기하는 상황을 완화할 수 있다.

---

### 5. `GET DIAGNOSTICS` ❌

**내 답:** PL/pgSQL  
**정답:** **`GET DIAGNOSTICS`**

직전에 수행한 SQL로 영향을 받은 Row 수를 가져올 수 있다.

```sql
GET DIAGNOSTICS v_rows_affected = ROW_COUNT;
```

- `PL/pgSQL` → PostgreSQL에서 Procedure/Function 등을 작성할 때 사용하는 Procedural Language
- `GET DIAGNOSTICS` → 실행 결과와 관련된 정보를 가져오는 구문
- `ROW_COUNT` → 직전 SQL에 의해 영향을 받은 Row 수
