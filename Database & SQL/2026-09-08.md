# Lecture Note

## 1. 서브쿼리 (Subquery)

**SELECT문 내부에 또 다른 SELECT문이 포함된 질의**

```sql
SELECT ...
FROM ...
WHERE column = (
    SELECT ...
);
```

일반적인 비상관 서브쿼리에서는 내부 쿼리가 먼저 실행되고 그 결과를 외부 쿼리가 사용한다.

```text
내부 쿼리 → 외부 쿼리
```

---

## 2. 서브쿼리의 위치에 따른 분류

### SELECT절 → 스칼라 서브쿼리 (Scalar Subquery)

스칼라(Scalar)는 **단일 값**을 의미한다.

```sql
SELECT
    name,
    (SELECT ...)
FROM ...
```

- `SELECT`절에 위치
- 반드시 **1개의 행 × 1개의 열**, 즉 하나의 값만 반환
- 여러 행을 반환하면 오류 발생

> **SELECT → Scalar**

---

### FROM절 → 인라인 뷰 (Inline View)

서브쿼리의 조회 결과를 하나의 **가상 테이블**처럼 사용하는 방법이다.

```sql
SELECT ...
FROM (
    SELECT ...
) AS sub;
```

- 실제 물리적인 테이블은 아님
- 서브쿼리의 조회 결과를 테이블처럼 사용
- FROM절에 위치

> **FROM → Inline View**

---

### WHERE절 → WHERE절 서브쿼리

```sql
SELECT ...
FROM ...
WHERE column IN (
    SELECT ...
);
```

조건을 판단하기 위해 서브쿼리의 결과를 사용한다.

> **WHERE → WHERE절 서브쿼리**

---

## 3. 상관 서브쿼리 (Correlated Subquery)

상관 서브쿼리는 단순히 `WHERE`절에 들어가는 서브쿼리를 의미하는 것이 아니다.

**외부 쿼리의 행 정보를 내부 서브쿼리가 참조하는 방식**이다.

```sql
SELECT *
FROM orders o
WHERE EXISTS (
    SELECT 1
    FROM customers c
    WHERE c.customer_id = o.customer_id
);
```

내부 서브쿼리에서 외부 쿼리의 `o.customer_id`를 참조하고 있다.

> **외부 쿼리의 값을 내부 서브쿼리가 참조 → 상관 서브쿼리**

⚠️ **헷갈렸던 부분**

```text
상관 서브쿼리 = WHERE절 서브쿼리
```

가 아니다.

서브쿼리의 **위치에 따른 분류**와 **외부 쿼리 참조 여부에 따른 분류**를 구별해야 한다.

---

## 4. 서브쿼리의 반환 결과에 따른 분류

### 단일행 서브쿼리

결과가 하나의 행으로 반환되는 서브쿼리

### 다중행 서브쿼리

여러 행이 반환되는 서브쿼리

대표적인 연산자:

- `IN`
- `NOT IN`
- `EXISTS`
- `NOT EXISTS`

---

## 5. IN과 EXISTS

### IN

서브쿼리가 반환한 **값 목록과 비교**한다.

```sql
WHERE customer_id IN (
    SELECT customer_id
    FROM vip_customer
);
```

> "이 값이 목록 안에 있는가?"

### EXISTS

서브쿼리의 조건을 만족하는 **행이 존재하는지** 확인한다.

```sql
WHERE EXISTS (
    SELECT 1
    FROM vip_customer v
    WHERE v.customer_id = c.customer_id
);
```

조건을 만족하는 행이 하나라도 존재하면 `TRUE`가 된다.

> "조건을 만족하는 데이터가 존재하는가?"

💡 대량 데이터에서는 상황에 따라 `EXISTS`가 유리한 경우가 있다.

---

## 6. NOT IN과 NULL 주의

`NOT IN`을 사용할 때 서브쿼리 결과에 `NULL`이 포함되어 있다면 주의해야 한다.

```sql
WHERE id NOT IN (1, 2, NULL)
```

논리적으로 보면 다음과 비슷하다.

```text
id ≠ 1
AND id ≠ 2
AND id ≠ NULL
```

SQL에서 `NULL`은 알 수 없는 값을 의미하기 때문에 `NULL`과의 비교 결과 역시 일반적인 `TRUE/FALSE`가 아닌 `UNKNOWN`이 될 수 있다.

WHERE절은 최종 결과가 `TRUE`인 행만 선택하기 때문에 예상과 달리 결과가 나오지 않을 수 있다.

⚠️ **NOT IN + NULL → 예상치 못한 빈 결과 가능**

💡 이런 경우 `NOT EXISTS` 사용을 고려한다.

```text
NOT IN + NULL ⚠️
        ↓
NOT EXISTS 💡
```

# Transaction & ACID

## 8. 트랜잭션 (Transaction)

여러 DB 작업을 **하나의 논리적인 작업 단위**로 묶어 처리하는 것

예를 들어 계좌이체는:

```text
A 계좌 -10,000원
        +
B 계좌 +10,000원
```

두 작업이 모두 성공해야 하나의 정상적인 거래가 된다.

```text
Transaction 시작
      ↓
여러 SQL 작업
      ↓
   모두 성공?
   ↙      ↘
 YES       NO
 ↓          ↓
COMMIT   ROLLBACK
```

- `COMMIT` → 작업 결과 확정
- `ROLLBACK` → 작업 이전 상태로 되돌림

---

## 9. ACID 원칙

트랜잭션이 안정적으로 수행되기 위해 지켜야 하는 핵심 원칙이다.

### Atomicity - 원자성

> **모두 성공하거나 모두 실패한다.**

트랜잭션 중 일부 작업만 성공한 상태로 남지 않도록 한다.

### Consistency - 일관성

트랜잭션 전후에도 데이터베이스가 정의된 규칙과 제약조건을 만족하는 일관된 상태를 유지해야 한다.

### Isolation - 격리성

동시에 실행되는 여러 트랜잭션이 서로의 작업에 부적절하게 영향을 주지 않도록 한다.

### Durability - 지속성

트랜잭션이 성공적으로 완료되어 `COMMIT`되면 그 결과가 지속적으로 보존되어야 한다.

> **ACID = 원자성 · 일관성 · 격리성 · 지속성**

⚠️ `ROLLBACK` 자체가 ACID 원칙 중 하나인 것은 아니다.  
`ROLLBACK`은 트랜잭션을 취소하는 기능이며, 특히 **원자성(Atomicity)**을 구현하는 데 관련된다.

### Q2. NULL이 포함된 서브쿼리에서 주의해야 할 연산자

**정답: `NOT IN`**

서브쿼리 결과에 `NULL`이 포함되면 `NOT IN` 사용 시 예상치 못하게 결과가 나오지 않을 수 있다.

```text
NOT IN + NULL ⚠️
→ NOT EXISTS 사용 고려 💡
```

⚠️ **오답 원인**

`비교 연산자`라고 넓게 생각했지만 문제에서는 NULL에 영향을 받는 **구체적인 연산자**를 묻고 있었다.

---

### Q3. 스칼라 서브쿼리

**정답**

> SELECT절에 위치하며 반드시 하나의 행, 하나의 열만 반환해야 한다.

```text
SELECT
  ↓
Scalar Subquery
  ↓
1 Row × 1 Column
  ↓
1 Value
```

여러 행이 반환되면 오류가 발생한다.

---

### Q4. 상관 서브쿼리

**정답: 상관 서브쿼리 (Correlated Subquery)**

> 외부 쿼리의 각 행 정보를 서브쿼리 내부에서 참조하여 서로 연관되어 실행되는 서브쿼리

핵심 방향:

```text
외부 쿼리의 값
      ↓
내부 서브쿼리가 참조
      ↓
Correlated Subquery
```

---

### Q5. IN과 EXISTS의 차이

**정답**

> EXISTS는 조건을 만족하는 행이 하나라도 존재하면 TRUE가 되며 NULL의 영향을 받지 않는다.

```text
IN
→ 반환된 값 목록과 비교

EXISTS
→ 조건을 만족하는 행의 존재 여부 확인
```

`EXISTS`는 조건을 만족하는 행의 **존재 여부**가 핵심이다.

# 오늘의 핵심 정리

```text
서브쿼리
│
├─ 위치 기준
│   ├─ SELECT → 스칼라 서브쿼리
│   ├─ FROM   → 인라인 뷰
│   └─ WHERE  → WHERE절 서브쿼리
│
├─ 결과 행 기준
│   ├─ 단일행 서브쿼리
│   └─ 다중행 서브쿼리
│
└─ 외부 쿼리 참조 여부
    └─ 상관 서브쿼리
```

그리고 오늘 특히 기억해야 할 세 가지:

```text
① SELECT → Scalar → 단일 값

② 외부 쿼리 값을 내부 쿼리가 참조
   → 상관 서브쿼리

③ NOT IN + NULL ⚠️
   → NOT EXISTS 💡
```

트랜잭션은:

```text
여러 DB 작업
→ 하나의 논리적 작업으로 묶음
→ 성공: COMMIT
→ 실패: ROLLBACK

ACID
→ Atomicity
→ Consistency
→ Isolation
→ Durability
```
