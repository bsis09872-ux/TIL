### A. Jinja2 — 템플릿 상속과 공통 UI

**1. Template Inheritance (템플릿 상속)**

공통 레이아웃을 부모 템플릿으로 정의하고, 개별 페이지에서는 변경되는 영역만 작성한다.

튜터 코드의 파일 구조:

```text
src/
├── main.py
├── templates/
│   ├── layouts/
│   │   └── base.html
│   ├── outlines/
│   │   ├── header.html
│   │   └── footer.html
│   ├── common_macro.html
│   ├── practice1.html
│   ├── practice2.html
│   └── practice3.html
└── static/
    ├── css/
    │   └── style.css
    └── img/
        └── image.png
```

**부모 템플릿 — `layouts/base.html`**

```html
<body>
  {% include 'outlines/header.html' %}

  <main>{% block content %} {% endblock %}</main>

  {% include 'outlines/footer.html' %}
</body>
```

**자식 템플릿 — `practice2.html`**

```html
{% extends "layouts/base.html" %} {% block content %}
<h2>치환된 영역...</h2>
{% endblock %} {% block title %} 사이트 제목!! {% endblock %}
```

| 문법      | 역할                           |
| --------- | ------------------------------ |
| `extends` | 부모 템플릿 상속               |
| `block`   | 자식 페이지가 변경할 영역 정의 |
| `include` | 헤더·푸터 등 별도 템플릿 삽입  |
| `macro`   | 반복되는 UI를 함수처럼 재사용  |

**새롭게 이해한 점**

React에서 공통 Layout과 컴포넌트를 재사용하는 것처럼, Jinja2에서도 HTML의 공통 구조를 분리할 수 있다.

다만 React 컴포넌트는 JavaScript 기반이고, Jinja2는 서버에서 HTML을 생성하는 템플릿 엔진이라는 차이가 있다.

### B. StaticFiles — CSS·이미지 연결

FastAPI에서는 `StaticFiles`를 사용해 정적 파일 디렉터리를 URL 경로에 연결한다.

**튜터 코드 — `chapter03-2/src/main.py`**

```python
from fastapi.staticfiles import StaticFiles

app.mount(
    "/static2",
    StaticFiles(directory=os.path.join(CURRENT_DIR, "static")),
    name="static"
)

app.mount(
    "/img",
    StaticFiles(directory=os.path.join(CURRENT_DIR, "static/img")),
    name="img"
)
```

**HTML에서 CSS 연결**

```html
<link
  rel="stylesheet"
  type="text/css"
  href="{{ url_for('static', path='/css/style.css') }}"
/>
```

**핵심 개념**

- `app.mount()`: URL 경로에 별도의 애플리케이션 또는 정적 파일 제공 기능 연결
- `StaticFiles()`: 정적 파일을 제공하는 ASGI 애플리케이션
- `directory`: 실제 파일이 저장된 디렉터리
- `name`: `url_for()`에서 참조할 이름

**주의**

튜터 코드의 URL 접두사는 `/static2`이지만 이름은 `static`이다.

따라서 `url_for('static', ...)`는 이름을 기준으로 경로를 생성한다. `name`과 URL 접두사가 반드시 같아야 하는 것은 아니다.

또한 `app.mount()`는 메서드 호출이므로 `@`를 붙이지 않는다.

### C. HTML Form — 요청 데이터 전송

HTML의 `<form>`은 사용자가 입력한 데이터를 서버에 전송한다.

**튜터 코드 — `practice3.html`**

```html
<form method="post" action="/practice3/process">
  제목: <input type="text" name="title" /><br />
  내용: <textarea name="content"></textarea><br />
  <button type="submit">작성하기</button>
</form>
```

**서버 — `main.py`**

```python
from fastapi import Form

@app.post("/practice3/process")
async def jinja_practice3_process(
    title: str = Form(description="제목"),
    content: str = Form(description="내용")
):
    logger.info(f"title={title}, content={content}")
```

**데이터 흐름**

```text
HTML 입력 필드
    ↓
name="title", name="content"
    ↓
POST /practice3/process
    ↓
FastAPI Form()
    ↓
Python 변수 title, content
    ↓
서버 로그 출력
```

**새롭게 이해한 점**

HTML의 `name` 속성은 서버에서 데이터를 구분하는 키 역할을 한다.

`Form()`으로 값을 받는 것과 브라우저에 처리 결과를 표시하는 것은 별개의 작업이다.

튜터 코드의 `/practice3/process`는 데이터를 로그에 기록하지만 별도 응답 본문을 반환하지 않는다. 사용자에게 완료 화면을 보여주려면 HTML 응답, 템플릿 또는 리다이렉트 등을 반환해야 한다.

### D. File·UploadFile·Form — 파일 업로드

FastAPI에서 사용하는 주요 객체:

```python
from fastapi import FastAPI, Request, File, UploadFile, Form
```

| 객체         | 역할                        |
| ------------ | --------------------------- |
| `Form()`     | 일반 폼 필드 수신           |
| `File()`     | 파일 입력 매개변수 선언     |
| `UploadFile` | 업로드된 파일을 다루는 객체 |

**예제 — 폼 필드와 파일 함께 수신**

```python
from fastapi import FastAPI, Form, File, UploadFile

app = FastAPI()

@app.post("/file")
async def upload_file(
    title: str = Form(),
    file: UploadFile = File()
):
    return {
        "title": title,
        "filename": file.filename,
        "content_type": file.content_type
    }
```

**[보충 예제]**

위 코드는 오늘 배운 내용을 조합한 예제이며, 튜터 저장소에 완성된 업로드 구현으로 존재하는 코드는 아니다.

튜터 GitHub의 `chapter03-2`에서는 `/file` POST 핸들러가 `pass`로 남아 있고, `UploadFile` 수신 예제는 주석 처리되어 있다.

**파일 업로드를 받기 위한 패키지**

```bash
uv add python-multipart
```

- FastAPI가 폼 데이터와 multipart 요청을 파싱할 때 필요
- `Form()` 또는 `File()`을 사용하는 엔드포인트 등록에 필요
- 단순 HTML 템플릿 렌더링 자체에는 필요하지 않음

**문제 해결**

`python-multipart`가 설치되지 않은 환경에서 `Form()`이나 `File()`을 사용하는 라우트를 등록하면 애플리케이션 시작 단계에서 오류가 발생할 수 있다.

따라서 다른 라우트까지 실행되지 않는 경우에도 해당 패키지와 import 구문을 확인해야 한다.

### E. multipart/form-data — 여러 데이터를 한 요청에 전송

파일을 포함하는 HTML Form은 다음과 같이 작성한다.

```html
<form method="post" action="/file" enctype="multipart/form-data">
  <input type="text" name="title" />
  <input type="file" name="file" />
  <button type="submit">업로드</button>
</form>
```

**multipart의 의미**

하나의 HTTP 요청 본문을 여러 파트로 나누고, 각 파트에 이름과 메타데이터를 부여해 전송하는 형식이다.

일반적인 텍스트 폼의 기본 인코딩은 `application/x-www-form-urlencoded`이고, 파일을 함께 보내는 경우 `multipart/form-data`를 사용한다.

**오늘 개발자 도구에서 확인한 Payload**

```text
Content-Disposition: form-data; name="title"

1111111

Content-Disposition: form-data;
name="file";
filename="스크린샷 2026-09-18 오전 8.23.50.png"

Content-Type: image/png
```

**확인한 요소**

1. `title`: 일반 텍스트 필드
2. `file`: 파일 필드
3. `filename`: 브라우저가 전달한 원본 파일명
4. `Content-Type: image/png`: 해당 파일 파트의 미디어 타입
5. `boundary`: 요청 본문에서 각 파트를 구분하는 문자열

**주의**

`filename`과 `Content-Type`은 클라이언트가 제공하는 정보이므로 신뢰할 수 있는 검증값은 아니다.

서버에서 파일을 저장할 때는 크기, 허용 형식, 저장 경로 등을 별도로 검증해야 한다.

또한 Payload 화면은 파일 전송 요청의 구성을 보여줄 뿐, 파일이 서버에 저장되었음을 증명하지는 않는다.

## 3. STUDY & EXERCISE — 4장 1강: APIRouter와 Middleware

### A. APIRouter — 도메인별 라우터 분리

하나의 `main.py`에 모든 엔드포인트를 작성하지 않고, 도메인별로 파일을 분리한다.

**튜터 GitHub 구조**

```text
chapter04-1/
└── src/
    ├── main.py
    ├── board/
    │   └── presentation/
    │       └── router.py
    └── order/
        └── presentation/
            └── router.py
```

**주문 라우터**

```python
router = APIRouter(
    prefix="/v1/order",
    tags=["주문", "태그1"],
    dependencies=[Depends(verify_secret_token)]
)
```

**게시판 라우터**

```python
router = APIRouter(
    prefix="/v1/board",
    tags=["게시판", "태그1"]
)
```

**메인 애플리케이션**

```python
app.include_router(order_router)
app.include_router(board_router)
```

**설정 항목**

- `prefix`: API 공통 경로
- `tags`: Swagger UI 문서의 그룹 이름
- `dependencies`: 라우터에 공통 적용할 의존성
- `include_router()`: 메인 애플리케이션에 라우터 등록

### B. Depends — 공통 검증 및 의존성 주입

**튜터 코드 — 주문 라우터**

```python
def verify_secret_token(
    x_token: str | None = Header(None)
):
    if x_token != "secret":
        raise HTTPException(
            status_code=403,
            detail="토큰이 잘못되었습니다."
        )
```

```python
router = APIRouter(
    prefix="/v1/order",
    tags=["주문", "태그1"],
    dependencies=[Depends(verify_secret_token)]
)
```

**실행 흐름**

```text
HTTP 요청
    ↓
주문 라우터 접근
    ↓
Depends(verify_secret_token)
    ↓
X-Token 헤더 확인
    ├── 불일치 → 403 응답
    └── 일치 → 엔드포인트 실행
```

**새롭게 이해한 점**

`Depends()`는 공통 로직을 필요한 곳에서 재사용하도록 하는 FastAPI의 의존성 주입(Dependency Injection) 기능이다.

인증뿐 아니라 DB 연결, 공통 검증 등에도 사용할 수 있다.

**주의**

튜터 코드의 `"secret"`은 의존성 동작을 설명하기 위한 실습값이다. 실제 서비스에서는 비밀값을 코드에 직접 고정하는 방식으로 인증을 구현하지 않는다.

### C. Middleware — 요청과 응답의 공통 처리

Middleware는 HTTP 요청이 라우터에 도달하기 전과, 응답이 클라이언트로 전달되기 전에 공통 처리를 수행한다.

**튜터 코드 — `chapter04-1/src/main.py`**

```python
@app.middleware("http")
async def middleware1(request: Request, call_next):
    logger.info("middleware1()의 요청 처리전")

    response = await call_next(request)

    logger.info("middleware1()의 응답 처리 전")

    return response
```

**실행 흐름**

```text
Client Request
    ↓
Middleware 전처리
    ↓
call_next(request)
    ↓
APIRouter / Endpoint
    ↓
Middleware 후처리
    ↓
Client Response
```

**`call_next(request)`의 역할**

다음 요청 처리 단계로 제어를 전달하고, 반환된 응답을 받는다.

**Middleware와 Depends의 차이**

| 구분      | Middleware                  | Depends                    |
| --------- | --------------------------- | -------------------------- |
| 적용 범위 | 애플리케이션 요청 처리 계층 | 지정한 라우트·라우터       |
| 주요 목적 | 공통 로깅, 요청·응답 처리   | 인증, 검증, 공통 자원 제공 |
| 실행 시점 | 요청 전후                   | 엔드포인트 실행 과정       |
| 대표 문법 | `@app.middleware("http")`   | `Depends()`                |

### D. CORS — 브라우저 간 출처 제어

CORS(Cross-Origin Resource Sharing)는 브라우저가 서로 다른 출처의 서버 자원에 접근할 때 적용되는 정책과 관련된다.

출처(Origin)는 일반적으로 다음 세 요소의 조합으로 구분한다.

- 프로토콜
- 호스트
- 포트

**[교안 개념 보충 예제]**

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],
    allow_credentials=True,
    allow_methods=["GET", "POST"],
    allow_headers=["*"]
)
```

**학습 포인트**

프론트엔드와 백엔드가 다른 포트에서 실행되면 출처가 달라질 수 있다.

예를 들어 Next.js와 FastAPI를 별도 개발 서버로 실행할 때 CORS 설정이 필요할 수 있다.

**주의**

CORS는 브라우저의 교차 출처 접근을 제어하는 메커니즘이지, API의 인증·인가를 대신하는 보안 기능은 아니다.

### E. TrustedHostMiddleware

요청의 `Host` 헤더가 허용된 호스트 이름과 일치하는지 검사한다.

**[교안 개념 보충 예제]**

```python
from fastapi.middleware.trustedhost import TrustedHostMiddleware

app.add_middleware(
    TrustedHostMiddleware,
    allowed_hosts=["localhost", "127.0.0.1"]
)
```

CORS와 TrustedHostMiddleware는 목적이 다르다.

- CORS: 브라우저의 교차 출처 요청 허용 정책
- TrustedHostMiddleware: 요청의 호스트 헤더 검증

두 기능 모두 실제 사용자 인증을 대체하지는 않는다.

## 4. TROUBLESHOOTING — 오늘 발생한 문제와 해결

### A. 새 라우트가 404로 표시됨

**현상**

새로 작성한 `/practice3` 경로에 접속했지만 `404 Not Found`가 발생했다.

**확인 및 해결**

- 기존 서버가 8000번 포트를 사용 중인지 확인
- 이전 서버가 `--reload` 없이 실행된 상태인지 확인
- 기존 서버 종료 후 새 서버 실행
- 전체 URL로 재접속

```bash
uv run uvicorn main:app --app-dir src --reload
```

```text
http://127.0.0.1:8000/practice3
```

**배운 점**

코드를 수정했다고 해서 현재 실행 중인 서버에 반드시 변경 내용이 반영되는 것은 아니다.

404가 발생하면 코드의 경로뿐 아니라 **실행 중인 서버가 어떤 코드 버전을 사용하고 있는지**도 확인해야 한다.

### B. WinError 10013

**현상**

Windows에서 서버가 소켓 주소에 바인딩하지 못하는 오류 발생.

**확인할 항목**

1. 동일 포트의 기존 서버 실행 여부
2. 포트 사용 권한 및 보안 정책
3. 방화벽 또는 보안 소프트웨어 제한
4. 다른 포트에서 실행 가능한지 여부

**주의**

`WinError 10013`만으로 포트 중복이 원인이라고 단정할 수는 없다.

### C. Form·File 관련 실행 오류

**원인 후보**

- `Form`, `File`, `UploadFile` import 누락
- `python-multipart` 미설치
- 다른 uv 프로젝트 환경에 패키지 설치

**해결 방법**

```bash
uv add python-multipart
```

현재 프로젝트의 `pyproject.toml`과 실행 환경을 확인한다.

### D. 서버 로그와 브라우저 응답 혼동

**문제**

폼 데이터를 전송했는데 브라우저에 결과가 표시되지 않는 상황.

**정리**

- `Form()`: 요청 데이터 수신
- `logger.info()`: 서버 로그 기록
- `return`: 클라이언트에 응답 반환

데이터를 수신하고 로그에 출력하는 것만으로는 결과 페이지가 생성되지 않는다.

## 5. REVIEW — 새롭게 이해한 점

### A. 핵심 학습 내용

1. Jinja2의 `extends`, `block`, `include`, `macro`로 HTML을 재사용할 수 있다.
2. `StaticFiles`와 `app.mount()`를 이용해 CSS·이미지 경로를 제공할 수 있다.
3. HTML의 `name` 속성과 FastAPI의 `Form()` 매개변수가 연결된다.
4. `multipart/form-data`는 텍스트와 파일을 구분된 파트로 함께 전송한다.
5. `python-multipart`는 폼 데이터 파싱을 위해 필요한 의존성이다.
6. `UploadFile`은 업로드된 파일을 처리하는 객체다.
7. `APIRouter`로 기능별 API 경로를 분리할 수 있다.
8. `Depends()`로 공통 검증 로직을 재사용할 수 있다.
9. Middleware는 요청 전후의 공통 처리 계층이다.
10. CORS와 호스트 검증은 서로 다른 문제를 다룬다.

### B. 헷갈렸던 개념

| 개념                     | 구분해서 기억할 점                               |
| ------------------------ | ------------------------------------------------ |
| `File` / `UploadFile`    | 파일 매개변수 선언 / 업로드 파일 객체            |
| `Form` / `Body`          | 폼 인코딩 데이터 / 일반적인 요청 본문 선언       |
| `app.mount` / `@app.get` | 애플리케이션 마운트 / 경로 데코레이터            |
| `include` / `extends`    | 템플릿 삽입 / 부모 템플릿 상속                   |
| `Depends` / Middleware   | 선택한 엔드포인트의 공통 의존성 / 요청 처리 계층 |
| CORS / Host 검증         | 출처 접근 정책 / Host 헤더 검증                  |
| 로그 / 응답              | 서버 내부 기록 / 클라이언트에 반환할 결과        |
| 404 / 포트 오류          | 경로 불일치 / 서버 바인딩 문제                   |
