## 2. STUDY & EXERCISE

### A. Connection Pool — 데이터베이스 연결 재사용

**1. 커넥션 풀이 필요한 이유**

웹 서버가 데이터베이스에 접근할 때마다 새로운 연결을 생성하면 연결 설정에 시간과 자원이 소모된다.

커넥션 풀(Connection Pool)은 DB 연결을 재사용할 수 있도록 관리하는 구조다.

**동작 흐름**

```text
FastAPI 요청
    ↓
Connection Pool
    ↓
사용 가능한 DB 연결 확보
    ↓
SQL 실행
    ↓
작업 완료
    ↓
DB 연결을 풀에 반납
    ↓
다음 요청에서 재사용
```

**핵심 개념**

- DB 연결을 재사용해 연결 생성 비용 감소
- 여러 요청이 연결을 효율적으로 공유
- 연결 수를 관리해 서버 자원 사용 조절

### B. Connection Validation — 연결 유효성 검사

**1. 문제가 발생하는 상황**

커넥션 풀에 보관된 연결이 항상 정상 상태인 것은 아니다.

오랫동안 사용하지 않은 연결은 DB 서버의 타임아웃이나 네트워크 문제 등으로 끊어질 수 있다.

이때 유효하지 않은 연결을 그대로 사용하면 데이터베이스 작업 중 오류가 발생할 수 있다.

**2. 연결 유효성 검사 흐름**

```text
커넥션 풀에서 연결 요청
    ↓
연결 유효성 확인
    ↓
연결 상태 판단
    ├── 정상 → 연결 사용
    └── 비정상 → 연결 무효화 및 재연결
    ↓
SQL 실행
```

**3. `pool_pre_ping`**

SQLAlchemy에서는 `pool_pre_ping` 옵션으로 풀에서 연결을 가져올 때 연결 상태를 확인할 수 있다.

```python
pool_pre_ping=True
```

**주의할 점**

강의 전사에는 연결을 주기적으로 확인한다는 설명이 있지만, SQLAlchemy의 `pool_pre_ping`은 일반적으로 **연결을 풀에서 가져오는 시점**에 유효성을 검사한다.

백그라운드에서 일정 시간마다 모든 연결을 검사하는 기능과는 구분해야 한다.

### C. `pool_recycle` — 오래된 연결 관리

이전 강의에서 학습한 `pool_recycle`도 함께 복습할 필요가 있다.

| 설정 | 역할 |
|---|---|
| `pool_pre_ping` | 연결 사용 전 유효성 확인 |
| `pool_recycle` | 지정한 시간이 지난 연결을 다음 체크아웃 시 재생성하도록 관리 |
| `pool_size` | 기본 연결 풀 크기 관리 |

**핵심 차이**

`pool_pre_ping`은 연결이 살아 있는지 확인하고, `pool_recycle`은 연결의 사용 기간을 기준으로 재생성을 관리한다.

*이 설정들의 구체적인 실습값은 녹음에서 확인되지 않아 기록하지 않았다.*

**교안 학습 시 확인할 주요 개념**

| 개념 | 역할 |
|---|---|
| ORM | Python 객체와 관계형 DB 데이터 매핑 |
| Engine | 데이터베이스 연결 및 실행 기반 관리 |
| Connection Pool | DB 연결 재사용 |
| Model | 테이블과 연결되는 Python 클래스 |
| Session | ORM 객체 조회·변경 등 DB 작업 관리 |
| Transaction | DB 작업을 하나의 논리적 단위로 처리 |

**이전 수업과의 연결**

```text
FastAPI
    ↓
SQLAlchemy ORM
    ↓
Engine / Connection Pool
    ↓
PostgreSQL
```

## 3. 문제 해결 및 새롭게 이해한 점

### A. 연결을 재사용하더라도 오류가 발생할 수 있음

**문제 상황**

커넥션 풀에 연결이 남아 있어도 해당 연결이 실제 DB 서버와 끊어졌을 수 있다.

**해결 방향**

연결을 사용하기 전에 유효성을 확인하고, 끊어진 연결은 무효화한 뒤 다시 연결하도록 설정한다.

**배운 점**

커넥션 풀은 단순히 연결을 저장하는 기능이 아니라, 연결의 재사용과 상태 관리를 함께 고려해야 하는 구조다.

### B. Connection Pool과 ORM의 역할 구분

| 구분 | 역할 |
|---|---|
| ORM | 객체와 DB 데이터의 매핑 |
| Connection Pool | DB 연결의 생성·재사용·관리 |
| Session | ORM을 통한 DB 작업 및 트랜잭션 관리 |

ORM을 사용한다는 것과 커넥션 풀을 사용한다는 것은 서로 다른 개념이다.

SQLAlchemy에서는 이 기능들을 함께 구성할 수 있다.
