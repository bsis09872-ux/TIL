## 2. REVIEW — 이전 강의 복습

### A. FE와 BE의 역할

| 구분          | 역할                                                |
| ------------- | --------------------------------------------------- |
| FE (Frontend) | 사용자에게 보이는 화면 및 사용자 상호작용           |
| BE (Backend)  | 요청 처리, 비즈니스 로직, 데이터 접근, 인증·인가 등 |

**[보충 설명]**

FE와 BE는 HTTP 요청과 응답을 통해 연결된다.

```text
사용자
  ↓
Frontend
  ↓ HTTP Request
Backend API
  ↓
비즈니스 로직 / 데이터베이스
  ↓
Backend API
  ↓ HTTP Response
Frontend
  ↓
사용자 화면
```

### B. Pydantic 검증과 부분 수정

- `BaseModel`: 요청·응답 데이터 구조 정의
- `Field`: 필수값, 길이, 범위 등 제약 설정
- `field_validator`: 개별 필드 검증
- `model_validator`: 모델 전체 검증
- `model_dump(exclude_unset=True)`: 명시적으로 전달된 값만 추출

**부분 수정(PATCH)의 핵심**

요청에 없는 필드를 기본값으로 덮어쓰지 않도록 주의한다.

```python
updates = payload.model_dump(exclude_unset=True)
```

단, 명시적으로 `null`을 보낸 필드는 `exclude_unset=True`만으로 제거되지 않는다.

### C. 요청 모델과 응답 모델

- Request Schema: 클라이언트가 보내는 데이터
- Response Schema: 클라이언트에게 반환하는 데이터
- `response_model`: 반환 데이터의 형식 검증·필터링

## 3. LECTURE NOTE — 3장 1강: 경로·쿼리 매개변수와 예외 처리

### A. Path와 Query Parameter

| 구분    | Path Parameter  | Query Parameter             |
| ------- | --------------- | --------------------------- |
| 목적    | 특정 자원 식별  | 검색·필터·정렬·페이지네이션 |
| 위치    | URL 경로        | `?` 뒤의 쿼리 문자열        |
| 예시    | `/groceries/10` | `/groceries?keyword=apple`  |
| FastAPI | `Path()`        | `Query()`                   |

**학습 포인트**

- 특정 상품의 ID → 일반적으로 Path
- 상품 목록의 검색어 → 일반적으로 Query
- URL 전체를 URI(Uniform Resource Identifier)의 한 형태로 볼 수 있지만, 식별자가 무조건 URI에만 들어가야 한다는 뜻은 아니다.

### B. Annotated — 타입과 검증 규칙 분리

```python
from typing import Annotated, Optional
from fastapi import Path, Query

@app.get("/groceries/{item_id}")
async def get_grocery(
    item_id: Annotated[int, Path(gt=0)],
    keyword: Annotated[
        Optional[str],
        Query(description="키워드")
    ] = None
):
    return {
        "item_id": item_id,
        "keyword": keyword
    }
```

**구조**

```python
Annotated[자료형, 검증 및 메타데이터]
```

- `int`: Python 자료형
- `Path(gt=0)`: 경로 매개변수의 검증 규칙
- `Optional[str]`: 문자열 또는 `None` 허용
- `Query()`: 쿼리 매개변수 선언

**주의**

`Annotated`는 타입과 검증 메타데이터를 분리하지만, Python 함수 매개변수의 기본값 순서 규칙 자체를 없애지는 않는다.

### C. 튜터 GitHub — 단건 조회 API

**파일:** `chapter03-1/src/main.py`

```python
@app.get("/groceries/{item_id}")
async def get_grocery(
    item_id: Annotated[int, Path(..., description="상품")],
    keyword: Annotated[
        Optional[str],
        Query(description="키워드")
    ] = None
):
    if item_id not in grocery_database:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="식료품을 찾을 수 없습니다."
        )

    logger.info(f"keyword={keyword}")

    item = grocery_database[item_id]

    if item["expiration_date"] < date.today():
        raise GroceryExpiredException(
            item["name"],
            item["expiration_date"]
        )

    return item
```

**처리 흐름**

1. 경로에서 `item_id` 수신
2. 필요하면 쿼리에서 `keyword` 수신
3. 상품 존재 여부 확인
4. 상품이 없으면 `404` 반환
5. 상품의 유통기한 확인
6. 유통기한이 지났으면 사용자 정의 예외 발생
7. 문제가 없으면 상품 정보 반환

### D. HTTP 상태 코드

| 코드  | 의미                  | 먼저 확인할 내용          | 일반적인 대응                 |
| ----- | --------------------- | ------------------------- | ----------------------------- |
| `200` | OK                    | 정상 조회 여부            | 응답 데이터 확인              |
| `201` | Created               | 생성 결과                 | 생성된 자원 확인              |
| `204` | No Content            | 응답 본문 없음            | 성공 여부 확인                |
| `400` | Bad Request           | 요청 형식·비즈니스 규칙   | 요청값과 서버 메시지 확인     |
| `401` | Unauthorized          | 인증 필요 또는 실패       | 로그인·토큰 유효성 확인       |
| `403` | Forbidden             | 접근 권한 거부            | 계정 권한·인가 정책 확인      |
| `404` | Not Found             | 경로 또는 자원 없음       | URL·ID·라우팅 확인            |
| `405` | Method Not Allowed    | 지원하지 않는 HTTP 메서드 | GET/POST 등 메서드 확인       |
| `409` | Conflict              | 데이터 상태 충돌          | 중복·동시 수정·현재 상태 확인 |
| `422` | Unprocessable Content | 요청 데이터 검증 실패     | 필드 누락·타입·제약 확인      |
| `429` | Too Many Requests     | 요청 횟수 제한            | 재시도 정책·제한 확인         |
| `500` | Internal Server Error | 서버 내부 오류            | 서버 로그·예외 추적           |
| `502` | Bad Gateway           | 상위 서버 응답 문제       | 프록시·업스트림 서버 확인     |
| `503` | Service Unavailable   | 서비스 일시 불가          | 서버 상태·배포·점검 확인      |
| `504` | Gateway Timeout       | 상위 서버 응답 시간 초과  | 네트워크·처리 지연 확인       |

**중요**

- `401`: 인증(Authentication) 문제
- `403`: 인가(Authorization) 문제
- `422`: FastAPI 요청 검증에서 자주 발생
- `500`: 서버 내부에서 발생한 오류

상태 코드만으로 원인을 확정하지 말고 응답 본문과 로그를 함께 확인한다.

### E. HTTPException

```python
raise HTTPException(
    status_code=status.HTTP_404_NOT_FOUND,
    detail="식료품을 찾을 수 없습니다."
)
```

- `status_code`: HTTP 상태 코드
- `detail`: 오류 설명

**HTTPException은 예외를 발생시키고 해당 요청의 정상 처리 흐름을 중단한다.**

### F. 사용자 정의 예외(Custom Exception)

**파일:** `chapter03-1/src/main.py`

튜터 코드:

```python
class GroceryExpiredException(Exception):
    def __init__(self, name: str, expiration_date: date):
        self.name = name
        self.expiration_date = date
```

**[코드 검토 — 수정 필요]**

마지막 줄의 `date`는 전달받은 `expiration_date`가 아니라 `datetime.date` 클래스다.

올바른 저장 방식:

```python
class GroceryExpiredException(Exception):
    def __init__(self, name: str, expiration_date: date):
        self.name = name
        self.expiration_date = expiration_date
```

**구성**

- `Exception`: Python 기본 예외 클래스
- `__init__`: 예외 객체 생성 시 초기화 메서드
- `name`: 식료품 이름
- `expiration_date`: 유통기한

### G. 전역 예외 처리기 — exception_handler

튜터 코드:

```python
@app.exception_handler(GroceryExpiredException)
async def handle_exception(
    request: Request,
    exc: GroceryExpiredException
):
    logger.error(f"에러발생: {str(exc)}")

    return JSONResponse(
        status_code=status.HTTP_400_BAD_REQUEST,
        content={
            "success": False,
            "message": (
                f"식료품 {exc.name}은 "
                f"유통기한({exc.expiration_date})이 지났습니다."
            )
        }
    )
```

**구조**

```python
@app.exception_handler(예외클래스)
```

1. 특정 예외 발생
2. 등록된 핸들러 실행
3. 예외 정보 확인
4. 로그 기록
5. `JSONResponse` 반환

**[보충 설명]**

튜터 코드에서 `GroceryExpiredException`은 `Exception`을 상속한다. 전역 예외 처리기는 해당 예외를 감지해 HTTP 응답으로 변환한다.

`JSONResponse`는 JSON 응답을 생성하는 클래스이며, `APIResponse`처럼 직접 정의한 Pydantic 모델과는 역할이 다르다.

## 4. LECTURE NOTE — 3장 2강: Jinja2 템플릿과 HTML 응답

### A. HTMLResponse와 JSONResponse

| 구분           | 역할             | Content-Type       |
| -------------- | ---------------- | ------------------ |
| `JSONResponse` | JSON 데이터 응답 | `application/json` |
| `HTMLResponse` | HTML 문서 응답   | `text/html`        |

- JSON API: FE가 데이터를 받아 화면을 구성
- HTML 템플릿: 서버가 데이터를 HTML에 삽입해 페이지 생성

### B. Jinja2Templates

**파일:** `chapter03-2/src/main.py`

튜터 코드:

```python
import os
import logging

from fastapi.responses import HTMLResponse
from fastapi import FastAPI, Request
from fastapi.templating import Jinja2Templates

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("app")

app = FastAPI()

CURRENT_DIR = os.path.dirname(__file__)

templates = Jinja2Templates(
    directory=os.path.join(CURRENT_DIR, "templates")
)

templates.env.add_extension("jinja2.ext.do")
```

**주요 개념**

- `__file__`: 현재 Python 파일의 경로
- `os.path.dirname()`: 경로에서 상위 디렉터리 부분 추출
- `os.path.join()`: 경로 요소 결합
- `Jinja2Templates`: Jinja2 템플릿 엔진 설정
- `jinja2.ext.do`: Jinja2의 `do` 확장 기능 활성화

**주의**

`os.path.dirname(__file__)`는 현재 파일 경로에서 디렉터리 부분을 추출한다. `__file__`이 항상 절대경로라는 보장은 없으므로 절대경로가 필요하다면 `os.path.abspath()` 등을 사용할 수 있다.

### C. TemplateResponse — 컨텍스트 전달

튜터 코드:

```python
@app.get("/practice1", response_class=HTMLResponse)
async def jinja_practice1(request: Request):
    student_context = {
        "name": "Sparta",

        "hobbies": ["독서", "영화"],
```

**처리 흐름**

2. Python 딕셔너리로 컨텍스트 데이터 준비
3. `practice1.html` 템플릿 선택
4. 컨텍스트를 템플릿에 전달
5. 렌더링된 HTML 반환

### D. Jinja2 기본 문법

**파일:** `chapter03-2/src/templates/practice1.html`

| 문법                   | 역할                           |
| ---------------------- | ------------------------------ |
| `{{ name }}`           | 변수 출력                      |
| `{{ name \| filter }}` | 필터 적용                      |
| `{% if %}`             | 조건문                         |
| `{% elif %}`           | 추가 조건                      |
| `{% else %}`           | 그 외 조건                     |
| `{% endif %}`          | 조건문 종료                    |
| `{% for %}`            | 반복문                         |
| `{% endfor %}`         | 반복문 종료                    |
| `{% set %}`            | 변수 선언                      |
| `{% with %}`           | 지역 스코프 생성               |
| `{% do %}`             | 값을 출력하지 않고 표현식 실행 |

### E. 변수 출력과 조건문

튜터 코드:

```html
<p>이름: {{ name }}</p>
<p>나이: {{ age }}</p>

{% if age >= 20 %}
<p>성인: 모든 기능 사용 가능</p>
{% elif age >= 14 %}
<p>청소년: 일부 기능 제한</p>
{% else %}
<p>어린이: 이용 불가</p>
{% endif %}
```

### F. 반복문과 do 확장

튜터 코드:

```html
{% do hobbies.append("운동") %}

<p>취미({{ hobbies | length }})</p>

<ul>
  {% for hobby in hobbies %}
  <li>{{ hobby }}</li>
  {% endfor %}
</ul>
```

**설명**

- `do`: 출력 없이 리스트 변경 등 표현식 실행
- `length`: 리스트 길이 반환
- `for`: 리스트 순회

### G. 필터(Filter)

튜터 코드에서 사용한 필터:

```html
<p>닉네임: {{ nickname2 | default('익명') }}</p>
<p>취미: {{ hobbies | join(',') }}</p>
```

- `default`: 값이 정의되지 않았을 때 기본값 사용
- `join`: 리스트 요소를 구분자로 연결
- `length`: 길이 반환
- `safe`: HTML 이스케이프 우회

**[보충 설명]**

`default('익명')`은 기본적으로 정의되지 않은 변수에 적용된다. `None`이나 빈 문자열까지 기본값으로 대체하려면 상황에 따라 `default('익명', true)` 등을 사용한다.

### H. HTML 출력 보안

튜터 템플릿에는 다음 코드가 있다.

```html
<p>{{ html_code | safe }}</p>
```

`safe`는 문자열을 HTML로 해석하도록 허용한다.

**주의**

신뢰할 수 없는 사용자 입력에 `safe`를 적용하면 XSS(Cross-Site Scripting, 교차 사이트 스크립팅) 위험이 생길 수 있다.

기본 HTML 이스케이프를 유지하고, 신뢰할 수 있는 HTML에만 제한적으로 사용한다.

## 5. LECTURE NOTE — APIRouter와 API 버전 관리

### A. APIRouter

튜터 GitHub에는 다음 구조가 있다.

```text
chapter03-1/
└── src/
    ├── main.py
    └── order/
        └── presentation/
            └── routers/
                └── v1/
                    └── router.py
```

**파일:** `order/presentation/routers/v1/router.py`

```python
from fastapi import APIRouter

router = APIRouter(
    prefix="/v1/order",
    tags=["Orders"]
)

@router.get("")
async def test1():
    return {"message": "테스트1"}

@router.get("/test")
async def test2():
    return {"message": "테스트2"}
```

**생성되는 경로**

- `GET /v1/order`
- `GET /v1/order/test`

### B. 메인 애플리케이션에서 라우터 등록

튜터 코드:

```python
from order.presentation.routers.v1.router import router as order_router

app = FastAPI()

app.include_router(order_router)
```

**역할 구분**

- `APIRouter`: 기능별 API 경로 정의
- `prefix`: 공통 URL 경로
- `tags`: Swagger UI에서 엔드포인트 그룹화
- `include_router`: 메인 FastAPI 애플리케이션에 라우터 등록

### C. API 버전 관리

```text
/v1/order
/v2/order
```

버전별로 API 인터페이스를 분리하면 기존 클라이언트와의 호환성을 유지하면서 새 버전을 제공하기 쉽다.

**[보충 설명]**

버전 경로를 만든다고 기존 버전이 자동으로 유지되는 것은 아니다. 실제로 각 버전의 라우터와 데이터 계약을 관리해야 한다.

### D. 프로젝트 구조와 관심사 분리

```text
src/
├── main.py

    ├── presentation/

    │       └── v1/

    ├── application/
    ├── domain/
    └── infrastructure/
```

**[보충 예시 — 팀 프로젝트 설계안]**

- `presentation`: HTTP 요청·응답, Pydantic 스키마

## 6. ADDITIONAL LEARNING — 기타 학습 내용

### A. MRO — Method Resolution Order

**올바른 표기:** `__mro__`

MRO는 Python에서 다중 상속 시 어떤 클래스의 메서드를 먼저 탐색할지 결정하는 순서다.

```python
class A:
    pass

class B(A):
    pass

print(B.__mro__)
```

- `__mro__`: 클래스의 메서드 탐색 순서
- `ClassName.mro()`: 탐색 순서를 리스트로 확인

### B. uv 프로젝트와 패키지 관리

```bash
uv init grocery-validator --python 3.13
cd grocery-validator
uv add fastapi uvicorn pydantic
```

**학습 포인트**

- `uv init`: 프로젝트 초기화
- `uv add`: 현재 프로젝트의 의존성 추가
- `pyproject.toml`: 프로젝트 설정·의존성 정보
- `uv.lock`: 의존성 버전 잠금 정보

**주의**

상위 폴더와 하위 폴더에 각각 `pyproject.toml`이 있다면 독립 프로젝트인지, uv 워크스페이스인지 먼저 확인해야 한다.

무조건 모든 하위 폴더에서 `uv add`를 실행하는 것이 정답은 아니다.

## 8. TROUBLESHOOTING & LEARNING

### A. 헷갈렸던 개념

| 개념                            | 헷갈린 부분           | 정리                            |
| ------------------------------- | --------------------- | ------------------------------- |
| `401` / `403`                   | 인증과 권한의 차이    | 인증 실패 vs 접근 거부          |
| `422`                           | 검증 오류 코드        | FastAPI 요청 데이터 검증 실패   |
| `Path` / `Query`                | 식별자와 검색 조건    | 단건 식별 vs 목록 조건          |
| `HTTPException`                 | 오류 발생 방식        | 요청 처리 중 예외 발생          |
| `exception_handler`             | 예외 처리 방식        | 특정 예외를 공통 응답으로 변환  |
| `JSONResponse` / `HTMLResponse` | 반환 데이터           | JSON vs HTML                    |
| `Field` / Validator             | 기본 제약과 추가 검증 | 선언적 검증 vs 사용자 정의 검증 |
| `APIRouter`                     | 라우터 분리           | 기능별 경로 모듈화              |
| `__mro__`                       | 다중 상속             | 메서드 탐색 순서                |

### B. 튜터 코드 검토에서 발견한 점

1. `GroceryExpiredException`의 `self.expiration_date = date`는 수정 필요.
2. Jinja2의 `safe`는 HTML 이스케이프를 우회하므로 주의 필요.
3. `APIRouter`는 기능별 경로 분리를 담당하며, 메인 앱에서 등록해야 한다.
4. `Annotated`는 타입과 검증 규칙을 함께 표현할 수 있다.

## 9. REVIEW

### A. 오늘 새롭게 이해한 점

1. Path와 Query는 전달하는 데이터의 목적에 따라 구분한다.
2. `Annotated`를 사용하면 타입과 검증 조건을 명확하게 표현할 수 있다.
3. HTTP 상태 코드는 문제를 분류하는 첫 번째 단서다.
4. 사용자 정의 예외와 전역 예외 처리기를 조합하면 공통 오류 응답을 만들 수 있다.
5. 로그에는 오류 메시지뿐 아니라 발생 위치와 요청 맥락도 중요하다.
6. Jinja2는 Python 데이터를 HTML에 전달해 서버에서 화면을 생성한다.
7. `APIRouter`는 기능별 API를 분리하고 버전별로 관리하는 데 활용할 수 있다.
8. 팀 프로젝트에서는 로직·데이터 구조·API 명세의 순서로 합의해야 한다.
