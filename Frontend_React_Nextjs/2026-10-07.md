## 오늘의 학습 목표

React와 Next.js의 역할과 렌더링 방식의 차이를 이해하고 개발 환경을 구축했다. 페이지와 공통 레이아웃을 만들고 컴포넌트 분리와 props 전달을 실습했다.

## 1. React와 Next.js

### A. React — UI 라이브러리

React는 컴포넌트를 조합하여 **UI(User Interface, 사용자 인터페이스)**를 만드는 JavaScript 라이브러리다.

일반적인 클라이언트 렌더링 앱에서는 다음과 같은 루트 요소에 JavaScript로 화면을 구성한다.

```html
<div id="root"></div>
```

**CSR(Client-Side Rendering, 클라이언트 측 렌더링)**은 브라우저에서 JavaScript를 실행하여 화면을 만드는 방식이다.

- 초기 JavaScript를 내려받고 실행하는 시간이 필요하다.
- 필요한 코드가 로딩된 이후에는 전체 문서를 다시 받지 않고 화면을 전환할 수 있다.
- 초기 **HTML(HyperText Markup Language)**에 콘텐츠가 적으면 검색 엔진의 수집과 색인에 불리할 수 있다.

CSR이 자동으로 오프라인 사용을 지원하는 것은 아니다. 필요한 코드와 데이터가 준비되어 있어야 하며 서버 요청에는 인터넷 연결이 필요할 수 있다.

**SEO(Search Engine Optimization, 검색 엔진 최적화)** 문제도 검색이 불가능하다는 뜻은 아니다. 콘텐츠 수집에 JavaScript 실행이 필요하므로 검색 엔진에 따라 처리가 지연되거나 제한될 수 있다는 의미다.

React 자체는 CSR뿐 아니라 서버 렌더링에도 사용할 수 있다.

### B. Next.js — React 기반 프레임워크

Next.js는 React에 라우팅, 서버 렌더링, 빌드, 서버 실행 등의 기능을 제공한다.

**SSR(Server-Side Rendering, 서버 측 렌더링)**은 요청에 응답하여 서버에서 HTML을 생성하는 방식이다. 콘텐츠가 포함된 HTML을 브라우저에 먼저 전달할 수 있다.

**사전 렌더링(pre-rendering)**은 브라우저에서 화면을 구성하기 전에 HTML을 생성하는 넓은 개념이다. **SSG(Static Site Generation, 정적 사이트 생성)**와 SSR을 구분한다.

| 방식 | HTML 생성 시점   |
| ---- | ---------------- |
| SSR  | 요청에 응답할 때 |
| SSG  | 빌드할 때        |

**Hydration**은 서버에서 만든 HTML에 React의 클라이언트 로직을 연결하여 상호작용이 가능하게 만드는 과정이다. App Router에서는 클라이언트 컴포넌트에 hydration이 적용되며 서버 컴포넌트 자체가 모두 hydration되는 것은 아니다.

## 2. 트랜스파일과 번들링

**JSX(JavaScript XML)**는 JavaScript 안에서 HTML과 비슷한 마크업을 작성하는 확장 문법이다. TypeScript에서 JSX를 사용하는 파일은 `.tsx` 확장자를 사용한다. TSX는 이 파일 형식을 가리키며 별도의 공식 풀네임을 붙이지 않는다.

| 개념       | 역할                                             |
| ---------- | ------------------------------------------------ |
| 트랜스파일 | JSX·TypeScript 등을 JavaScript로 변환            |
| 번들링     | 여러 모듈과 의존성을 실행에 필요한 묶음으로 구성 |
| 빌드       | 변환·번들링·최적화 등을 거쳐 배포용 결과물 생성  |

Babel은 대표적인 코드 변환 도구이고 webpack은 대표적인 번들러다. 모든 React 프로젝트가 반드시 두 도구를 사용하는 것은 아니다.

Next.js는 성능을 높이기 위해 Rust 기반 도구를 활용한다.

- **SWC(Speedy Web Compiler, 스피디 웹 컴파일러):** 코드 변환과 압축 등에 사용하는 도구
- **Turbopack:** JavaScript·TypeScript를 처리하는 번들러

Next.js 전체가 Rust로 작성된 것은 아니다. Next.js는 빌드 성능뿐 아니라 라우팅과 렌더링 등 앱 개발 전반의 기능을 제공한다.

## 3. 개발 환경 구축

### A. 프로젝트 생성과 실행

Node.js와 **npm(자바스크립트 패키지 관리 도구)**이 설치되어 있는지 확인한다. npm에는 공식적으로 고정된 풀네임이 없으므로 이름 그대로 사용한다.

```bash
node -v
npm -v
```

작업 폴더에서 프로젝트를 생성한다.

```bash
npx create-next-app@latest chapter02
cd chapter02
npm run dev
```

`npx`는 패키지의 실행 도구를 실행하는 명령이고 `@latest`는 실행 시점의 최신 버전을 선택한다. 수업 로그에서는 생성 도구 버전이 16.4.0이었다.

권장 설정으로 TypeScript, ESLint, **Tailwind CSS(Cascading Style Sheets)**, App Router 등을 선택했다. React와 Next.js 관련 패키지는 생성 과정에서 함께 설치되었다.

서버 실행 후 터미널에 표시된 주소로 접속했다. 기본 주소는 `http://localhost:3000`이며 포트 사용 상황에 따라 달라질 수 있다. 서버 종료는 `Ctrl + C`다.

### B. Prettier와 ESLint 설정

**VS Code(Visual Studio Code)**에 다음 확장 프로그램을 설치했다.

| 도구     | 역할                              |
| -------- | --------------------------------- |
| Prettier | 들여쓰기·줄바꿈 등 코드 형식 정리 |
| ESLint   | 코드 문제와 규칙 위반 검사        |

`chapter02` 최상위에 `.prettierrc`를 추가했다. 설정은 **JSON(JavaScript Object Notation)** 형식이다.

```json
{
  "useTabs": false,
  "tabWidth": 4,
  "singleQuote": true,
  "trailingComma": "all",
  "semi": true
}
```

| 규칙                   | 의미                                             |
| ---------------------- | ------------------------------------------------ |
| `useTabs: false`       | 탭 대신 공백 사용                                |
| `tabWidth: 4`          | 들여쓰기 너비 4칸                                |
| `singleQuote: true`    | JavaScript·TypeScript 문자열에서 작은따옴표 선호 |
| `trailingComma: "all"` | 허용되는 여러 줄 구문에 마지막 쉼표 추가         |
| `semi: true`           | 세미콜론 사용                                    |

VS Code 설정에서 **Format On Save**를 활성화하고 **Default Formatter**를 Prettier로 지정했다.

JSON의 키에는 큰따옴표를 사용하며 주석과 마지막 항목 뒤 쉼표를 넣지 않는다. `singleQuote` 설정에도 JSON은 큰따옴표를 유지한다. JSX 속성 따옴표는 `jsxSingleQuote`라는 별도 옵션이다.

### C. 해결한 오류

상위 폴더에서 `npm run dev`를 실행하여 `package.json`을 찾지 못하는 `ENOENT(파일 또는 디렉터리가 없음을 나타내는 오류 코드)`가 발생했다.

프로젝트 폴더로 이동하여 해결했다.

```bash
cd chapter02
npm run dev
```

**이번 실습의 npm 명령어는 `package.json`이 있는 프로젝트 최상위에서 실행한다.**

### D. 다른 PC에서 설치

다른 **PC(Personal Computer, 개인용 컴퓨터)**에서는 Node.js를 준비하고 소스와 `package.json`, `package-lock.json`을 가져온 뒤 설치한다.

```bash
npm i
npm run dev
```

`npm i`는 `npm install`의 줄임말이다. VS Code 확장 프로그램과 편집기 설정도 다른 PC에서 준비해야 한다. 환경 차이를 줄이려면 Node.js와 npm 버전도 기록하여 맞춘다.

## 4. 프로젝트 명세와 설정 파일

### A. 의존성과 scripts

`package.json`에는 프로젝트 정보, 의존성, 실행 명령어 등이 기록된다. npmjs.com에서는 패키지의 사용법과 버전 등을 확인할 수 있다.

| 항목              | 역할                    |
| ----------------- | ----------------------- |
| `dependencies`    | 앱 실행에 필요한 패키지 |
| `devDependencies` | 개발·검사·빌드 도구     |
| `scripts`         | 실행 명령어 정의        |
| `version`         | 프로젝트 자체의 버전    |

```bash
npm i 패키지명
npm i -D 패키지명
```

개발 의존성도 배포 환경의 빌드 단계에서는 필요할 수 있다. `devDependencies`라는 이유만으로 자동으로 업로드에서 제외되는 것은 아니다.

### B. 실행 명령어

| 명령어          | 역할                            |
| --------------- | ------------------------------- |
| `npm run dev`   | 개발 서버 실행과 코드 변경 반영 |
| `npm run lint`  | 등록된 코드 검사 명령 실행      |
| `npm run build` | 배포용 결과물 생성              |
| `npm run start` | 빌드된 결과물로 운영 서버 실행  |

실제 명령어는 `package.json`의 `scripts`에서 확인한다. `lint`도 등록되어 있어야 실행할 수 있다.

Next.js 16에서는 빌드가 ESLint 검사를 자동 실행하지 않으므로 별도로 검사한다. 기본 빌드 결과물은 `.next` 폴더에 생성된다.

### C. 설정 파일의 역할

| 파일                | 역할                           |
| ------------------- | ------------------------------ |
| `package-lock.json` | 결정된 의존성 버전과 구조 기록 |
| `tsconfig.json`     | TypeScript 설정                |
| `eslint.config.mjs` | 코드 검사 설정                 |
| `.prettierrc`       | 코드 형식 설정                 |
| `next.config.ts`    | Next.js 동작 설정              |

`tsconfig.json`의 `target`은 JavaScript 문법 수준, `module`은 모듈 처리 방식을 정한다. `CommonJS`는 모듈 방식이며 `target`을 대신하는 값이 아니다. 실습에서는 자동 생성된 Next.js 설정을 유지한다.

`.mjs`는 ECMAScript 모듈로 해석하는 JavaScript 파일 확장자다. `next.config.ts`에서는 외부 이미지 허용, 리다이렉트, **HTTP(HyperText Transfer Protocol)** 응답 헤더 등을 설정할 수 있다.

## 5. App Router와 레이아웃

### A. 파일 위치와 URL

App Router는 `app` 폴더의 구조와 정해진 파일명을 기준으로 **URL(Uniform Resource Locator)**과 페이지를 구성한다.

| 파일                    | 역할                  |
| ----------------------- | --------------------- |
| `app/page.tsx`          | 메인 페이지 `/`       |
| `app/member/page.tsx`   | 회원 페이지 `/member` |
| `app/layout.tsx`        | 전체 공통 레이아웃    |
| `app/member/layout.tsx` | 회원 공통 레이아웃    |
| `app/globals.css`       | 공통 스타일           |
| `app/favicon.ico`       | 사이트 아이콘         |

**URL은 함수 이름이 아니라 파일 위치로 결정된다.** 일반 파일을 추가한다고 모두 페이지가 되는 것은 아니다.

```tsx
export default function MemberPage(): React.JSX.Element {
  return <h1>/member</h1>;
}
```

### B. 공통 레이아웃

레이아웃의 `{children}`에는 해당 페이지 또는 하위 레이아웃이 들어간다.

`/member`에서는 다음 순서로 화면을 구성했다.

1. 전체 공통 상단
2. 회원 공통 상단
3. 회원 페이지 내용
4. 전체 공통 하단

`<html>`과 `<body>`는 최상위 레이아웃에서 작성한다. 헤더·본문·푸터는 `<body>` 안에 배치하며 하위 레이아웃에는 두 태그를 다시 작성하지 않는다.

## 6. 컴포넌트와 모듈

### A. 컴포넌트 정의

컴포넌트는 UI의 한 부분을 정의하는 단위다. 컴포넌트 이름은 대문자로 시작해야 하고 파일명도 대문자로 시작하는 관례가 있다.

```tsx
export default function Counter(): React.JSX.Element {
  return <div>Counter!</div>;
}
```

일반 변수나 함수까지 대문자로 시작해야 하는 것은 아니다. 현재 Counter는 문구를 표시하며 숫자 증가 기능은 아직 없다.

### B. 내보내기와 가져오기

| 방식               | 내보내기                  | 가져오기                                             |
| ------------------ | ------------------------- | ---------------------------------------------------- |
| 기본 내보내기      | `export default Counter;` | `import Counter from './components/Counter';`        |
| 이름 있는 내보내기 | `export { counterVar };`  | `import { counterVar } from './components/Counter';` |

기본 내보내기는 파일당 최대 하나다. 모든 모듈에 필수는 아니지만 Next.js의 `page.tsx`와 `layout.tsx`는 해당 컴포넌트를 기본 내보내기로 제공한다. 이름 있는 내보내기는 객체뿐 아니라 함수와 컴포넌트도 포함할 수 있다.

같은 파일에서 함께 가져올 수 있다.

```tsx
import Counter, {
  counterVar as counterData,
  counterVar2,
} from "./components/Counter";
```

`as`는 현재 파일에서 사용할 이름을 바꾼다. 객체 이름을 대문자로 바꾼다고 컴포넌트가 되지는 않는다. import만으로 화면에 표시되지 않으며 `<Counter />`처럼 사용해야 한다.

### C. 경로 구분

| 표현      | 의미                                            |
| --------- | ----------------------------------------------- |
| `./`      | 현재 파일의 폴더                                |
| `../`     | 한 단계 위 폴더                                 |
| `@/`      | 수업 설정에서는 프로젝트 최상위에 대응하는 별칭 |
| `'react'` | 설치된 패키지 이름                              |

수업의 `"paths": { "@/*": ["./*"] }` 설정은 별도 `baseUrl`이 없다면 `tsconfig.json`이 있는 폴더를 기준으로 한다.

```tsx
import Counter from "@/app/components/Counter";
```

패키지는 직접 `node_modules` 경로를 적지 않고 이름으로 가져온다. 도구가 패키지 설정을 확인하여 진입 파일을 찾는다.

## 7. TypeScript 타입

### A. 타입 가져오기

타입만 사용할 항목은 `type`으로 표시한다.

```tsx
import type { ReactNode } from "react";
```

다음 방식도 가능하다.

```tsx
import { type ReactNode } from "react";
```

타입 import는 변환된 JavaScript에서 제거된다.

### B. interface와 type

| 구분                  | `interface`    | `type`      |
| --------------------- | -------------- | ----------- |
| 객체 구조 정의        | 가능           | 가능        |
| 확장·조합             | 주로 `extends` | 주로 `&` 등 |
| 유니온·원시 타입 별칭 | 직접 정의 불가 | 가능        |
| 같은 이름 선언 병합   | 가능           | 불가능      |

```ts
interface ProductItemProps {
  itemName: string;
  itemPrice: number;
}

type Status = "loading" | "success" | "error";
```

단순한 객체 구조는 둘 다 정의할 수 있다. interface로도 함수 호출 형태를 정의할 수 있다.

## 8. JSX 핵심 규칙

### 1. 태그 형태 — 화면을 설명하는 표현식

```tsx
return <div>Counter!</div>;
```

JSX는 React 요소 객체를 만들도록 변환되며 실제 **DOM(Document Object Model, 문서 객체 모델)** 요소 자체는 아니다.

**태그 형태로 작성하고 React 요소 객체로 변환된다**고 이해한다.

### 2. 닫는 태그 — 빈 요소도 닫기

JSX에서는 모든 태그를 닫는다.

```tsx
<div>내용</div>
<br />
<img src="/sample.png" alt="예시 이미지" />
```

위 코드는 개별 태그 문법 예시다. 여러 요소를 함께 반환할 때는 하나로 묶는다.

### 3. 소괄호 — 여러 줄 반환 묶기

```tsx
return (
  <div>
    <h1>상품 정보</h1>
    <p>상품을 확인하세요.</p>
  </div>
);
```

소괄호는 표현식을 묶는 JavaScript 문법이다. JSX 객체를 생성하는 기호는 아니다. 한 줄이면 생략할 수 있다.

```tsx
return <div>Counter!</div>;
```

여러 줄에서는 **`return`과 여는 소괄호를 같은 줄에 작성한다.** `return` 직후에 줄을 바꾸면 의도한 JSX가 반환되지 않을 수 있다.

### 4. Fragment — 여러 요소 묶기

```tsx
return (
  <>
    <h1>상품 정보</h1>
    <p>상품 설명</p>
  </>
);
```

`<>...</>`는 Fragment의 축약형이다.

- 여러 자식 요소를 묶는다.
- 감싸는 DOM 요소는 추가하지 않는다.
- 축약형은 import 없이 사용한다.

명시적으로 작성할 수도 있다.

```tsx
import { Fragment } from "react";

return (
  <Fragment>
    <h1>상품 정보</h1>
    <p>상품 설명</p>
  </Fragment>
);
```

나란한 JSX 태그를 하나의 표현식으로 구성하기 위한 규칙이다. 모든 컴포넌트에 감싸는 DOM 태그가 필수라는 뜻은 아니다. 컴포넌트는 배열이나 null 등도 반환할 수 있다.

### 5. 중괄호 — JavaScript 표현식 사용

```tsx
const itemName = "아이폰18";
const itemPrice = 10000;

return (
  <div>
    <h1>{itemName}</h1>
    <p>{itemPrice.toLocaleString()}원</p>
  </div>
);
```

중괄호에는 변수·계산·함수 호출처럼 값을 만드는 표현식을 넣는다. `const`나 `if` 문은 `return` 전에 작성한다.

#### 스타일의 이중 중괄호

```tsx
<dt style={{ backgroundColor: "black", color: "orange" }}>상품명</dt>
```

| 기호         | 역할                           |
| ------------ | ------------------------------ |
| 바깥 `{...}` | JSX에서 JavaScript 표현식 사용 |
| 안쪽 `{...}` | JavaScript 객체 리터럴         |

**JSON 문법이 아니다.** 객체를 변수로 정의했다면 변수만 전달한다.

```tsx
const styles = {
  backgroundColor: "skyblue",
  height: "2rem",
};

return <dl style={styles}>...</dl>;
```

CSS 속성 이름은 `backgroundColor`처럼 camelCase로 작성한다.

### 6. 조건부 렌더링 — 삼항 연산자와 AND 연산자

두 결과 중 하나를 표시하려면 삼항 연산자를 사용한다.

```tsx
{
  isSoldOut ? <p>품절</p> : <p>구매 가능</p>;
}
```

조건이 참일 때만 표시하려면 `&&`를 사용한다.

```tsx
{
  isSoldOut && <p>품절</p>;
}
```

`&&`는 왼쪽 값이 거짓으로 평가되면 오른쪽을 평가하지 않는 단락 평가를 이용한다.

숫자 `0`이 왼쪽에 오면 화면에 `0`이 표시될 수 있으므로 명확한 조건을 작성한다.

```tsx
{
  stock > 0 && <p>재고 있음</p>;
}
```

### 7. 주석 — 작성 위치 구분

**`//`는 그 줄 끝까지 주석 처리한다.** 따라서 뒤에 필요한 코드가 있으면 줄을 바꿔야 한다. 모든 JSX 주석에 줄개행이 필요한 것은 아니다.

#### A. 일반 JavaScript 코드 영역

`return` 전처럼 일반 JavaScript를 작성하는 곳에서는 평소처럼 주석을 사용한다.

```tsx
export default function ProductPage() {
  // 상품명 정의
  const itemName = "아이폰18";

  /* 상품 화면 반환 */
  return <h1>{itemName}</h1>;
}
```

#### B. 태그 사이의 내용 영역

`<div>`와 `</div>` 사이처럼 화면 내용을 작성하는 곳에서는 `{/* ... */}`을 사용한다.

```tsx
return (
  <div>
    {/* 상품명 표시 */}
    <h1>아이폰18</h1>
  </div>
);
```

여러 줄도 가능하다.

```tsx
return (
  <div>
    {/*
            상품 정보를 표시하는 영역
            상품명과 가격을 함께 표시한다.
        */}
    <h1>아이폰18</h1>
  </div>
);
```

이 형식은 한 줄에 작성해도 괜찮다. 태그 사이에서 `//`를 그냥 쓰면 주석이 아니라 화면의 글자가 된다.

```tsx
return (
  <div>
    // 이 문장은 화면에 표시됨
    <h1>상품</h1>
  </div>
);
```

#### C. 중괄호 안에서 한 줄 주석 사용

중괄호 안에서 `//`를 사용할 수도 있다. 이때 **닫는 중괄호는 다음 줄에 작성한다.**

```tsx
return (
  <div>
    {
      // 상품명 표시
    }
    <h1>상품</h1>
  </div>
);
```

다음은 잘못된 예시다.

```tsx
{// 상품명 표시}
```

`//`가 뒤의 `}`까지 주석 처리하기 때문에 닫는 중괄호가 사라진 것으로 해석된다. 실습에서는 `{/* 상품명 표시 */}`이 더 간단하다.

#### D. 시작 태그의 속성 영역

태그 안의 주석은 시작 태그에서 속성을 작성하는 위치를 뜻할 수 있다.

```tsx
return (
  <div
    // CSS 클래스 설정
    className="product"
  >
    상품 정보
  </div>
);
```

여기서는 `//`를 사용할 수 있지만 다음 속성과 `>`는 주석과 다른 줄에 있어야 한다.

```tsx
// 잘못된 예시: >까지 주석 처리됨
<div // 설명>
```

시작 태그의 속성 사이에는 `{/* ... */}`을 그대로 넣지 않는다. 헷갈린다면 주석을 시작 태그 밖으로 옮긴다.

```tsx
return (
  <>
    {/* 상품 정보 영역 */}
    <div className="product">상품 정보</div>
  </>
);
```

**우선 기억할 기준:** 일반 JavaScript에서는 `//`, JSX의 태그 사이에서는 `{/* ... */}`을 사용한다.

### 8. 반환 타입 — JSX 요소와 렌더링 가능한 값

| 타입                | 의미                                |
| ------------------- | ----------------------------------- |
| `React.JSX.Element` | JSX 요소 객체                       |
| `React.ReactNode`   | React가 렌더링할 수 있는 더 넓은 값 |

```tsx
function Title(): React.JSX.Element {
  return <h1>상품 정보</h1>;
}

function Message(): React.ReactNode {
  return "상품이 없습니다.";
}
```

`ReactNode`에는 JSX 요소, 문자열, 숫자, `null`, `undefined`, 불리언, 노드 배열 등이 포함된다.

일반 객체와 함수는 그대로 렌더링하지 않는다. 객체의 속성이나 함수 호출 결과를 표시한다.

```tsx
return <div>{product.name}</div>;
```

```tsx
return <div>{getMessage()}</div>;
```

`null`, `undefined`, 불리언은 화면에 내용을 표시하지 않는다.

## 9. props로 데이터 전달

**props(properties, 속성)**는 부모 컴포넌트가 자식에게 전달하는 데이터다. 자식은 받은 값으로 화면을 구성한다.

### A. 자식 컴포넌트

`app/product/productitem.tsx`:

```tsx
interface ProductItemProps {
  itemName: string;
  itemPrice: number;
}

export default function ProductItem(
  props: ProductItemProps,
): React.JSX.Element {
  return (
    <>
      <dl>
        <dt>상품명</dt>
        <dd>{props.itemName}</dd>
      </dl>
      <dl>
        <dt>판매가</dt>
        <dd>{props.itemPrice.toLocaleString()}원</dd>
      </dl>
    </>
  );
}
```

### B. 부모 컴포넌트

`app/product/page.tsx`:

```tsx
import ProductItem from "./productitem";

export default function ProductPage(): React.JSX.Element {
  return <ProductItem itemName="아이폰18" itemPrice={10000} />;
}
```

| 전달 방식             | 의미                      |
| --------------------- | ------------------------- |
| `itemName="아이폰18"` | 문자열 전달               |
| `itemPrice={10000}`   | 숫자 전달                 |
| `props.itemName`      | 자식에서 받은 상품명 사용 |
| `props.itemPrice`     | 자식에서 받은 가격 사용   |

상품명은 실습용 문구다. 수업에서는 `props` 매개변수의 타입이 없어 오류가 발생했고 위처럼 `interface`로 구조를 정의하여 해결할 수 있다.

props는 읽기 전용이다. 부모가 새 값으로 렌더링하면 자식도 새 값을 받는다. 일반 변수 변경만으로 화면 갱신이 발생하는 것은 아니며 이후 state를 배워 연결한다.

## 오늘 배운 점

설정 파일, 페이지, 레이아웃, 컴포넌트의 역할을 구분했다. 오류가 발생하면 코드뿐 아니라 현재 실행 경로, 파일 위치, 타입 정의도 확인해야 한다는 점을 배웠다.

JSX는 HTML과 비슷해 보여도 JavaScript 표현식이므로 닫는 태그, 중괄호, 주석의 작성 위치를 구분해야 한다.
