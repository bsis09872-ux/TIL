## 4. Props, Interface, Children

Props는 부모에서 자식으로 전달하는 읽기 전용 데이터이다. TypeScript interface로 구조를 지정할 수 있다.

```tsx
interface Product {
  itemName: string;
  itemPrice: number;
}

export default function ProductItem({
  itemName,
  itemPrice,
}: Product): React.JSX.Element {
  return (
    <>
      <dl>
        <dt>상품명</dt>
        <dd>{itemName}</dd>
      </dl>
      <dl>
        <dt>판매가</dt>
        <dd>{itemPrice}</dd>
      </dl>
    </>
  );
}
```

- 구조 분해 할당: `({ itemName, itemPrice }: Product)`는 props 객체에서 필드를 꺼내는 문법이다.
- `<dl>`: 설명 목록, `<dt>`: 항목명, `<dd>`: 설명.
- `children`: 컴포넌트 시작·종료 태그 사이에 전달하는 콘텐츠. 일반적으로 `React.ReactNode`로 타입 지정.
- 자식은 Props를 직접 변경하지 않는다. 부모가 State를 변경해 새로운 Props를 전달하거나 콜백을 전달한다.
- Props의 읽기 전용 원칙과 `Object.freeze()` 또는 property descriptor는 동일한 개념이 아니다.

## 5. 렌더링 방식과 use client

- SSR(Server-Side Rendering): 서버에서 HTML 렌더링.
- CSR(Client-Side Rendering): 브라우저에서 JavaScript로 UI 렌더링.
- Pre-rendering: 화면을 미리 렌더링해 초기 결과 제공.
- Hydration: 서버에서 렌더링한 HTML의 Client Component 부분에 React 상호작용 연결.
- `"use client"`: Client Component 경계 선언. CSR만 수행하라는 뜻은 아니다.

```tsx
"use client";
import { useState } from "react";
```

## 6. 이벤트와 이벤트 타입

React는 JSX에서 camelCase 이벤트 Props를 사용한다.

```tsx
<button onClick={increase}>증가</button> // 함수 참조 전달
<button onClick={() => increase()}>증가</button> // 클릭 시 호출
```

`onClick={increase()}`는 렌더링 중 즉시 실행되므로 상태를 계속 변경하면 Too many re-renders 오류를 일으킬 수 있다.

| 이벤트      | React TypeScript 타입           |
| ----------- | ------------------------------- |
| 값 변경     | React.ChangeEvent<T>            |
| 클릭·마우스 | React.MouseEvent<T>             |
| 폼 제출     | React.SubmitEvent<T> (React 19) |
| 키보드      | React.KeyboardEvent<T>          |
| 포커스      | React.FocusEvent<T>             |
| 스크롤      | React.UIEvent<T>                |
| 휠          | React.WheelEvent<T>             |
| 터치        | React.TouchEvent<T>             |

- `React.FormEvent<T>`는 기존 코드에서 흔하며 React 19 타입에서는 deprecated로 표시된다.
- `event.target`: 실제 이벤트 발생 대상.
- `event.currentTarget`: 현재 이벤트 핸들러가 연결된 요소.
- 함수 컴포넌트에서는 DOM 이벤트의 `this`에 의존하지 않고 이벤트 객체나 ref를 사용한다.
- `preventDefault()`: 기본 브라우저 동작 취소.
- `stopPropagation()`: 이벤트 전파 중단.

```tsx
const handleChange = (event: React.ChangeEvent<HTMLInputElement>) => {
  console.log(event.currentTarget.value);
};
```

## 7. Form 제출과 입력값 관리

HTML form은 기본 제출 동작을 가진다. 클라이언트에서 제출을 처리할 때 필요하면 `preventDefault()`를 사용한다.

```tsx
const handleSubmit = (event: React.SubmitEvent<HTMLFormElement>) => {
  event.preventDefault();
  const formData = new FormData(event.currentTarget);
  console.log(formData.get("title"));
};
```

`FormData`로 값을 읽으려면 input에 `name="title"` 같은 name 속성이 필요하다. Next.js Server Actions 등에서는 반드시 preventDefault가 필요한 것은 아니다.

Controlled Component:

```tsx
<input value={title} onChange={(e) => setTitle(e.currentTarget.value)} />
```

입력 → onChange → setTitle → State 갱신 → 입력창 value 반영.

## 8. useState와 카운터

```tsx
"use client";
import { useState } from "react";

export default function Counter(): React.JSX.Element {
  const [number, setNumber] = useState<number>(0);
  const increase = () => setNumber((prev) => prev + 1);
  const decrease = () => setNumber((prev) => prev - 1);

  return (
    <>
      <h1>{number}</h1>
      <button type="button" onClick={increase}>
        +1
      </button>
      <button type="button" onClick={decrease}>
        -1
      </button>
    </>
  );
}
```

- `useState(0)`는 현재 상태값과 Setter를 반환한다.
- Setter는 상태 업데이트를 요청한다.
- `setNumber(prev => prev + 1)`은 이전 상태를 기준으로 계산하는 함수형 업데이트이다.
- React의 Automatic Batching은 여러 업데이트를 모아 불필요한 렌더링을 줄인다.
- `setNumber(number + 1)`을 한 핸들러에서 3번 호출해도 같은 렌더의 number를 사용하므로 보통 +1이다.
- `setNumber(prev => prev + 1)`을 3번 호출하면 순차 계산되어 +3이다.

## 9. 지역변수, 순수성, 재렌더링

컴포넌트 함수는 재렌더링될 때 다시 실행된다.

```tsx
let count = 0;
const increase = () => {
  setNumber((prev) => prev + 1);
  count++;
  console.log(count);
};
```

위의 count는 렌더링할 때마다 다시 0으로 초기화된다. 따라서 클릭마다 로그가 1로 나올 수 있지만 State인 number는 유지된다.

- 지역변수 사용이 금지된 것은 아니다. 렌더링 사이에 유지해야 하는 값을 일반 지역변수로 저장하지 않는다.
- 지역 함수나 변수를 다시 만드는 것이 곧 메모리 누수는 아니다.
- 렌더링은 순수해야 한다. 이벤트 핸들러에서는 State 업데이트나 필요한 부수 효과를 수행할 수 있다.

## 10. Virtual DOM, 비교와 불변성

State 변경 → Render(새 UI 계산) → Reconciliation(비교) → Commit(실제 DOM 반영).

- React는 실제 DOM 전체를 매번 삭제하고 다시 만들지 않는다.
- State의 이전 값과 새 값 비교에 Object.is()를 사용한다.
- 배열·객체는 내부 깊은 값보다 참조 동일성이 중요하다.
- State 배열을 직접 push한 뒤 같은 참조로 setItems하면 업데이트가 무시될 수 있다.

```tsx
// 피할 것
items.push({ id: Date.now(), title, checked: false });
setItems(items);

// 권장
setItems((prev) => prev.concat([{ id: Date.now(), title, checked: false }]));
```

- 추가: concat, 전개 연산자.
- 수정: map.
- 삭제: filter.
- map/filter/concat은 새 배열을 반환하지만 호출 자체가 재렌더링을 유발하는 것은 아니다.

## 11. JSX 반복 렌더링, map과 key

JSX의 중괄호 안에는 JavaScript 표현식을 작성한다. if·for 문을 직접 넣기보다 조건부 연산자와 map을 활용한다.

```tsx
<ul>
  {items.length === 0
    ? null
    : items.map(({ id, title }) => <li key={id}>{title}</li>)}
</ul>
```

- `map()`: 배열 데이터를 JSX 요소 배열로 변환.
- `key`: React가 목록 항목의 정체성을 구별하는 특별한 Props.
- `key`는 HTML의 `id`와 다르다.
- `#menu`는 CSS의 ID 선택자이며 해시 함수와 다른 개념이다.
- `Date.now()`: 1970-01-01 00:00:00 UTC부터 경과한 밀리초. 간단한 실습용 ID로 가능하지만 중복 위험이 있다.

## 12. Hook과 useRef

Hook은 React 기능을 활용하는 함수다. 일반적으로 use로 시작한다.

Hook 규칙:

1. React 함수 컴포넌트 또는 사용자 정의 Hook에서 호출한다.
2. 최상위 수준에서 호출하며 조건문·반복문·이벤트 핸들러 내부에서 임의로 호출하지 않는다.
3. 사용자 정의 Hook 이름은 use로 시작한다.
4. Next.js App Router에서 useState·useRef 등 클라이언트 Hook을 쓰려면 Client Component 경계가 필요하다.

useRef 사용 목적:

1. 재렌더링을 요청하지 않으면서 렌더링 사이에 값을 유지.
2. input, video, audio, div, canvas, dialog 등의 DOM 요소 참조.

```tsx
"use client";
import { useRef } from "react";

export default function FocusInput() {
  const inputRef = useRef<HTMLInputElement>(null);
  return (
    <>
      <input ref={inputRef} />
      <button onClick={() => inputRef.current?.focus()}>포커스</button>
    </>
  );
}
```

| 비교                   | useState           | useRef                |
| ---------------------- | ------------------ | --------------------- |
| 렌더링 사이 값 유지    | O                  | O                     |
| 값 변경 시 렌더링 요청 | O                  | X                     |
| 접근 방식              | 상태 변수          | ref.current           |
| 대표 용도              | 화면에 반영할 상태 | DOM 참조, 비반응형 값 |

## 13. forwardRef와 React 19 Direct ref prop

기존 React에서는 부모의 ref를 자식 함수 컴포넌트 내부 DOM까지 전달하기 위해 forwardRef를 사용했다.

React 18:

```tsx
import { forwardRef } from "react";

const CustomInput = forwardRef<HTMLInputElement, {}>(
  function CustomInput(_props, ref) {
    return <input ref={ref} />;
  },
);
```

React 19에서는 함수 컴포넌트가 ref를 Props로 직접 받을 수 있다.

```tsx
import type { Ref } from "react";

function CustomInput({ ref }: { ref?: Ref<HTMLInputElement> }) {
  return <input ref={ref} />;
}
```

- useRef: 참조 객체 생성·유지.
- forwardRef: 부모의 ref를 자식 내부 요소로 전달하던 기존 패턴.
- React 19: ref를 일반 Props처럼 직접 전달할 수 있음.
- forwardRef는 기존 코드에서 여전히 보일 수 있으므로 버전 확인이 필요하다.

## 15. 오늘의 한 줄 정리
