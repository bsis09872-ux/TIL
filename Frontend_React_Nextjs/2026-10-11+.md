#### 2. 새롭게 이해한 내용

##### A. 구조 재사용과 CSS 적용 범위

기존 HTML 구조를 복사하더라도 클래스명이 달라지면 기존 CSS가 자동으로 적용되지는 않는다.

```css
.DailyList,
.GenreList,
.UpdatesList,
.SetList {
  display: flex;
  gap: 10px;
}
```

- 공통 배치는 선택자를 묶어 지정한다.
- 랭킹·할인 문구·필터 등 영역별 차이는 별도 스타일로 처리한다.
- 재사용할 때 HTML 계층과 CSS 선택자를 함께 확인해야 한다.

**핵심:** HTML 구조 재사용과 CSS 스타일 재사용은 함께 점검해야 한다.

##### B. 새로운 이미지 추가와 선택자 범위

랭킹 SVG를 `<img>`로 추가하면서 포스터용 CSS가 랭킹 이미지까지 선택할 수 있다는 점을 확인했다.

```css
/* 목록 내부의 모든 이미지 선택 */
.GenreList img {
  width: 100%;
}

/* 포스터 틀의 직접 자식 이미지만 선택 */
.GenreList .HomeView_Poster > img {
  width: 100%;
}
```

**배운 점:** 새로운 요소를 추가할 때 기존 CSS 선택자의 적용 대상이 늘어나는지 확인해야 한다.

랭킹 SVG가 포스터 틀 밖에 있으면 두 번째 선택자로 구분할 수 있다. 같은 틀 안에 있다면 별도 클래스로 구분해야 한다.

##### C. SVG 랭킹 숫자 활용

SVG(Scalable Vector Graphics)는 도형과 경로 정보로 표현하는 벡터 이미지 형식이다.

```html
<img class="Genre_rank" src="./icons/ranking-1.svg" alt="1위" />
```

- SVG 파일도 `<img>`로 불러올 수 있다.
- `<path>`는 도형을 구성하는 경로 정보를 표현한다.
- 랭킹 이미지를 포스터와 별도 요소로 두어 크기와 위치를 구분할 수 있다.

##### D. Normal Flow — 기본 문서 흐름 ⭐

```html
<div class="content_left">
  <section class="HomeView_Updates">...</section>
  <section class="HomeView_Set">...</section>
</div>
```

`content_left`에 Flexbox를 선언하지 않았는데도 내부 `section`들이 세로로 배치되었다.

이는 **Normal Flow(기본 문서 흐름)**에서 블록 요소가 위에서 아래로 배치되기 때문이다.

```text
content_left
    │
    ├─ HomeView_Updates
    │
    └─ HomeView_Set
```

**배운 점**

- 세로로 배치되었다고 반드시 `flex-direction: column`이 적용된 것은 아니다.
- 부모가 Grid Item이어도 내부 자식까지 자동으로 Grid 배치되는 것은 아니다.
- 단순한 세로 나열은 기본 흐름으로 두고, 정렬·간격 제어가 필요할 때 Flexbox를 사용할 수 있다.

##### E. 중첩 Flexbox — 배치 역할 분리

장르별 인기웹툰에서 제목과 필터는 세로로, 더보기는 오른쪽에 배치했다.

```css
.HomeView_Hot_Genre {
  display: flex;
  justify-content: space-between;
  align-items: center;
}

.Hot_Genre_Head {
  display: flex;
  flex-direction: column;
  align-items: flex-start;
}
```

```text
HomeView_Hot_Genre (가로 배치)
│
├─ Hot_Genre_Head (세로 배치)
│    ├─ 제목
│    └─ 필터
│
└─ 더보기
```

- 바깥 부모 → 제목 묶음과 더보기의 가로 배치
- 안쪽 부모 → 제목과 필터의 세로 배치

`flex-direction: column`에서 `justify-content: space-between`은 세로 방향으로 작동하며, 분배할 남는 높이가 있어야 간격이 벌어진다.

### D. JavaScript / TypeScript — 변수 선언과 스코프 복습

#### 1. 변수 선언과 할당

JavaScript와 TypeScript는 `const`, `let`, `var`의 선언 및 Scope 규칙을 공유한다.

| 개념          | 설명                                          |
| ------------- | --------------------------------------------- |
| Declaration   | 변수를 선언하는 것                            |
| Assignment    | 변수에 값을 할당하는 것                       |
| Reassignment  | 기존 변수에 값을 다시 할당하는 것             |
| Redeclaration | 동일 Scope에서 같은 이름으로 다시 선언하는 것 |

```javascript
const apiEndpoint = "https://server.com/v1";

apiEndpoint = "https://server.com/v2"; // ❌ 재할당 불가

let endpoint = apiEndpoint;
endpoint = "https://server.com/v2"; // ✅ 재할당 가능
```

`const`는 동일한 값을 다시 할당하더라도 오류가 발생한다.

#### 2. `const` · `let` · `var` 비교

| 구분              | `const` | `let` | `var`    |
| ----------------- | ------- | ----- | -------- |
| 재할당            | ❌      | ✅    | ✅       |
| 동일 Scope 재선언 | ❌      | ❌    | ✅       |
| Scope             | Block   | Block | Function |
| 선언 시 초기값    | 필수    | 선택  | 선택     |

```javascript
let count = 1;
count = 2; // ✅ 재할당
let count = 3; // ❌ 재선언

var number = 1;
var number = 2; // ✅ 재선언
```

> ⭐ `let`은 재할당이 불가능한 것이 아니라, **동일 Scope에서 재선언이 불가능**한 것이다.

#### 3. Scope — 변수의 유효 범위

**Block Scope (`const`, `let`)**

```javascript
let score = 10;

{
  let score = 20;
  console.log(score); // 20
}

console.log(score); // 10
```

- `{}`로 구분되는 블록마다 별도의 Scope를 가진다.
- `if`, `for`, 함수 내부 등에서 적용된다.
- 서로 다른 Scope에서는 같은 이름의 변수를 선언할 수 있다.
- 안쪽 변수가 바깥쪽의 같은 이름 변수를 가리는 현상을 **Variable Shadowing**이라고 한다.

**Function Scope (`var`)**

```javascript
function example() {
  if (true) {
    var message = "Hello";
  }

  console.log(message); // Hello
}
```

`var`는 일반적인 `{}` 블록을 별도 Scope로 취급하지 않고, 함수 내부에서 선언하면 해당 함수 범위에서 유효하다.

#### 4. `const` 객체의 Property 변경

`const`는 변수 자체의 재할당을 금지하지만, 객체 내부 Property 변경까지 금지하지는 않는다.

```javascript
const config = {
  version: 1,
};

config.version = 2; // ✅ 속성 변경 가능
config = { version: 3 }; // ❌ 재할당 불가
```

단, `Object.freeze()` 또는 TypeScript의 `readonly` 등 추가 제약이 있으면 변경이 제한될 수 있다.

#### 5. JavaScript와 TypeScript의 차이

```typescript
let count = 10;
count = "Hello";
```

- **JavaScript:** 정상 실행. 다른 타입의 값을 재할당할 수 있다.
- **TypeScript:** `count`가 `number`로 추론되므로 문자열 할당 시 타입 오류가 발생한다.

| 상황                                 | 대표 오류     |
| ------------------------------------ | ------------- |
| TypeScript `const` 재할당            | `TS2588`      |
| TypeScript `let` / `const` 재선언    | `TS2451`      |
| JavaScript `let` / `const` 중복 선언 | `SyntaxError` |
| JavaScript `const` 재할당            | `TypeError`   |
| TypeScript 타입 불일치               | `TS2322`      |

**실무 원칙:** 기본적으로 `const`를 사용하고, 재할당이 필요할 때만 `let`을 사용한다. `var`는 가급적 사용하지 않는다.
