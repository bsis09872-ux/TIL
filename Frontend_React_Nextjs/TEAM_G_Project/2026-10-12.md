## 3. TROUBLESHOOTING & LEARNING

### A. 상태 업데이트와 불변성

**어려웠던 점**

- 상태 변수에 값을 직접 할당하는 방식과 React 상태 업데이트의 차이
- 객체와 배열을 수정할 때 새로운 참조가 필요한 이유
- `useCallback`의 의존성 배열과 함수형 업데이트의 관계

**학습 및 해결**

```tsx
setItems((prev) => [...prev, newItem]);
```

이전 상태를 직접 변경하지 않고 새로운 배열을 반환하는 방식으로 정리했다.

`useCallback`은 무조건 사용해야 하는 기능이 아니라, 함수 참조 유지가 필요한 상황에서 선택적으로 사용하는 최적화 도구라는 점을 학습했다.

### B. Route Groups와 슬롯의 차이

**어려웠던 점**

- `(shop)`과 `@modal` 모두 URL에 표시되지 않아 역할을 혼동함
- `(.)`, `(..)`, `(...)`의 상대 경로 계산 기준
- `default.tsx`에서 `return null`을 사용하는 이유

**학습 및 해결**

| 개념 | 역할 |
|---|---|
| `(shop)` | 페이지 그룹화 |
| `@modal` | 병렬 라우팅 슬롯 |
| `(.)` | 같은 라우트 세그먼트 수준 |
| `(..)` | 한 단계 위 라우트 세그먼트 |
| `(...)` | App Router의 루트 |
| `default.tsx` | 슬롯의 활성 경로를 복원할 수 없을 때 대체 콘텐츠 제공 |

라우트 세그먼트는 실제 폴더 깊이와 다르며, Route Group과 슬롯 폴더는 세그먼트 수준 계산에서 제외된다.
