**2. 나머지 연산을 이용한 파일 분산**

- 증가형 정수 ID를 20으로 나눈 나머지에 따라 폴더를 구분

- UUID 문자열을 사용하는 G조는 다른 분산 기준 검토 필요

```ts
const fileId = 12345;
const folder = fileId % 20;

// folder = 5
```

- `original_name` 컬럼 유지

**4. done 컬럼 추가**

- `done BOOLEAN` 필드 추가 제안

## 3. TROUBLESHOOTING & LEARNING

### A. Git Rebase 이후 Push 문제

**문제**

최신 `main`을 개인 브랜치에 반영하는 과정에서 기존 커밋 이력이 변경되어 원격 브랜치와 차이가 발생할 수 있었다.

**해결 및 학습**

```bash
git fetch origin
git rebase origin/main
```

이미 Push한 커밋을 Rebase한 경우, 원격 상태와 팀원의 변경 여부를 확인한 후 다음 명령어 사용을 판단한다.

```bash
git push --force-with-lease origin feat/common
```

`--force-with-lease`는 무조건 안전한 강제 Push가 아니므로 공유 브랜치에서는 팀원과 협의해야 한다.

### B. 커밋 메시지 수정

```bash
git commit --amend -m "chore: initialize project structure"
```

- 가장 최근 커밋의 메시지 수정
- Amend 시 커밋 해시가 변경될 수 있음
- 이미 Push한 커밋이라면 원격 이력에 영향이 생길 수 있음

### C. 미완료 업로드 파일

**문제**

사용자가 게시글을 작성하다 중단하면 파일만 업로드되고 연결된 게시글은 존재하지 않을 수 있다.

**해결 방향**

`done` 상태값으로 업로드된 파일과 등록이 완료된 콘텐츠의 연결 상태를 관리한다.

추후 정리 작업에서는 업로드 진행 중인 파일까지 삭제하지 않도록 생성 시점과 보존 기간도 고려해야 한다.
