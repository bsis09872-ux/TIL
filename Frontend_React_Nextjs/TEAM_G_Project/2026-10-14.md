### A. UPLOADS 스키마 구체화

| 컬럼 | 타입 | 목적 |
|---|---|---|
| `id` | `VARCHAR(36)` PK | 파일 고유 식별자 |
| `gid` | `VARCHAR(36)` | 관련 미디어 그룹 |
| `original_name` | `VARCHAR(255)` | 원본 파일명 |
| `extension` | `VARCHAR(10)` | 확장자 |
| `mime_type` | `VARCHAR(100)` | 파일 형식 |
| `file_path` | `VARCHAR(500)` | 파일 경로 |
| `location` | `VARCHAR(50)` | 사용 위치 |

추가로 이미지 표시 순서를 위한 `sort_order` 컬럼을 검토했다.

### B. 파일 식별자와 저장 방식 학습

- UUID v4: 난수 기반 고유 식별자
- UUID v7: 시간 정보가 포함된 식별자
- AUTO INCREMENT: 순차 증가하는 정수 ID
- `crypto.randomUUID()`를 이용한 UUID v4 생성
- 파일명에 UUID를 사용하고 원본 파일명은 별도 보존하는 방식 검토

```ts
const id = crypto.randomUUID();
const fileName = `${id}.jpg`;
```

### C. 미디어 조회 구조 검토

```sql
SELECT *
FROM uploads
WHERE gid = 'P001'
  AND location = 'detail';
```

`gid`와 `location`을 이용해 특정 상품의 상세 이미지를 구분하는 방식을 검토했다.

## 3. TROUBLESHOOTING & LEARNING

### A. 파일 경로와 브라우저 접근

**문제**

프로젝트 루트의 `uploads/`에 저장한 파일을 브라우저에서 `/uploads/...`로 바로 불러올 수 있는지 확인이 필요했다.

**학습 및 해결 방향**

Next.js에서 정적 파일을 직접 제공하려면 `public/uploads/`를 사용하는 것이 간단하다.

```text
public/uploads/example.jpg
```

브라우저 경로:

```text
/uploads/example.jpg
```

이 내용을 튜터님께 확인할 사항으로 정리했다.

### B. gid와 외래키 관계

**문제**

하나의 `gid`가 상품·회원·게시글 등 여러 종류의 데이터를 가리킬 때 FK를 어떻게 설정해야 하는가?

**검토 내용**

- 일반적인 FK 하나로 여러 테이블의 관계를 보장하기 어려움
- 엔티티 구분 컬럼 또는 연결 테이블 검토
- 프로젝트 구현 범위를 고려해 단순 구조부터 시작하는 방안 검토

최종 설계 방향은 튜터 피드백 이후 다시 정리하기로 했다.

### C. ID 생성과 파일 분산 저장

**문제**

튜터님이 설명한 나머지 연산이 ID 생성 방식인지, 저장 위치 분산 방식인지 불명확했다.

**학습 및 해결 방향**

- UUID는 고유 식별자를 생성하는 방식
- `%` 연산은 정수를 나눈 나머지를 구하는 방식
- ID 생성과 저장 경로 분산은 서로 다른 작업

튜터님께 구체적인 의도를 질문하기로 했다.
