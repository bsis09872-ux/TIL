## 2. TODAY'S WORK — 진행 업무

### A. 개발환경 구축 과정 정리

- Next.js 프로젝트 생성 및 초기 폴더 구조 검토
- React, TypeScript, Tailwind CSS 사용 환경 확인
- shadcn/ui 설정 및 `components.json` 역할 학습
- `react-icons`, `clsx`, `tailwind-merge` 등 패키지 용도 정리
- Prettier 및 ESLint 설정 검토
- `.gitignore`, `.prettierignore` 관리 방식 정리
- `package.json`의 스크립트와 의존성 관리 학습
- 테스트 코드와 `npm run test` 실행 구조 정리

설치·설정 절차를 문서화한 내용과 실제 적용 여부가 확인되지 않은 설정은 구분한다.

### B. Git 협업 컨벤션 정리

| 타입 | 의미 |
|---|---|
| `feat` | 새로운 기능 |
| `fix` | 오류 수정 |
| `docs` | 문서 변경 |
| `refactor` | 기능 변경 없는 코드 구조 개선 |
| `chore` | 환경 설정 및 유지보수 |
| `test` | 테스트 추가·수정 |

- 브랜치별 작업 범위 구분
- 공통 코드 변경 시 팀원 간 사전 조율 필요성 검토
- PR(Pull Request)을 통한 코드 통합 과정 이해

### C. UPLOADS 스키마 설계 착수

- 쇼핑몰에서 사용할 이미지·영상 관리 방식 검토
- 상품 목록, 상품 상세, 큐레이션, 게시글, 프로필 이미지의 공통 관리 필요성 확인
- 실제 파일과 DB 메타데이터를 분리하는 구조 검토
- UUID 기반 파일명 관리 방식 검토
- 스키마 및 ERDCloud 활용 제안

### D. 프로젝트 기획 및 개인 기여 정리

- 팀의 서비스 아이디어와 개인 보완 제안을 구분해 작업 기록 정리
- 서비스 문제 정의, 화면 구조, 사용자 흐름과 구현 범위 검토
- 디자인 시안과 목업 자료를 기획 논의에 활용
- 데이터 구조와 ERDCloud 사용을 제안

개인 기여는 팀원들의 기존 아이디어를 보완하거나 대안을 제안한 범위로 기록하며, 팀 전체의 기획을 혼자 수립한 것으로 표현하지 않는다.

## 3. TROUBLESHOOTING & LEARNING

### A. 개발환경의 일관성

**문제**

팀원별 패키지·설정·코드 작성 방식이 달라지면 프로젝트 통합 시 오류가 발생할 수 있다.

**접근 및 해결 방향**

- 설정 파일을 Git으로 공유
- 공통 패키지와 폴더 구조 정리
- 코드 포맷팅 및 커밋 규칙 문서화
- 설치 과정과 실행 명령어를 팀이 재현할 수 있도록 정리

### B. 미디어 파일 관리 구조

**문제**

각 페이지에서 이미지 경로와 파일명을 개별 관리하면 중복과 관리 혼선이 발생할 수 있다.

**접근 및 해결 방향**

- UPLOADS 테이블을 통한 공통 메타데이터 관리 검토
- 파일 식별자, 저장 경로, 사용 위치를 분리
- 다음 날 세부 컬럼과 관계 구조를 구체화하기로 함
