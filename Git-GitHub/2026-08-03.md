# 3. Git Config

Git 설정은 적용 범위에 따라 세 가지로 나뉜다.

| 옵션 | 적용 범위 |
|------|-----------|
| --local | 현재 저장소(Repository)에만 적용 |
| --global | 현재 사용자에게 적용 |
| --system | 컴퓨터의 모든 사용자에게 적용 |

설정이 중복될 경우 우선순위는 다음과 같다.

```
Local > Global > System
```

즉, Local 설정이 있으면 Global이나 System 설정보다 우선 적용된다.


### 언제 Local Config를 사용할까?

보통은 Global 설정만 사용하면 충분하다.

하지만 프로젝트마다 다른 Git 계정이나 이메일을 사용해야 하는 경우에는 Local Config를 사용한다.

예를 들어 개인 프로젝트와 회사 프로젝트를 같은 컴퓨터에서 관리할 때 서로 다른 계정을 사용해야 한다면 Local Config가 유용하다.

# 4. SSH Key 생성

SSH는 GitHub와 **비밀번호를 반복해서 입력하지 않고 안전하게 통신하기 위한 인증 방식**이다.

### SSH Key 생성

```bash
ssh-keygen -t ed25519 -C "이메일"
```

### 공개 키 확인

Windows

```bash
type id_ed25519.pub
```

Mac

```bash
cat ~/.ssh/id_ed25519.pub
```

확인한 공개 키를 GitHub의

**Settings → SSH and GPG Keys → New SSH Key**

에 등록한다.

# 5. Git이란?

Git은 **분산 버전 관리 시스템(Distributed Version Control System, DVCS)** 이다.

프로젝트의 변경 이력을 기록하고 관리하며, 필요할 때 이전 버전으로 되돌아갈 수 있도록 도와준다.

기존 버전 관리 시스템은 변경된 내용을 하나씩 계산하여 이전 버전부터 순서대로 복원해야 했다.

그래서 변경 이력이 많아질수록 계산량이 증가하여 속도가 느려질 수 있다.

반면 Git은 프로젝트의 특정 시점을 하나의 **Snapshot(스냅샷)** 으로 저장한다.

필요한 버전을 불러올 때는 해당 Snapshot을 바로 가져오기 때문에 더 빠르고 효율적이다.

또한 변경되지 않은 파일은 내부적으로 중복 저장하지 않아 저장 공간도 효율적으로 관리한다.

나는 Git을 게임의 **Save Point**와 비슷하다고 이해했다.

Commit을 할 때마다 하나의 저장 지점이 생성되고, 필요하면 언제든지 그 시점으로 돌아갈 수 있다.


## Git과 GitHub의 차이

| Git | GitHub |
|------|---------|
| 내 컴퓨터(Local)에서 사용하는 분산 버전 관리 시스템 | Git 저장소를 온라인에서 관리하고 공유하는 서비스 |
| 버전 관리 및 변경 이력 기록 | 원격 저장소(Remote Repository) 제공 및 협업 지원 |
| 인터넷 없이도 사용 가능 | Git과 연동하여 협업 및 백업 가능 |

Git은 버전을 관리하는 프로그램이고,

GitHub는 Git 저장소를 인터넷에서 관리하고 공유하는 서비스이다.

즉, Git 없이 GitHub를 사용할 수는 없지만, GitHub 없이도 Git은 사용할 수 있다.

# 6. Git의 작업 흐름

```
Working Directory
        ↓
Staging Area
        ↓
Repository
```

### Working Directory

실제로 파일을 수정하는 작업 공간

### Staging Area

다음 Commit에 포함할 변경 사항을 선택하는 공간

### Repository

Commit을 통해 버전이 저장되는 공간

### 저장소 생성

```bash
git init
```

### Staging Area에 올리기

```bash
git add 파일명
```

현재 디렉터리 이하의 모든 변경 사항 추가

```bash
git add .
```

### Commit

```bash
git commit -m "메시지"
```

Staging Area에 있는 변경 사항을 하나의 버전으로 저장한다.

### Commit 기록 확인

```bash
git log
```

# 8. 자주 사용하는 명령어

### Staging Area의 변경 사항 확인

```bash
git diff --staged
```

Commit 전에 어떤 내용이 저장될지 확인할 수 있다.

### Commit 기록 한 줄로 보기

```bash
git log --oneline
```

### Branch를 포함한 전체 기록 보기

```bash
git log --graph --decorate --all
```

# 💡 오늘 이해한 내용

오늘 가장 중요하게 이해한 것은 Git의 작업 흐름이다.

파일을 수정했다고 바로 버전이 저장되는 것이 아니라,

```
Working Directory
        ↓
Staging Area
        ↓
Repository
```

의 과정을 거쳐야 하나의 버전(Commit)으로 기록된다.

또한 Commit은 단순히 파일을 저장하는 것이 아니라 프로젝트의 특정 시점을 저장하는 **Save Point**라는 점이 인상적이었다.

또한 Git과 GitHub는 같은 개념이 아니라는 점도 이해했다.

Git은 내 컴퓨터에서 버전을 관리하는 프로그램이고,

GitHub는 Git 저장소를 온라인에서 관리하고 공유하는 서비스이다.
