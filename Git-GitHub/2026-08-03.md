# 1. 개발 환경 설치

Git을 사용하기 위해 다음 프로그램들을 설치하였다.

- Git
- GitHub
- Visual Studio Code
- Notion
- Slack
- Google 계정

Git 사용자 정보를 등록하는 명령어

```bash
git config --global user.name "사용자명"
git config --global user.email "이메일"
```

VSCode를 기본 에디터로 설정

```bash
git config --global core.editor "code --wait"
```

# 3. Git Config

Git 설정은 적용 범위에 따라 세 가지로 나뉜다.

| 옵션 | 적용 범위 |
|------|-----------|
| --local | 현재 저장소 |
| --global | 현재 사용자 |
| --system | 컴퓨터의 모든 사용자 |

적용 우선순위

```
Local > Global > System
```

# 4. SSH Key 생성

GitHub와 안전하게 통신하기 위해 SSH Key를 생성한다.

생성

```bash
ssh-keygen -t ed25519 -C "이메일"
```

공개키 확인

Windows

```bash
type ~/.ssh/id_ed25519.pub
```

Mac

```bash
cat ~/.ssh/id_ed25519.pub
```

확인한 공개키를 GitHub의

Settings → SSH and GPG Keys → New SSH Key

에 등록한다.

# 5. Git이란?

Git은 **분산 버전 관리 시스템(Version Control System)** 이다.

예전 버전 관리 프로그램은 변경된 부분만 계산하여 저장했지만,

Git은 프로젝트 전체 상태를 하나의 **Snapshot(스냅샷)** 으로 저장한다.

나는 Git을 게임의 **Save Point**와 비슷하다고 이해했다.

Commit을 할 때마다 하나의 저장 지점이 생성되고,
필요하면 언제든지 이전 상태로 돌아갈 수 있다.

---

# 6. Git의 작업 흐름

```
Working Directory
        ↓
Staging Area
        ↓
Repository
```

### 저장소 생성

```bash
git init
```

### Staging Area에 올리기

```bash
git add 파일명
```

모든 변경사항 올리기

```bash
git add .
```

### Commit

```bash
git commit -m "메시지"
```

### Commit 기록 확인

```bash
git log
```

---

# 7. 이전 버전으로 이동

특정 Commit으로 이동

```bash
git checkout <commit id>
```

직전 위치로 이동

```bash
git checkout -
```

---

# 8. 자주 사용하는 명령어

Staging Area의 변경사항 확인

```bash
git diff --staged
```

Commit 기록 한 줄로 보기

```bash
git log --oneline
```

Branch까지 함께 보기

```bash
git log --graph --decorate --all
```

# 💡 오늘 이해한 내용

오늘 가장 중요하게 이해한 것은 Git의 작업 흐름이다.

파일을 수정했다고 바로 버전이 저장되는 것이 아니라,

```
Working Directory
→ Staging Area
→ Repository
```

의 과정을 거쳐야 하나의 버전(Commit)으로 기록된다.

또한 Commit은 단순히 파일을 저장하는 것이 아니라,
프로젝트의 특정 시점을 저장하는 **Save Point**라는 점이 인상적이었다.
