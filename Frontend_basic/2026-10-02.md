## 🧭 오늘의 전체 흐름

```text
JavaScript
동적 타입
   ↓
TypeScript

   ↓
```

오늘 배운 문법의 흐름은:

```text

        ↓
특수 타입

        ↓

        ↓

매개변수 / 반환값 / optional / rest
        ↓
함수 자체의 타입
함수 타입 표현식 / 호출 시그니처
        ↓
객체의 타입
type / interface
        ↓
더 유연한 객체 구조
index signature / extends / declaration merging
```

## 😊 SUMMARY

오늘부터 JavaScript를 기반으로 **정적 타입 시스템을 추가한 TypeScript**를 학습했다. TypeScript 코드는 브라우저에서 그대로 실행하는 것이 아니라 `tsc`를 통해 JavaScript로 변환한 뒤 실행된다.

기본 타입에서 시작하여 `any`, `unknown`, `never`, **타입 추론과 타입 단언**을 살펴보고, 함수의 매개변수와 반환값에 타입을 지정하는 방법으로 확장했다. 이후 `type`과 `interface`를 이용해 객체의 구조를 정의하고, `readonly`, 선택적 속성, Index Signature, Interface 확장까지 학습했다.

**Keywords:** `Static Type`, `TypeScript`, `tsc`, `any`, `unknown`, `never`, `Type Inference`, `Type Assertion`, `Optional Parameter`, `Rest Parameter`, `Function Type`, `type`, `interface`, `readonly`, `Index Signature`, `extends`

## 📚 LECTURE NOTE

### 1. TypeScript란?

JavaScript는 기본적으로 **동적 타입(Dynamic Type)** 언어이고, TypeScript는 JavaScript에 **정적 타입(Static Type)**을 추가한다.

Java, C# 등 일반적인 정적 타입 언어처럼 코드 실행 전에 타입을 검사하여 오류를 미리 발견할 수 있도록 한다.

```typescript
let age: number = 20;

age = "hello"; // 컴파일 오류
```

TypeScript는 Microsoft에서 개발한 언어이며 **JavaScript의 Superset(상위 집합)**이다.

```text
JavaScript 문법
      ⊂
TypeScript 문법
```

수업에서 정리한 버전 흐름:

```text
ES5
 ↓
ES6+
 ↓
ESNext
```

TypeScript는 특정 ECMAScript 버전 다음 단계라기보다는 **JavaScript 문법을 포함하면서 타입 시스템 등을 추가한 Superset**으로 이해한다.

---

### 2. TypeScript는 어떻게 실행될까? ⭐

```text
TypeScript (.ts)
      ↓
tsc
TypeScript Compiler
      ↓
JavaScript (.js)
      ↓
JavaScript Runtime에서 실행
```

![tsc 설치 후 실행](image-15.png)

`tsc`를 설치하고 TypeScript 파일을 Compile하면 JavaScript 파일이 생성된다.

> ⭐ **실제로 실행되는 것은 변환된 JavaScript 코드이다.**

## 2장 1강 - 원시 타입과 배열 · 튜플

### 3. 기본 타입

TypeScript에서는 값이 어떤 타입인지 명시할 수 있다.

```typescript
let age: number = 20;
let name: string = "Kim";
let isDone: boolean = true;

let numbers: number[] = [1, 2, 3];
```

Tuple은 **위치별 타입과 길이를 지정할 수 있는 배열 형태**이다.

```typescript
let user: [number, string] = [1, "Kim"];
```

---

### 4. `any`와 `unknown` ⭐

타입을 명확히 알기 어려운 상황에서 사용할 수 있다.

#### `any`

```typescript
let value: any;
```

- 모든 타입의 값 할당 가능
- 타입 검사 없이 Property / Method 접근 가능
- TypeScript의 타입 검사를 사실상 우회
- Runtime 오류 가능성 ↑
- **가급적 사용 지양**

#### `unknown`

```typescript
let value: unknown;
```

모든 타입의 값을 받을 수 있다는 점은 `any`와 비슷하지만, 사용하기 전에 **Type Narrowing(타입 좁히기)**이 필요하다.

```typescript
if (typeof value === "string") {
    console.log(value.toUpperCase());
}
```

| 비교 | `any` | `unknown` |
|---|---|---|
| 모든 값 할당 | O | O |
| 바로 사용 | O | X |
| 타입 확인 필요 | X | O |
| 타입 안전성 | 낮음 | 높음 |

> ⭐ **정체를 모르는 값 → 일단 `unknown` → 확인 후 사용**

JavaScript Legacy Code를 TypeScript로 옮기는 초기 과정 등에서는 `any`가 임시로 사용될 수 있지만, 가능한 경우 구체적인 타입으로 변경한다.

---

### 5. `never`

`never`는 **정상적으로 값을 반환하는 지점에 도달하지 않는 경우**를 나타내는 타입이다.

```typescript
function throwError(message: string): never {
    throw new Error(message);
}
```

예외를 항상 던지는 함수처럼 정상적인 반환이 없는 경우에 사용할 수 있다.

---

### 6. 타입 추론 (Type Inference)

TypeScript가 코드의 초기값 등을 보고 타입을 자동으로 판단한다.

```typescript
let age = 20;
```

TypeScript가 `age`를 `number`로 추론한다.

```typescript
age = "hello"; // 오류
```

즉 모든 변수에 타입을 직접 적어야 하는 것은 아니다.

---

### 7. 타입 단언 (Type Assertion)

개발자가 TypeScript에게 **"이 값은 이 타입으로 간주해"**라고 알려주는 방법이다.

```typescript
value as Type
```

예:

```typescript
type Todo = {
    userId: number;
    id: number;
    title: string;
    completed: boolean;
};

const res = await fetch(
    "https://jsonplaceholder.typicode.com/todos/1"
);

const json = await res.json();

console.log((json as Todo).title);
```

> ⚠️ 타입 단언은 실제 Runtime 데이터를 검사하거나 변환하는 기능은 아니다. 개발자가 해당 타입이라고 TypeScript에게 알려주는 것이다.

## 3장 1강 - 매개변수와 반환 타입 명세

### 8. 함수의 타입

```typescript
function discountedPrice(
    amount: number,
    discountRate: number
): number {
    return amount * (1 - discountRate);
}
```

```text
amount: number
→ 매개변수 타입

discountRate: number
→ 매개변수 타입

): number
→ 반환값 타입
```

Python의 Type Hint와 형태를 비교하면:

```python
def discounted_price(
    amount: float,
    discount_rate: float
) -> float:
    return amount * (1 - discount_rate)
```

---

### 9. 선택적 매개변수 `?`

매개변수를 반드시 전달하지 않아도 되도록 만든다.

```typescript
function greet(name?: string) {
    // ...
}
```

`?`는 이후 객체의 **선택적 Property**에서도 다시 등장한다.

---

### 10. 가변 인자 (Rest Parameter)

```typescript
function sum(...numbers: number[]) {
    // ...
}
```

`...`으로 여러 인수를 받아 하나의 **Array**로 다룬다.

> ⭐ JavaScript에서 배운 Rest Parameter가 TypeScript에서는 **배열 내부 값의 타입까지 명시**된다고 연결해서 이해하기.

## 3장 2강 - 함수 타입

### 11. 함수 타입 표현식

함수도 하나의 값이므로 **함수 자체의 타입**을 정의할 수 있다.

```typescript
(a: number, b: number) => number
```

의미:

```text
number를 받음
     +
number를 받음
     ↓
number를 반환하는 함수
```

함수 Type Alias:

```typescript
type Calculator = (
    a: number,
    b: number
) => number;
```

---

### 12. 호출 시그니처 (Call Signature)

객체 형태의 Type 안에서 **호출 가능한 함수의 규격**을 표현할 수 있다.

```typescript
type Calculator = {
    (a: number, b: number): number;
};
```

오늘 함수 파트의 핵심:

```text
함수
 ↓
입력 타입
+
출력 타입
 ↓
함수 자체도 하나의 타입으로 표현 가능
```

- **함수 타입 별칭** → 함수의 입력·출력 규격에 이름을 붙임
- **인라인 함수 타입** → 필요한 위치에 함수 타입을 직접 작성
- **호출 시그니처** → 객체 형태로 함수의 호출 규격 표현
- **화살표 함수** → 함수를 간결하게 표현
- 다른 함수에 전달된 함수 → Callback으로 사용 가능
- `map()` → Callback 반환값으로 새로운 배열 생성

## 4장 1강 - 객체 타입

### 13. `type`으로 객체 정의

```typescript
type User = {
    id: number;
    name: string;
};
```

객체가 어떤 Property와 타입을 가져야 하는지 **구조를 정의**한다.

---

### 14. `interface`로 객체 정의 ⭐

```typescript
interface Account {
    readonly accountId: string;
    owner: string;
    balance: number;
}
```

`interface` 역시 객체가 가져야 할 **구조 또는 명세**를 정의한다.

```typescript
const account: Account = {
    accountId: "110-123-456789",
    owner: "Kim",
    balance: 50000
};
```

> 여기서 TypeScript의 `interface` 문법과 **API(Application Programming Interface)**의 Interface는 같은 문법을 의미하는 것은 아니지만, 둘 다 **경계에서 지켜야 할 규격·명세**라는 의미로 연결해서 이해할 수 있다.

---

### 15. `readonly`

생성 후 변경하면 안 되는 Property를 정의한다.

```typescript
interface Account {
    readonly accountId: string;
    owner: string;
}
```

```typescript
account.accountId = "220-987-654321";
// 컴파일 오류
```

> ⭐ `readonly`는 **컴파일 단계에서 변경을 막는 TypeScript의 타입 제약**이다.

---

### 16. 선택적 속성 `?`

```typescript
type User = {
    id: number;
    nickname?: string;
};
```

- `id` → 필수
- `nickname?` → 선택

오늘 `?`가 두 번 등장했다.

```text
함수
name?: string
→ 선택적 매개변수

객체
nickname?: string
→ 선택적 Property
```

## 4장 2강 - Index Signature와 Interface 확장

### 17. Index Signature ⭐

Property의 이름을 미리 모두 알 수 없을 때 **Key와 Value의 타입 규격**을 정의한다.

```typescript
interface Dictionary {
    [key: string]: string;
}
```

```text
Property 이름
→ 동적으로 들어올 수 있음

대신

Key 타입   → string
Value 타입 → string
```

#### Symbol Key

```typescript
interface Example {
    [key: symbol]: string;
}
```

`symbol`은 각각 고유한 값을 가지므로 Property Key로 사용할 수 있다.

#### Template Literal Key

```typescript
interface GetterMap {
    [key: `get_${string}`]: string;
}
```

→ Key가 `get_`으로 시작하도록 제한한다.

---

### 18. 특정 Key만 허용하기 - `Record`

```typescript
type AllowedKeys = "id" | "name";

type User = Record<AllowedKeys, string>;
```

```text
"id" | "name"
      ↑
Union Type

| → 둘 중 하나
```

> `|` = Union(합집합처럼 여러 가능 타입 중 하나)  
> `&` = Intersection(여러 타입을 동시에 만족)

---

### 19. Interface 확장

기존 Interface를 기반으로 새로운 Interface를 만들 수 있다.

```typescript
interface Person {
    name: string;
}

interface Employee extends Person {
    employeeId: number;
}
```

```text
Person
  │
  │ extends
  ↓
Employee

name
+
employeeId
```

Type을 조합할 때는 `&`도 사용할 수 있다.

```typescript
type A = {
    name: string;
};

type B = {
    age: number;
};

type C = A & B;
```

---

### 20. 선언 병합 (Declaration Merging)

`interface`는 같은 이름으로 여러 번 선언하면 TypeScript가 이를 **자동으로 병합**할 수 있다.

```typescript
interface User {
    name: string;
}

interface User {
    age: number;
}
```

결과적으로:

```typescript
interface User {
    name: string;
    age: number;
}
```

처럼 사용할 수 있다.

> ⭐ 오늘 `type`과 `interface`의 눈에 띄는 차이 중 하나: **`interface`는 선언 병합이 가능하다.**
