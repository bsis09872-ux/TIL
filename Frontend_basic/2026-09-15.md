## 😊 SUMMARY

오늘은 HTML의 **Form 요소를 이용해 사용자 입력을 서버로 전달하는 구조**를 학습하고, Semantic Tag를 이용해 웹 문서의 영역에 의미를 부여하는 방법을 정리했다.

이후 CSS의 기본 구조인 **Selector → Property → Value**를 학습하고, CSS를 HTML에 적용하는 세 가지 방식과 `tag`, `.class`, `#id` 선택자의 차이 및 우선순위를 확인했다. 마지막으로 **Descendant, Child, General Sibling, Adjacent Sibling Selector**를 이용해 HTML 요소의 관계를 기준으로 스타일을 적용하는 방법을 실습했다.

**Keywords:** `Form`, `GET`, `POST`, `Query String`, `Semantic Tag`, `CSS`, `Selector`, `Class`, `ID`, `Specificity`, `Descendant`, `Child`, `Sibling`

# 🔄 REVIEW

### Block 요소와 Inline 요소

- **Block 요소** → 기본적으로 새 줄에서 시작하며 영역을 차지
- **Inline 요소** → 콘텐츠의 흐름 안에서 필요한 만큼 영역을 차지
- 어떤 요소를 서로 포함할 수 있는지는 단순 Block / Inline 구분이 아니라 **HTML 요소별 Content Model**에 따라 결정된다.

> **핵심:** Block / Inline은 기본적인 배치 특성이고, 포함 가능 여부는 HTML 문법 규칙에 따른다.

## 1. Form 태그

`<form>`은 사용자가 입력한 데이터를 모아 **서버에 제출하는 영역**이다.

```html
<form action="/signup" method="post" target="_self">
    ...
</form>
```

### 주요 속성

| 속성 | 역할 |
|---|---|
| `action` | 데이터를 제출할 서버 URL |
| `method` | HTTP 전송 방식 |
| `target` | 응답 결과를 표시할 위치 |

### `target`

- `_self` → 현재 창
- `_blank` → 새 창 또는 탭
- `_parent` → 부모 프레임
- `_top` → 최상위 창

---

### GET

주로 **조회·검색** 요청에 사용한다.

Form의 GET 요청은 입력값이 URL의 **Query String**에 포함된다.

```url
/search?keyword=html&page=1
```

```text
?name=value&name=value
```

```html
<form action="/search" method="get">
    <input type="text" name="keyword">
    <button type="submit">검색</button>
</form>
```

---

### POST

주로 데이터를 서버로 전달하여 **등록이나 처리를 요청**할 때 사용한다.

예:

- 회원가입
- 게시글 작성
- 상품 등록

일반적인 HTML Form의 POST 요청에서는 입력값이 **Request Body**에 담긴다.

```text
GET  → URL Query String
POST → Request Body
```

> HTTP Method의 실제 동작은 서버/API 설계에 따라 달라질 수 있다.

---

### HTTP Request / Response

HTTP 메시지는 크게 **Header와 Body**로 나누어 볼 수 있다.

- **Header** → 요청/응답에 대한 부가 정보
- **Body** → 실제 전송 데이터
- 요청이나 응답에 항상 Body가 존재하는 것은 아니다.

## 2. Input 요소

`<input>`은 사용자 입력을 받는 대표적인 Form 요소이다.

```html
<input type="text" name="username">
```

### 주요 `type`

```text
text
password
email
number
color
range
date
time
datetime-local
radio
checkbox
submit
reset
button
```

### 주요 속성

| 속성 | 역할 |
|---|---|
| `type` | 입력 유형 |
| `name` | 서버에 전달될 데이터의 Key |
| `value` | 입력·선택 값 |
| `required` | 필수 입력 |
| `placeholder` | 입력 안내 |
| `readonly` | 수정 불가 / 전송 O |
| `disabled` | 비활성화 / 일반적으로 전송 X |
| `min` | 최솟값 |
| `max` | 최댓값 |
| `step` | 값의 간격 |

Form 데이터는 보통 다음과 같은 **name-value 구조**로 전달된다.

```text
name=value
```

---

### Radio / Checkbox

`radio`는 같은 `name`을 사용하여 하나의 그룹을 만든다.

```html
<input type="radio" name="gender" value="male"> 남성
<input type="radio" name="gender" value="female"> 여성
```

`checkbox`는 여러 항목을 선택할 수 있다.

```html
<input type="checkbox" name="hobby" value="coding"> 코딩
<input type="checkbox" name="hobby" value="music"> 음악
```

---

### Button

```html
<button type="submit">제출</button>
<button type="reset">초기화</button>
<button type="button">일반 버튼</button>
```

| Type | 역할 |
|---|---|
| `submit` | Form 제출 |
| `reset` | Form 입력값 초기화 |
| `button` | 별도의 기본 동작이 없는 버튼 |

> Form 내부의 `<button>`은 기본적으로 `submit`으로 동작할 수 있으므로 일반 버튼에는 `type="button"`을 명시한다.

## 3. Label · Textarea · Select

### Label

`<label>`은 입력 요소와 설명을 연결한다.

```html
<label for="userName">이름</label>
<input type="text" id="userName" name="userName">
```

```text
label의 for
      ↕
input의 id
```

또는 입력 요소 자체를 감쌀 수 있다.

```html
<label>
    이름
    <input type="text" name="userName">
</label>
```

Label을 클릭해도 입력 요소에 Focus가 이동하므로 **사용성과 접근성 향상**에 도움이 된다.

---

### Textarea

여러 줄의 텍스트 입력에 사용한다.

```html
<textarea name="message" rows="5" cols="30"></textarea>
```

`<input>`과 달리 여는 태그와 닫는 태그가 존재한다.

---

### Select

여러 항목 중 값을 선택한다.

```html
<select name="language">
    <option value="python">Python</option>
    <option value="javascript" selected>JavaScript</option>
    <option value="java">Java</option>
</select>
```

- `<option>` → 선택 항목
- `selected` → 기본 선택
- `multiple` → 다중 선택
- `size` → 한 번에 보이는 항목 수

## 4. Semantic Tag

**Semantic Tag**는 태그 이름 자체에 콘텐츠의 **의미와 역할**이 포함된 태그이다.

```html
<header>
<nav>
<main>
<section>
<article>
<aside>
<footer>
```

반대로 `<div>`, `<span>`은 대표적인 **Non-semantic Tag**이다.

### 필요한 이유

1. **SEO (Search Engine Optimization)**
2. **Web Accessibility**
3. **코드 구조와 가독성 향상**

### 주요 Semantic Tag

| 태그 | 역할 |
|---|---|
| `<header>` | 페이지·영역의 머리말 |
| `<nav>` | 주요 Navigation |
| `<main>` | 문서의 핵심 본문 |
| `<section>` | 주제별 콘텐츠 그룹 |
| `<article>` | 독립적으로 의미가 성립하는 콘텐츠 |
| `<aside>` | 본문과 간접적으로 관련된 보조 콘텐츠 |
| `<footer>` | 페이지·영역의 하단 정보 |

> `<aside>`는 오른쪽이나 왼쪽이라는 **위치**를 의미하지 않는다. 위치는 CSS가 결정하고, `<aside>`는 **보조 콘텐츠라는 의미**를 표현한다.

```html
<body>
    <header>...</header>

    <nav>...</nav>

    <main>
        <section>
            <article>...</article>
        </section>

        <aside>...</aside>
    </main>

    <footer>...</footer>
</body>
```

HTML 문서를 작성할 때는 먼저 **Heading과 Semantic Tag로 문서 구조를 만들고**, 이후 CSS로 디자인과 배치를 적용한다.

```text
HTML       → 구조와 의미
CSS        → 디자인과 배치
JavaScript → 동작과 상호작용
```

# 5. CSS 기본 문법

**CSS (Cascading Style Sheets)**는 HTML 요소의 시각적 스타일을 정의한다.

기본 구조:

```css
선택자 {
    속성: 값;
    속성: 값;
}
```

예:

```css
h1 {
    color: blue;
    font-size: 20px;
}
```

| 구성 | 의미 |
|---|---|
| Selector | 어떤 요소에 적용할지 지정 |
| Property | 어떤 스타일을 바꿀지 지정 |
| Value | 어떤 값으로 바꿀지 지정 |

> CSS 선언에서는 `속성: 값;`처럼 **콜론 `:`과 세미콜론 `;`**을 사용한다.

---

### CSS 주석

```css
/* 설명 */

/*
여러 줄
설명
*/
```

브라우저가 해당 부분을 해석하지 않으므로 설명을 적거나 스타일을 임시로 비활성화할 때 사용할 수 있다.

---

### Cascading과 Inheritance

**Cascading**

여러 CSS 규칙이 같은 요소에 적용될 때 **우선순위와 선언 순서 등의 규칙에 따라 최종 스타일을 결정**한다.

**Inheritance**

일부 CSS 속성은 부모 요소의 값을 자식 요소가 상속받는다.

```css
body {
    font-family: Arial;
}
```

`font-family`처럼 상속되는 속성은 하위 요소에도 적용될 수 있다.

> 모든 CSS 속성이 자동으로 상속되는 것은 아니다.

## 6. CSS 적용 방법

CSS를 HTML에 적용하는 대표적인 방법은 세 가지다.

### ① Inline Style

HTML 태그의 `style` 속성에 직접 작성한다.

```html
<li style="color: orange; background: black;">감</li>
```

### ② Internal Style Sheet

현재 HTML 문서 안에서 `<style>` 태그를 이용한다.

```html
<style>
    li {
        background: gray;
    }
</style>
```

### ③ External Style Sheet ⭐

별도의 `.css` 파일을 만들고 HTML과 연결한다.

```html
<link rel="stylesheet" href="css/style.css">
```

```text
HTML
  ↓ link
CSS 파일
```

유지보수와 재사용 측면에서 **외부 스타일 시트**를 주로 사용한다.

## 7. 기본 선택자

### 전체 선택자

```css
* {
    margin: 0;
}
```

모든 요소를 선택한다.

### 태그 선택자

```css
li {
    background: gray;
}
```

동일한 태그를 모두 선택한다.

### Class 선택자

```css
.kia {
    background: orange;
}
```

```html
<li class="kia">모하비</li>
```

같은 Class를 여러 요소에 사용할 수 있다.

하나의 요소에 여러 Class도 지정할 수 있다.

```html
<li class="kia kia2 discontinued">모하비</li>
```

---

### ID 선택자

```css
#sorento {
    background: red;
}
```

```html
<li id="sorento">소렌토</li>
```

`id`는 한 문서 안에서 **고유하게 사용하도록 설계된 식별자**이다.

> `아이디어 선택자`가 아니라 **아이디 선택자(ID Selector)**이다.

---

## 8. CSS 우선순위

같은 요소에 여러 스타일 규칙이 충돌하면 **Specificity(명시도)** 등을 기준으로 적용 여부가 결정된다.

수업에서 확인한 기본적인 우선순위는:

```text
Tag Selector
    <
Class Selector
    <
ID Selector
    <
Inline Style
```

예:

```html
<li
    class="kia"
    id="sorento"
    style="background: pink;"
>
    소렌토
</li>
```

```css
li {
    background: gray;
}

.kia {
    background: orange;
}

#sorento {
    background: red;
}
```

이 경우 같은 `background` 속성이 충돌하면 Inline Style의 우선순위가 가장 높아 `pink`가 적용된다.

> 단순히 **“범위가 좁을수록 항상 강하다”**라고만 외우기보다는 CSS의 **Specificity와 Cascade 규칙**으로 이해한다.

### `!important`

```css
.kia {
    background: orange !important;
}
```

일반 우선순위를 강하게 덮어쓸 수 있다.

> 유지보수를 어렵게 만들 수 있으므로 **남용하지 않는다.**

## 9. 복합 선택자

HTML 요소 사이의 **관계**를 기준으로 대상을 선택한다.

### 9-1. Descendant Selector - 하위 선택자

```css
ol span {
    background: orange;
}
```

`ol` 안에 포함된 모든 후손 `span`을 선택한다.

```text
ol
└─ ...
   └─ span  ← 선택
```

공백으로 표현한다.

```css
조상 자손
```

---

### 9-2. Child Selector - 자식 선택자

```css
div > span {
    background: skyblue;
}
```

`div`의 **바로 아래 자식**인 `span`만 선택한다.

```text
div
└─ span  ← 선택
```

```css
부모 > 자식
```

> Descendant는 모든 하위 단계, Child는 **한 단계 바로 아래**만 선택한다.

---

### 9-3. General Sibling Selector - 일반 형제 선택자

```css
.menu5 ~ li {
    background: gray;
}
```

`.menu5`와 같은 부모를 가지면서 **뒤에 등장하는 형제 `li` 요소들**을 선택한다.

```text
메뉴5
 ├─ 메뉴6 ← 선택
 ├─ 메뉴7 ← 선택
 ├─ 메뉴8 ← 선택
 └─ ...
```

```css
기준요소 ~ 뒤쪽 형제요소
```

---

### 9-4. Adjacent Sibling Selector - 인접 형제 선택자

```css
.menu5 + li {
    background: red;
}
```

`.menu5` 바로 다음에 위치한 **첫 번째 인접 형제 `li` 하나**를 선택한다.

```text
메뉴5
 ↓
메뉴6 ← 선택
메뉴7
메뉴8
```

```css
기준요소 + 바로 다음 형제
```

### 복합 선택자 비교

| 선택자 | 문법 | 의미 |
|---|---|---|
| Descendant | `A B` | A 내부의 모든 후손 B |
| Child | `A > B` | A의 바로 아래 자식 B |
| General Sibling | `A ~ B` | A 뒤에 오는 같은 부모의 모든 B |
| Adjacent Sibling | `A + B` | A 바로 다음의 B 하나 |
