# 🔄 REVIEW — CSS

## 1. 명시도(Specificity)

같은 요소에 여러 CSS 규칙이 충돌할 경우 어떤 선언이 우선할지 결정하는 기준 중 하나이다.

```text
Inline > ID > Class·Pseudo-class > Tag·Pseudo-element > Universal
```

> 실제 CSS 적용 순서는 명시도뿐 아니라 `!important`, Cascade Layer, 선언 위치 등 Cascade 규칙의 영향도 받는다.

---

## 2. `box-sizing`

- `content-box` → `width`, `height`가 Content 영역 기준
- `border-box` → `width`, `height`에 Padding과 Border까지 포함

---

## 3. Block vs Inline

- **Block** → 기본적으로 한 줄을 차지하며 다음 요소는 새로운 줄에서 시작
- **Inline** → 콘텐츠 크기를 중심으로 같은 줄에 배치

---

## 4. Position

- `relative` → 자신의 원래 위치를 기준으로 배치
- `absolute` → 가장 가까운 Positioned 조상을 기준으로 배치

> `absolute`는 단순히 "절대 위치", `relative`는 "상대 위치"라고 외우기보다 **무엇을 위치의 기준으로 삼는지** 이해하는 것이 중요하다.

# 1. JavaScript와 실행 환경

## 1-1. JavaScript

JavaScript는 코드를 실행하면서 해석하는 **인터프리터 방식의 언어**이다.

JavaScript 코드를 실행하려면 **JavaScript Engine**이 필요하다.

대표적으로 Chrome에는 **V8 Engine**이 사용된다.

```text
JavaScript Code
      ↓
JavaScript Engine
      ↓
실행
```

---

## 1-2. Node.js

**Node.js**는 JavaScript를 **웹브라우저 밖에서도 실행할 수 있도록 해주는 JavaScript Runtime Environment**이다.

Node.js 역시 **V8 Engine**을 사용한다.

### Node.js 환경에서 자주 사용하는 세 가지 명령어

| 명령어 | 의미 | 역할 |
|---|---|---|
| `node` | Node.js | JavaScript 파일이나 코드를 실행 |
| `npm` | Node Package Manager | Package 설치 및 Node.js 프로젝트 관리 |
| `npx` | Node Package Executor | 설치된 또는 가져온 Package의 명령어 실행 |

> Python 학습 경험과 연결하면 `npm`을 이용한 프로젝트·Package 관리는 `uv`를 이용한 환경 및 Package 관리와 일부 비슷한 역할이 있지만, 서로 동일한 도구는 아니다.

# 3. 변수와 Hoisting

JavaScript의 변수와 함수를 이해할 때 중요한 특징 중 하나가 **Hoisting(호이스팅)**이다.

![alt text](image-7.png)

정의 후 `window`를 불러오면 → `add` 함수가 보인다.

![alt text](image-8.png)

`window`를 먼저 불러온 뒤 함수를 정의했는데도 → `add` 함수가 보인다?!

![alt text](image-9.png)

함수 정의 코드보다 앞에서 호출했는데도 → 계산이 된다!

JavaScript에서는 실행 전에 선언을 처리하는 과정이 있기 때문에 **함수 선언문은 코드상 선언 위치보다 앞에서도 호출할 수 있다.**

```text
실행 전 선언 처리
        ↓
함수 선언 정보가 준비됨
        ↓
실행 단계에서 함수 호출 가능
```

> 💡 중요한 건 **"호이스팅 = 코드를 실제로 위로 이동시킨다"**가 아니라, **실행 전에 선언을 먼저 처리하기 때문에 위로 끌어올려진 것처럼 보이는 현상**이라는 점이다.

브라우저의 전통적인 일반 `<script>` 환경에서 최상위 함수 선언이나 `var` 선언은 전역 객체인 `window`와 연결되는 경우가 있다.

> 단, 모든 JavaScript 실행 환경에서 최상위 선언이 무조건 `window`의 속성이 되는 것은 아니다. Node.js, ES Module 등 실행 환경에 따라 다르다.

또한 JavaScript의 함수와 값 역시 변수에 할당하거나 다른 곳에 전달할 수 있는 **값(Value)**으로 다룰 수 있다.

# 4. `var` / `let` / `const`

## 4-1. `var`

기존 JavaScript에서 사용하던 변수 선언 방식이다.

### 특징

1. 선언이 Hoisting의 영향을 받음
2. **Function Scope**를 가짐
3. 같은 Scope에서 중복 선언 가능
4. 선언 없이 값을 대입하는 코드는 환경에 따라 의도하지 않은 전역 변수를 만들 수 있음

![alt text](image-10.png)

→ `var`는 같은 Scope에서 중복 선언이 가능하기 때문에 코드가 길어질수록 기존 변수를 의도치 않게 다시 선언하거나 변경할 위험이 있다.

> `var` 자체가 값을 계속 바꾸는 것이 아니라, **중복 선언을 허용하고 Function Scope를 사용한다는 특성** 때문에 변수 관리가 어려워질 수 있다.

---

## 4-2. `<내 말로 필기하기>`

초기 JavaScript는 웹 환경에서 유연하게 동작할 수 있도록 비교적 관대한 문법적 특성을 많이 가지고 있다.

하지만 `var`의 **Function Scope, 중복 선언 허용, Hoisting 특성** 등은 코드가 복잡해질수록 변수의 위치와 상태를 파악하기 어렵게 만들 수 있다.

특히 의도하지 않은 전역 변수 사용은 **전역 Namespace 오염(Global Namespace Pollution)**으로 이어질 수 있다.

이를 보완하기 위해 **ES6(ECMAScript 2015)**에서 `let`과 `const`가 도입되었다.

> ⚠️ Hoisting 자체가 "중복 선언을 허용하기 위해 만들어진 특성"인 것은 아니다.  
> `var`의 여러 특성이 함께 사용될 때 예상하기 어려운 동작이 발생할 수 있다고 이해한다.

---

## 4-3. `let`과 `const`

ES6에서 등장한 변수 선언 방식이다.

### 공통 특징

1. **Block Scope**
2. 같은 Scope에서 중복 선언 불가
3. 선언 전에 접근할 수 없는 **TDZ(Temporal Dead Zone)** 존재

![alt text](image-12.png)

→ `let`, `const`는 `{ }`를 기준으로 만들어지는 **Block Scope**를 따른다.

> `{ }`가 Block을 만드는 문맥에서는 중괄호 내부를 하나의 지역 Scope라고 이해하면 편하다.

### 차이

- `let` → 값 **재할당 가능**
- `const` → 값 **재할당 불가능**

![alt text](image-11.png)

→ `let`은 선언한 변수에 새로운 값을 다시 할당할 수 있지만, `const`는 선언 후 다른 값을 다시 할당할 수 없다.

### 변수 선언 기준 ⭐

```text
기본 → const

값의 재할당이 필요함
→ let

var
→ 주로 Legacy Code에서 확인
```

> **결론:** JavaScript에서는 우선 `const`로 선언하고, **재할당이 필요한 변수만 `let`을 사용하는 방식**이 일반적이다.

# 6. 주요 Data Type

JavaScript에서는 `typeof` 연산자를 이용해 값의 Type을 확인할 수 있다.

> Python의 `type()`과 비슷한 목적으로 사용할 수 있지만 동작 방식과 반환 결과는 다르다.

| Type | 의미 | 예 |
|---|---|---|
| `Number` | 숫자 | `10`, `3.14` |
| `String` | 문자열 | `"hello"`, `'hello'` |
| `Boolean` | 논리값 | `true`, `false` |
| `null` | 값이 없음을 의도적으로 표현 | `null` |
| `undefined` | 값이 정의되지 않은 상태 | `undefined` |

### `Number`

일반적인 JavaScript `Number`는 Python처럼 정수형과 실수형을 별도의 Type으로 나누지 않는다.

```javascript
typeof 10
typeof 3.14
```

→ 둘 다 `"number"`

### `null` vs `undefined`

- `null` → **값이 없음을 의도적으로 나타내는 값**
- `undefined` → 변수를 선언하고 값을 할당하지 않은 경우 등 **값이 정의되지 않은 상태**

> ⚠️ `typeof null`은 `"object"`를 반환한다. JavaScript 초기 설계에서 비롯된 오래된 동작이며 하위 호환성을 위해 현재까지 유지되고 있다.

# 7. 연산자와 Type Coercion

JavaScript의 `+` 연산자는 값의 Type에 따라 다르게 동작할 수 있다.

```text
10 + 10
→ 20

"Hello" + " JavaScript"
→ "Hello JavaScript"
```

문자열과 다른 Type을 `+`로 연산하면 **문자열 연결을 위해 Type 변환(Type Coercion)**이 발생할 수 있다.

```javascript
10 + "10"
```

→ `"1010"`

> 따라서 **"연산에 문자가 있으면 모든 연산 결과가 문자열이 된다"**고 일반화하기보다는, 특히 `+` 연산자가 문자열과 함께 사용될 때 문자열 연결과 암시적 Type 변환이 발생할 수 있다고 이해하는 것이 정확하다.

# 8. Template Literal

백틱(`` ` ``)을 사용하면 문자열 안에 변수나 표현식을 쉽게 삽입할 수 있다.

![alt text](image-13.png)

→ `${...}` 안에 변수나 표현식을 넣어 문자열을 동적으로 구성할 수 있다.


Template Literal은 문자열 연결을 위해 `+`를 반복해서 사용하는 것보다 읽기 쉽게 작성할 수 있다.

# 9. Truthy & Falsy

JavaScript의 조건문에서는 Boolean 값이 아니더라도 값에 따라 **참 또는 거짓처럼 평가**될 수 있다.

## Falsy

조건식에서 `false`로 평가되는 대표적인 값:

- `false`
- `0`
- `""` → 빈 문자열
- `null`
- `undefined`
- `NaN`

> 수업에서 우선 위 **6가지 대표 Falsy 값**을 기준으로 기억한다.

이외의 많은 값은 조건식에서 **Truthy**로 평가된다.

```javascript
if ("hello") {
    console.log("실행");
}
```

`"hello"`는 Truthy이므로 조건문이 실행된다.

> ⭐ **Falsy = 값 자체가 반드시 Boolean `false`라는 뜻이 아니라, Boolean이 필요한 문맥에서 `false`처럼 평가되는 값**
