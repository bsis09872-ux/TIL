## REVIEW

### 1. TypeScript와 Transpile

- TypeScript는 JavaScript에 **정적 타입 시스템**을 추가한 언어이다.
- 작성한 TypeScript 코드는 JavaScript로 변환되어 실행된다.
- **트랜스파일(Transpile)**: 하나의 프로그래밍 언어로 작성된 코드를 비슷한 추상화 수준의 다른 프로그래밍 언어 코드로 변환하는 과정

```text
TypeScript → Transpile → JavaScript
```

---

### 2. `any`와 `unknown`

JavaScript에서는 함수의 매개변수에 다양한 타입의 값이 들어올 수 있다.

TypeScript에서 타입을 정확히 모르는 경우 `any`, `unknown` 등을 사용할 수 있다.

- `any`: 타입 검사를 사실상 포기한다.
- `unknown`: 바로 사용할 수 없으며 **타입 좁히기(Type Narrowing)** 이후 안전하게 사용할 수 있다.
- 따라서 타입 안전성을 위해 가능하면 `any`보다 `unknown`을 사용하는 것이 좋다.

```ts
let value: unknown = "hello";

if (typeof value === "string") {
    value.toUpperCase();
}
```

> `unknown`은 트랜스파일할 때 타입을 유추하는 것이 아니라, **TypeScript의 타입 검사 과정에서 타입을 좁혀 안전하게 사용할 수 있게 하는 것**이다.

---

### 3. 선택적 매개변수 `?`

매개변수 뒤에 `?`가 붙으면 **선택적 매개변수**가 된다.

```ts
function greet(name?: string) {
    console.log(name);
}
```

값을 전달하지 않아도 되며, 전달하지 않은 경우 `undefined`가 될 수 있다.

# LECTURE NOTE

# 5장 1강 — Union / Intersection / Literal Type

## 1. Union `|`

유니온 타입은 여러 타입 중 **하나에 해당하는 값**을 허용한다.

```ts
type ID = string | number;
```

즉:

```text
string OR number
```

이다.

> **Union은 여러 타입을 하나로 합쳐 모든 조건을 만족시키는 것이 아니라, 여러 타입 중 하나를 선택적으로 허용하는 방식이다.**

---

## 2. Intersection `&`

인터섹션 타입은 여러 타입의 속성을 **모두 결합**한다.

```ts
type A = {
    name: string;
};

type B = {
    age: number;
};

type Person = A & B;
```

`Person` 객체는 두 타입의 속성을 모두 가져야 한다.

```ts
const person: Person = {
    name: "Seoin",
    age: 25
};
```

정리하면:

```text
Union        A | B → A 또는 B
Intersection A & B → A와 B의 조건 모두
```

---

## 3. Literal Type

리터럴 타입은 `string`, `number`처럼 넓은 범위가 아니라 **특정 값 자체를 타입으로 제한**한다.

```ts
type OrderStatus =
    "PENDING"
    | "SHIPPED"
    | "DELIVERED";
```

Union / Intersection 등과 함께 실제 데이터의 상태를 구체적으로 모델링할 수 있다.

```ts
interface BaseOrder {
    orderId: string;
    totalAmount: number;
}

type DetailedOrder = BaseOrder & {
    status: OrderStatus;
};
```

---

## 4. 서로소 판별 유니온 (Discriminated Union)

여러 타입에 `status`, `type`, `kind`와 같은 **공통 리터럴 속성(판별자)**을 두고 이를 기준으로 타입을 구분하는 패턴이다.

```ts
type Success = {
    status: "success";
    data: string;
};

type Failure = {
    status: "failure";
    message: string;
};

type Result = Success | Failure;
```

이제 `status`를 확인하면 TypeScript가 타입을 좁힐 수 있다.

```ts
function printResult(result: Result) {
    switch (result.status) {
        case "success":
            console.log(result.data);
            break;

        case "failure":
            console.log(result.message);
            break;
    }
}
```

```text
Result
  ↓ status 확인
  ├─ "success" → Success
  └─ "failure" → Failure
```

> 핵심은 **공통된 리터럴 속성을 판별자로 사용한다는 것**이다. 클래스나 `any`는 필수 요소가 아니다.

# 5장 2강 — Duck Typing / Type Narrowing

## 1. Duck Typing

**덕 타이핑(Duck Typing)**은 객체의 이름보다 **실제로 어떤 구조와 속성을 가지고 있는지**를 기준으로 타입 호환성을 판단하는 방식이다.

---

## 2. Type Narrowing

넓은 타입을 조건을 이용해 **더 구체적인 타입으로 좁히는 것**이다.

대표적인 방법:

```ts
typeof value === "string"

value instanceof SomeClass

"property" in value

Array.isArray(value)
```

### `typeof`

`typeof`는 런타임에서 피연산자의 타입 정보를 확인할 수 있다.

이를 조건문에 사용하면 TypeScript가 해당 블록에서 타입을 좁힌다.

```ts
function print(value: string | number) {
    if (typeof value === "string") {
        value.toUpperCase();
    }
}
```

### `instanceof`

`instanceof`는 **특정 클래스의 인스턴스인지 확인**할 때 사용할 수 있다.

```ts
if (value instanceof User) {
    // value를 User로 좁혀 사용
}
```

따라서:

```text
typeof
→ string, number 등 런타임 타입 확인

instanceof
→ 특정 클래스의 인스턴스인지 확인
```

# 6장 1강 — Generic

## 1. `any`와 Generic

제네릭(Generic)은 타입을 미리 하나로 고정하지 않고 **사용하는 시점에 타입을 결정하면서 타입 간의 관계를 유지**할 수 있게 한다.

오늘 질문한 코드:

```ts
function getFirstElement<T, U>(
    arr: T[],
    info: U
): T | undefined {

    if (arr.length === 0) {
        return undefined;
    }

    console.log("Info:", info);

    return arr[0];
}
```

여기서:

```text
T → 배열 원소의 타입
U → info의 타입
반환 → T | undefined
```

사용:

```ts
const numbers = [10, 20, 30];

const firstNumber =
    getFirstElement<number, string>(numbers, "출력");
```

이 경우:

```text
T = number
U = string
```

---

## 2. 오늘 발생한 Generic 오류

다음 코드는 문제가 발생했다.

```ts
getFirstElement<string>(numbers, "출력");
```

`T = string`으로 지정하면 함수는 첫 번째 매개변수로 `string[]`을 기대한다.

하지만:

```ts
const numbers = [10, 20, 30];
```

는 `number[]`이다.

따라서 타입이 맞지 않는다.

타입 추론을 이용하면 더 간단하게 작성할 수 있다.

```ts
const firstNumber =
    getFirstElement(numbers, "출력");
```

TypeScript가 자동으로:

```text
T → number
U → string
```

으로 추론한다.

> **Generic은 아무 타입이나 허용하는 것이 아니라, 타입을 나중에 결정하면서 타입 간 관계를 일관되게 유지하는 기능이다.**

# 6장 2강 — `keyof`

`keyof`는 특정 객체 타입이 가진 **속성 key를 타입으로 추출**한다.

```ts
interface User {
    name: string;
    age: number;
}
```

```ts
keyof User
```

는 개념적으로:

```ts
"name" | "age"
```

이다.

이를 Generic과 함께 사용할 수 있다.

```ts
function getProperty<T, K extends keyof T>(
    obj: T,
    key: K
): T[K] {
    return obj[key];
}
```

### `K extends keyof T`

`K` 타입이 반드시 **T 객체가 실제로 가지고 있는 key들의 유니온 중 하나**여야 한다는 제약이다.

따라서 존재하지 않는 속성에 접근하는 실수를 컴파일 단계에서 막을 수 있다.

```text
T = User

keyof T
   ↓
"name" | "age"

K extends keyof T
   ↓
K는 "name" 또는 "age"만 가능
```

> **`keyof` = 객체에 존재하는 key 추출**
>
> **`K extends keyof T` = K를 그 key들로 제한**

# 7장 1강 — Class

## 1. 접근 제어자 (Access Modifier)

TypeScript 클래스에서는 멤버에 접근할 수 있는 범위를 지정할 수 있다.

| 접근 제어자 | 접근 범위 |
|---|---|
| `public` | 클래스 내·외부 모두 접근 가능, 기본값 |
| `protected` | 클래스 내부 + 상속받은 하위 클래스 |
| `private` | 해당 클래스 내부 |

```ts
class User {
    public name: string;
    protected role: string;
    private password: string;
}
```

---

## 2. Constructor와 `this`

생성자(Constructor)는 객체가 생성될 때 **초기값을 설정**한다.

```ts
class User {
    public name: string;
    private password: string;

    constructor(name: string, password: string) {
        this.name = name;
        this.password = password;
    }
}
```

`this`는 **현재 생성되는 객체 자체**를 가리킨다.

Java에서도 필드를 선언하고 생성자에서 `this.field = parameter` 형태로 초기화하는 방식을 사용한다.

---

## 3. 생성자 단축 속성 선언 (Parameter Properties)

TypeScript에서는 생성자 매개변수 앞에 접근 제어자를 작성하면 **필드 선언 + `this` 할당을 자동으로 처리**한다.

```ts
class User {
    constructor(
        public name: string,
        private password: string
    ) {}
}
```

즉:

```text
필드 선언
+
constructor 매개변수
+
this.name = name

        ↓

생성자 매개변수 + 접근 제어자
```

---

## 4. 클래스 상속과 `super`

상속(Inheritance)은 기존 클래스의 속성과 메서드를 새로운 클래스가 물려받는 것이다.

```ts
class Animal {
    constructor(public name: string) {}

    speak() {
        console.log("소리를 냅니다.");
    }
}

class Dog extends Animal {
    constructor(name: string) {
        super(name);
    }
}
```

- `extends` → 부모 클래스 상속
- `super()` → 부모 클래스 생성자 호출

---

## 5. Method Overriding

부모 클래스에서 물려받은 메서드를 **하위 클래스의 목적에 맞게 다시 정의**한다.

```ts
class Dog extends Animal {
    speak() {
        console.log("멍멍!");
    }
}
```

> **상속 = 물려받기**
>
> **오버라이딩 = 물려받은 동작을 다시 정의하기**

# 7장 2강 — Abstract Class / Interface

## 1. 추상화(Abstract)

추상화는 여러 구체적인 대상에서 **공통적이고 일반적인 특징이나 규칙을 뽑아 설계하는 것**과 연결된다.

```text
구체적인 대상들
      ↓
공통 특징 추출
      ↓
일반적인 규칙 / 구조
```

---

## 2. Abstract Class

추상 클래스는 다른 클래스들이 따라야 할 **공통 구조와 규칙을 정의하기 위한 클래스**이다.

```ts
abstract class Payment {
    abstract pay(amount: number): void;
}
```

여기서는:

```text
무엇을 해야 하는가?
→ pay()

구체적으로 어떻게 하는가?
→ 아직 결정하지 않음
```

추상 클래스 자체로는 인스턴스를 생성할 수 없다.

```ts
new Payment(); // ❌
```

하위 클래스가 상속받아 추상 메서드를 구현한다.

```ts
class TossPayment extends Payment {
    pay(amount: number): void {
        console.log(`${amount}원 결제`);
    }
}
```

추상 클래스에는 구현된 일반 메서드도 함께 존재할 수 있다.

```ts
abstract class Payment {

    printAmount(amount: number) {
        console.log(amount);
    }

    abstract pay(amount: number): void;
}
```

> **추상 클래스 = 공통 설계 틀**
>
> **추상 메서드 = 하위 클래스가 반드시 구현해야 하는 지침**

---

## 3. Interface

`interface`는 객체가 가져야 할 **구조와 계약을 정의하는 타입**이다.

```ts
interface Payment {
    pay(amount: number): void;
}
```

메서드의 형태를 정의하지만 실제 구현 코드는 작성하지 않는다.

```ts
interface Payment {
    pay(amount: number): void;
}
```

interface 메서드에는 직접 `abstract`를 붙이지 않는다.

```ts
// abstract pay(...); ❌

pay(amount: number): void; // ✅
```

Interface는 클래스가 아니므로 직접 객체를 생성할 수 없다.

```ts
new Payment(); // ❌
```

---

## 4. `implements`

클래스가 interface의 구조를 **실제로 구현하겠다고 선언**할 때 사용한다.

```ts
interface Payment {
    pay(amount: number): void;
}

class TossPayment implements Payment {
    pay(amount: number): void {
        console.log("토스 결제");
    }
}
```

필요한 메서드를 구현하지 않으면 TypeScript가 오류를 발생시킨다.

```text
extends
→ 클래스 상속
→ 구현된 기능도 물려받을 수 있음

implements
→ Interface의 계약 구현
→ 기능을 물려받는 것이 아니라 직접 구현
```

> **`extends` = 상속**
>
> **`implements` = 계약 구현**

---

## 5. Interface와 기능별 설계

하나의 거대한 interface에 모든 기능을 모으면 클래스가 **필요하지 않은 기능까지 의존하거나 구현해야 할 위험**이 생길 수 있다.

따라서 역할이나 기능 단위로 interface를 나누어 설계할 수 있다.

```ts
interface Payable {
    pay(amount: number): void;
}

interface Refundable {
    refund(amount: number): void;
}
```

```text
거대한 하나의 설계
        ↓
기능 / 역할별 분리
        ↓
Payable
Refundable
...
```

---

## 6. 다중 구현

하나의 클래스가 **여러 interface를 동시에 구현**할 수 있다.

```ts
class TossPayment
    implements Payable, Refundable {

    pay(amount: number): void {
        console.log("결제");
    }

    refund(amount: number): void {
        console.log("환불");
    }
}
```

필요한 계약들을 조합해서 하나의 클래스를 설계할 수 있다.

---

## 7. 다형성 (Polymorphism)

**다형성**은 같은 타입 또는 interface를 통해 서로 다른 객체를 다룰 수 있는 특성이다.

```ts
interface Payment {
    pay(amount: number): void;
}

class TossPayment implements Payment {
    pay(amount: number): void {
        console.log("토스 결제");
    }
}

class CardPayment implements Payment {
    pay(amount: number): void {
        console.log("카드 결제");
    }
}
```

둘은 구현 방식이 다르지만 모두 `Payment`로 다룰 수 있다.

```ts
function checkout(payment: Payment) {
    payment.pay(10000);
}

checkout(new TossPayment());
checkout(new CardPayment());
```

`checkout()` 입장에서는 구체적으로 어떤 결제 클래스인지보다:

> **"Payment라는 계약을 지키는 객체인가?"**

가 중요하다.

```text
             Payment
                ↑
        ┌───────┴───────┐
 TossPayment       CardPayment
      ↓                  ↓
 토스 방식            카드 방식
```

> **다형성 = 같은 계약을 지키는 서로 다른 객체를 같은 타입으로 다룰 수 있는 성질**

---

## 8. Interface vs Abstract Class

| | Interface | Abstract Class |
|---|---|---|
| 목적 | 객체의 구조/계약 | 공통 클래스 설계 |
| 사용 | `implements` | `extends` |
| 공통 구현 코드 | 제공하지 않음 | 제공 가능 |
| 여러 개 적용 | 여러 interface 구현 가능 | 클래스 상속은 하나 |
| 직접 객체 생성 | 불가능 | 불가능 |
| 느낌 | 계약서 | 미완성 설계도 |

```text
Interface
→ "이 구조를 지켜라."

Abstract Class
→ "이 기본 설계를 물려받고
   미완성 부분을 완성해라."
```

---

## 9. Interface와 Transpile

Interface는 **TypeScript의 타입 검사와 설계를 위한 정보**이다.

```ts
interface Payment {
    pay(amount: number): void;
}
```

TypeScript 단계에서는 객체가 이 구조를 지키는지 검사한다.

JavaScript로 트랜스파일될 때는 interface 자체가 제거된다.

```text
TypeScript 작성
      ↓
Interface를 이용해 타입 검사
      ↓
JavaScript로 Transpile
      ↓
타입 정보 제거
      ↓
JavaScript 실행
```

### 1. `typeof`와 타입 좁히기

`typeof`를 조건문에 사용하면 런타임의 타입 정보를 바탕으로 TypeScript가 해당 블록에서 타입을 좁힐 수 있다.

`instanceof`는 특정 **클래스의 인스턴스 여부**를 확인할 때 사용한다.

### 2. 서로소 판별 유니온

`status`와 같은 공통 **리터럴 속성(판별자)**을 이용하여 Union에 포함된 타입을 명확하게 구분한다.

```text
공통 판별자
    ↓
switch / if
    ↓
Type Narrowing
```

### 3. `K extends keyof T`

`K`를 `T`가 실제로 가지고 있는 key들로 제한하여 **존재하지 않는 속성에 접근하는 실수를 컴파일 단계에서 방지**한다.

### 4. Union `|`

```text
A | B
= A 또는 B
```

여러 타입 중 하나를 허용한다.

### 5. Intersection `&`

```text
A & B
= A와 B의 조건을 모두 만족
```

결합된 객체는 각 타입이 요구하는 속성을 모두 포함해야 한다.

# TODAY'S KEY POINT

오늘 학습 내용은 결국 **TypeScript에서 타입과 객체의 규칙을 어떻게 설계하고 안전하게 사용하는가**로 연결된다.

```text
Union / Literal
→ 허용 가능한 타입과 값 표현

Discriminated Union
→ 리터럴 판별자로 타입 구분

Type Narrowing
→ 넓은 타입을 구체적인 타입으로 좁힘

Generic
→ 타입을 나중에 결정하면서 관계 유지

keyof
→ 실제 존재하는 객체 key로 제한

Class
→ 데이터와 동작을 객체로 설계

접근 제어자
→ 객체 내부 데이터의 접근 범위 통제

extends
→ 클래스 상속

Overriding
→ 상속받은 동작 재정의

Abstract Class
→ 공통 기능 + 구현해야 할 지침

Interface
→ 객체가 지켜야 할 구조/계약

implements
→ Interface의 계약 구현

다중 구현
→ 여러 Interface 계약을 하나의 클래스에서 구현

다형성
→ 같은 계약의 서로 다른 객체를 같은 타입으로 처리
```

## 오늘 기억할 문장

> **Union `|` = A 또는 B / Intersection `&` = A와 B 모두**

> **Type Narrowing = 검사한 정보를 바탕으로 넓은 타입을 구체적인 타입으로 좁히는 것**

> **Generic의 `T` = 아무 타입이나 막 받는 것이 아니라 타입 관계를 유지하는 타입 변수**

> **`K extends keyof T` = K를 T에 실제 존재하는 key로 제한**

> **Interface = 객체가 지켜야 할 구조와 계약**

> **`extends` = 상속 / `implements` = 계약 구현**

> **Abstract Class = 공통 설계와 하위 클래스가 구현해야 할 지침**

> **다형성 = 같은 계약을 지키는 서로 다른 객체를 같은 타입으로 다룰 수 있는 성질**
